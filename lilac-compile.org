** Object generation
:PROPERTIES:
:ID:       01da95fe-ba23-4481-9833-428423392f5f
:END:

The [[data:Object]] encodes information which we want to reuse when building up
either the "block universe" for tangling, or "cell universe" when weaving. Both
of these concepts are essentially the same thing (the "block universe" is a
special case of the "cell universe", such that all cells are code blocks).

#+name: data:Object
#+begin_src haskell
type Object :: Type
data Object = Object
  { orgDoc :: OrgDoc,
    symbols :: M.Map LinkOid Cell,
    externalOids :: [LinkOid]
  }
  deriving stock (Eq, Generic, Show)
  deriving anyclass (FromJSON, ToJSON)
#+end_src

The ~symbols~ houses all links that point to cells inside the current ~OrgDoc~. We
have to use [[id:f8254d58-7a3d-4595-a265-e0d6255e6ab5::data:LinkOid][data:LinkOid]] as a key, and for this we need to define a ~ToJSONKey~
instance for it.

#+name: tc:ToJSONKey LinkOid
#+begin_src haskell
instance ToJSONKey LinkOid where
  toJSONKey = toJSONKeyText T.show
#+end_src

The ~externalOids~ captures all links that point to some other cell in
another Org file. A consistent "cell universe" can be constructed when all
external links are resolved, by getting all other =Object= values for other Org
files we depend on.

#+name: f:mkObject
#+begin_src haskell
mkObject :: OrgDoc -> Object
mkObject orgDoc =
  Object
    { orgDoc = orgDoc,
      symbols = mkSymbols orgDoc,
      externalOids = findExternalOids orgDoc
    }
#+end_src

[[f:mkSymbols]] generates a mapping of all OIDs to their cells (headings), and also
any OID and name combinations to their cells.

#+name: f:mkSymbols
#+begin_src haskell
mkSymbols :: OrgDoc -> M.Map LinkOid Cell
mkSymbols orgDoc = M.fromList $ concatMap f orgDoc.cells
  where
    f cell = case cell of
      CBlock block -> getSymbols (Just block.parentOid) block.meta cell
      CHeading heading
        | Just oidText <- EM.lookup "ID" heading.meta,
          Just oid <- validateOidText oidText ->
            [ ( LinkOid
                  { oid = oid,
                    name = T.empty
                  },
                cell
              )
            ]
        | otherwise -> []
      CFigure figure -> getSymbols Nothing figure.meta cell
      CMathFragment mathFragment -> getSymbols Nothing mathFragment.meta cell
      CTable table -> getSymbols Nothing table.meta cell
      CListItem {}
      CParagraph {} -> []
    getSymbols :: Maybe OID -> M.Map T.Text T.Text -> Cell -> [(LinkOid, Cell)]
    getSymbols parentOid cellMeta cell =
      concatMap requireName $ catMaybes [parentOid, Just $ orgDoc.oid]
      where
        requireName oid
          | Just name <- EM.lookup "name" cellMeta =
              [ ( LinkOid
                    { oid = oid,
                      name = name
                    },
                  cell
                )
              ]
          | otherwise = []
#+end_src

The ~(name, cell)~ tuple is important, because otherwise Org links that
look like ~[[foo bar]]~ will be returned from [[f:findExternalOids]]. Links
like ~[[foo bar]]~ shouldn't be considered external, because they refer to cells
that have been named like ~foo bar~ inside the current Org file, not an external
Org file.

** External symbol (OID) detection

[[f:findExternalOids]] looks for ~LinkTargetOid~ links that point to cells that are
not inside the current Org file. We just look at all
links and see if any of them point to an OID that is not accounted for in the
=symbols= (symbols that are local to the current [[id:e16dd5c7-0a63-4c52-afe9-744fdf853643::data:OrgDoc][data:OrgDoc]]).

#+name: f:findExternalOids
#+begin_src haskell
findExternalOids :: OrgDoc -> [LinkOid]
findExternalOids orgDoc =
  sort
    . Set.toList
    . Set.fromList
    $ concatMap f orgDoc.cells
  where
    f cell = case cell of
      CBlock block -> foldl' g [] block.body
      CHeading heading -> foldl' h [] heading.body
      CParagraph prose -> foldl' h [] prose
      CTable table -> M.foldl (foldl' h) [] table.grid
      CFigure {}
      CListItem {}
      CMathFragment {} -> []
    g acc = \case
      BTokenLink link -> getExternal acc link
      BTokenString {}
      BTokenPadding -> acc
    h acc = \case
      PTokenLink link -> getExternal acc link
      PTokenStyledText {}
      PTokenMathFragment {} -> acc
    getExternal acc link = case link.target of
      LinkTargetOid linkOid ->
        if M.member linkOid symbols
          then acc
          else linkOid : acc
      LinkTargetURI {}
      LinkTargetOther {} -> acc
    symbols = mkSymbols orgDoc
#+end_src

** Archives
:PROPERTIES:
:ID:       25827c17-2015-434b-b686-db3d72b2ee4d
:END:

When dealing with multiple [[data:Object]] files at a time, we have to answer the
question, "is this collection of objects able to resolve all internal
[[id:f8254d58-7a3d-4595-a265-e0d6255e6ab5::data:LinkOid][data:LinkOid]] values"? Essentially this is the same question as asking if there
are any broken links, as far as [[id:f8254d58-7a3d-4595-a265-e0d6255e6ab5::data:LinkOid][data:LinkOid]] targets are concerned.

The above question also has two different "flavors", depending on what we want
to do:

  1) For tangling, we only care about broken Noweb links for those code blocks
     that have the ~:tangle~ metadata key set (aka "root" blocks). That is, if a
     code block depends on another block but is not itself something that a root
     block depends on, we don't care because such blocks are ignored for
     tangling purposes.

  2) For weaving, we care about any broken link ([[id:f8254d58-7a3d-4595-a265-e0d6255e6ab5::data:LinkOid][data:LinkOid]]) to a cell,
     because otherwise we will not be able to generate the correct HTML link tag
     (~href=...~ attribute) for it.

#+name: data:Archive
#+begin_src haskell
type Archive :: Type
data Archive = Archive
  { objects :: M.Map GPath Object,
    symbols :: M.Map LinkOid Cell
  }
  deriving stock (Eq, Generic, Show)
  deriving anyclass (ToJSON)
#+end_src

A [[data:Archive]] is just a collection of [[data:Object]] values, which are each paired
with the [[id:2d98229c-e318-434b-916b-364c04021306::newtype:GPath][newtype:GPath]] of where that object was found. We have to use ~GPath~
because there is no ~ToJSONKey~ instance for ~P.OsPath~ (which would otherwise have
been our first choice). We also check for any broken links.

#+name: f:mkArchive
#+begin_src haskell
mkArchive :: [(GPath, Object)] -> Either String Archive
mkArchive pathObjs =
  case foldlM concatObjs (M.empty, M.empty) pathObjs of
    Left errMsg -> Left errMsg
    Right (objects, symbols) ->
      let brokenLinks = findBrokenLinks objects symbols
       in if
            | brokenLinks /= [] ->
                Left
                  $ "broken links:\n"
                  <> intercalate
                    "\n"
                    (map showBrokenLink brokenLinks)
            | otherwise ->
                Right
                  Archive
                    { objects = objects,
                      symbols = symbols
                    }
  where
    concatObjs ::
      (M.Map GPath Object, M.Map LinkOid Cell) ->
      (GPath, Object) ->
      Either String (M.Map GPath Object, M.Map LinkOid Cell)
    concatObjs (accObjs, accSyms) (path, obj) =
      pure
        ( M.insert path obj accObjs,
          M.union obj.symbols accSyms
        )
    findBrokenLinks :: M.Map GPath Object -> M.Map LinkOid Cell -> [LinkOid]
    findBrokenLinks objs syms =
      foldl' (getBrokenLink syms) []
        $ allExternalOids objs
    getBrokenLink :: M.Map LinkOid Cell -> [LinkOid] -> LinkOid -> [LinkOid]
    getBrokenLink syms acc linkOid = case EM.lookup linkOid syms of
      Just _ -> acc
      Nothing -> linkOid : acc
    allExternalOids :: M.Map GPath Object -> [LinkOid]
    allExternalOids objs =
      M.foldl (\acc obj -> obj.externalOids <> acc) [] objs
    showBrokenLink :: LinkOid -> String
    showBrokenLink link =
      "  " <> (T.unpack $ LU.mkFqcn link.oid link.name)
#+end_src

** Cycle detection for Noweb links

All Noweb links (for code blocks) inside an [[data:Archive][Archive]] must be such that they do
not form a cycle. This is because we have to expand (replace with the actual
text) Noweb links during the tangling process, and we don't want to be in the
position of expanding things forever.

We want to build up a graph using the Noweb link information embedded in each
block. Using a graph data structure allows us to easily detect cycles, which are
not allowed for tangling because they cannot be resolved.

You may think we could avoid using graphs entirely, and just use an algorithm
like "keep expanding all Noweb links recursively; if we see a Noweb link being
used more than once, error out" to detect cycles. However this won't work
because you can technically reference the same block multiple times at different
points in the tree.

Specifically, we want to build a /directed/ graph where we treat all blocks as
nodes (vertices) and the dependency of Noweb links as edges. So if a block =x=
depends on a Noweb link =y=, then =x= would point to =y=.

From CLRS 3rd, Ch 22 p. 614 we can find a more formal definition of cycles in a
directed graph:

#+begin_quote
A directed graph G is acyclic if and only if a depth-first search of G yields no
back edges.
#+end_quote

And a back edge is defined like this in CLRS p. 609:

#+begin_quote
Back edges are those edges (u, v) connecting a vertex u to an ancestor v in a
depth-first tree. We consider self-loops, which may occur in directed graphs, to
be back edges.
#+end_quote

Note that a back edge can be either an edge that points back to an ancestor, or
a self-loop. Whether an edge points back to an ancestor can be determined by
finding strongly connected components with more than one vertex. And we can
check for self-loops by just seeing if a block links to itself.

Checking for strongly connected components can be done with the =scc= function
provided by the =Data.Graph= library. This library also lets us create a /single/
graph with all of the blocks in it because the library doesn't care whether the
edges we feed into it are connected.

The [[f:buildGraph]] function looks at all code blocks and generates the necessary
edges to build up a directed graph. It does this by constructing edges that have
the [[id:f8254d58-7a3d-4595-a265-e0d6255e6ab5::data:LinkOid][data:LinkOid]] of the starting block as one vertex, and the Noweb links found
inside the body as the other vertices.

#+name: f:buildGraph
#+begin_src haskell
buildGraph ::
  [Block] ->
  ( G.Graph,
    G.Vertex -> (Block, LinkOid, [LinkOid]),
    LinkOid -> Maybe G.Vertex
  )
buildGraph blocks = G.graphFromEdges $ foldl' f [] blocks
  where
    f ::
      [(Block, LinkOid, [LinkOid])] ->
      Block ->
      [(Block, LinkOid, [LinkOid])]
    f acc block
      | Just name <- EM.lookup "name" block.meta =
          let selfLink = LinkOid block.parentOid name
           in (\outLinks -> (block, selfLink, outLinks) : acc)
                . catMaybes
                $ map getOutLinks block.body
      | otherwise = acc
    getOutLinks = \case
      BTokenLink (Link _ (LinkTargetOid linkOid)) -> Just linkOid
      BTokenLink {}
      BTokenPadding {}
      BTokenString {} -> Nothing
#+end_src

The [[f:findCycles]] function takes the output of [[f:buildGraph]] and uses that to run
the =scc= function to get the strongly connected components, which we filter to
only keep the ones that have cycles in them.

#+name: f:findCycles
#+begin_src haskell
findCycles :: Archive -> [G.Tree LinkOid]
findCycles archive = map (fmap toLinkOid) . foldl' f [] $ G.scc graph
  where
    blocks = foldl' getBlocksFromAllSymbols [] $ M.elems archive.symbols
    getBlocksFromAllSymbols acc cell = case cell of
      CBlock b -> b : acc
      CHeading {}
      CListItem {}
      CParagraph {}
      CMathFragment {}
      CFigure {}
      CTable {} -> acc
    (graph, vertexToNode, _) = buildGraph blocks
    toLinkOid vertex =
      let (_, selfLink, _) = vertexToNode vertex
       in selfLink
    f acc tree@(G.Node vertex _)
      | length tree > 1 = tree : acc
      | (_, selfLink, outLinks) <- vertexToNode vertex,
        elem selfLink outLinks =
          tree : acc
      | otherwise = acc
#+end_src

The line ~M.elems archive.symbols~ just gets all code blocks from the ~symbols~
field of the [[data:Archive]] (perhaps ~M.elems~ is a poor name and should have been
called ~M.values~ instead, but that's another matter).

Checking for back edges means just seeing whether there is more than one vertex,
or if there are any self-loops; these concerns are encoded in the ~f~ helper
function.

** Block expansion for tangling

For tangling, we can't use the graph information from [[f:buildGraph]] directly
because it doesn't handle the case where we have multiple links to the same code
block. Instead we look at all of the root blocks (blocks which specify the
~:tangle~ header, and thus require writing to the file system), and expand each
one in turn in [[f:expandRootBlocks]]. The output is a list of tuples, where each
tuple encodes the filesystem path where we want to write some text (as a result
of tangling), and the contents of the text itself which we want to write there
--- hence the type is ~(P.OsPath, T.Text)~.

The call to ~maybeAddShebang~ adds a special shebang line at the beginning of the
file, if one was specified using the ~:shebang~ header. See [[id:caa38bf7-52ae-4246-8be0-8b2c9e58ccc2::unit-test.sh][unit-test.sh]] for an
example.

We also trim lines with only spaces in them (in ~trimTrailingSpaces~), because
these can happen from the ~prependExistingPrefix~ function in [[f:expandBlock]].

#+name: f:expandRootBlocks
#+begin_src haskell
expandRootBlocks :: Archive -> [(P.OsPath, T.Text)]
expandRootBlocks archive = map expandRootBlock rootBlocks
  where
    rootBlocks =
      concat $ M.foldlWithKey getRootBlocksFromObject [] archive.objects
    getRootBlocksFromObject ::
      [[(P.OsPath, Block)]] ->
      GPath ->
      Object ->
      [[(P.OsPath, Block)]]
    getRootBlocksFromObject acc objPath object =
      M.foldl (getRootBlock objPath) [] object.symbols : acc
    getRootBlock objPath acc cell = case cell of
      CBlock b
        | Just path <- EM.lookup "tangle" b.meta,
          Just osPath <- P.encodeUtf $ T.unpack path,
          Just osPathOfObject <- P.encodeUtf $ decodeGPath objPath ->
            (P.combine (P.takeDirectory osPathOfObject) osPath, b) : acc
        | otherwise -> acc
      CHeading {}
      CListItem {}
      CParagraph {}
      CMathFragment {}
      CFigure {}
      CTable {} -> acc
    expandRootBlock :: (P.OsPath, Block) -> (P.OsPath, T.Text)
    expandRootBlock (p, rootBlock) =
      ( p,
        maybeAddShebang rootBlock
          . trimTrailingSpaces
          $ expandBlock archive rootBlock ""
      )
    trimTrailingSpaces :: T.Text -> T.Text
    trimTrailingSpaces text =
      T.unlines
        . map (T.dropWhileEnd (== ' '))
        $ T.lines text
    maybeAddShebang :: Block -> T.Text -> T.Text
    maybeAddShebang rootBlock text
      | Just shebang <- EM.lookup "shebang" rootBlock.meta =
          shebang <> "\n" <> text
      | otherwise = text
#+end_src

In [[f:expandBlock]], we recursively expand all Noweb links until there are none.

#+name: f:expandBlock
#+begin_src haskell
expandBlock :: Archive -> Block -> T.Text -> T.Text
expandBlock archive block existingPrefix =
  let acc = "" :: T.Text
      prefix = "" :: T.Text
   in fst $ foldl' expand (acc, prefix) block.body
  where
    expand (acc, _) BTokenPadding =
      (acc <> "\n", "")
    expand (acc, _) (BTokenString text) =
      (acc <> prependExistingPrefix text, getPrefix text)
    expand (acc, prefix) (BTokenLink (Link _ (LinkTargetOid linkOid)))
      | Just (CBlock targetBlock) <- EM.lookup linkOid archive.symbols =
          ( acc <> (expandBlock archive targetBlock $ existingPrefix <> prefix),
            prefix
          )
      | otherwise = (acc, prefix)
    expand (acc, prefix) _ = (acc, prefix)
    getPrefix text = T.takeWhileEnd (/= '\n') text
    prependExistingPrefix text =
      T.intercalate "\n"
        . reverse
        . fst
        . foldl' prefixTailLines ([], True)
        $ T.split (== '\n') text
    prefixTailLines (acc, isFirstLine) line
      | isFirstLine = (line : acc, False)
      | otherwise = (T.append existingPrefix line : acc, False)
#+end_src

The ~expand~ function recursively calls ~expandBlock~ if it detects a ~LinkOid~ type
link. Otherwise, for ~BTokenString~ tokens it searches for an indentation prefix
with ~getPrefix~. We need the prefix because we want to indent entire blocks if
the name of the link referring to it is indented. See
[[t:0101-block-expansion-prefix]] and [[t:0101-block-expansion-prefix-nested]] for
examples.

The ~getPrefix~ function is simple and uses any characters it finds, not just
spaces, looking backwards and stopping at a newline. See
[[t:0101-block-expansion-prefix-nonspace]] and
[[t:0101-block-expansion-prefix-nonspace-nested]] for examples.

The ~prependExistingPrefix~ function splits up the given text, and injects the
prefix on every line in the text except the very first line. This is because
given the text

#+header: :noweb off
#+begin_src txt
xx<<a>>
#+end_src

where ~xx~ is the prefix, we only want to give this prefix to the lines in ~<<a>>~
except the first line (because the first line of ~<<a>>~ is already prefixed (from
the outer block) with ~xx~); so only the lines after the first line in ~<<a>>~ need
the ~xx~ prefix. This is what we do in ~prefixTailLines~, where we avoid adding the
prefix to the "head", and instead only add it to the "tail."

We use ~T.intercalate~ and ~T.split~ in ~prependExistingPrefix~ to avoid losing any
information about the exact locations of newlines. If we used ~T.lines~ we would
lose information about whether the last line actually had a trailing newline,
because ~T.lines "a\nb"~ and ~T.lines "a\nb\n"~ both give ~["a", "b"]~.

#+name: t:lines-unlines-info-loss
#+begin_src haskell
it "loses information" $ do
  let withoutNewline = T.lines "a\nb"
      withNewline = T.lines "a\nb\n"
  T.unlines withoutNewline `shouldBe` T.unlines withNewline
#+end_src
