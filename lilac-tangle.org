* Tangling
:PROPERTIES:
:ID:       b449a097-d702-4fd6-98de-cb81f7e49177
:END:

In Literate Programming, /tangling/ is the act of extracting the source code out
of a literate document. It is the opposite of documentation generation found in
many programming language environments, such as =javadoc=, where documentation is
extracted from source code.

** Tangling overview

Tangling essentially boils down to the following:

  1) find all code blocks that need to get tangled (they have ~#+header: :tangle
     ...~ in their metadata), and

  2) for each of these code blocks expand any Noweb references in them until
     none are left, and finally

  3) write the files to disk (but only for those files that are different than
     what we already have on disk).

The first two steps are the bare minimum required in order to feed source code
to the computer for interpretation by it, while the third is a way to avoid
unnecessarily busting the modification timestamp cache for Makefiles (because
they use file modification timestamps to see whether we need to rerun a rule).

The [[data:SourceCode]] data structure captures the information needed from the
first two steps.

#+name: data:SourceCode
#+begin_src haskell
type SourceCode :: Type
data SourceCode = SourceCode
  { roots :: [FQBN],
    fqbnToCodeBlock :: M.Map FQBN Block
  }
#+end_src

#+name: f:defaultSourceCode
#+begin_src haskell
defaultSourceCode :: SourceCode
defaultSourceCode =
  SourceCode
    { roots = [],
      fqbnToCodeBlock = M.fromList []
    }
#+end_src

The ~roots~ field has a list of file paths that need to be tangled. The
~fqbnToCodeBlock~ field is a simple mapping from the /fully qualified block name/
(or "FQBN") of the block to the block itself. The FQBN is the combination of the
OID and the human-friendly name of the block from the ~#+name:~ field of the
block's metadata. The [[type:FQBN]] is just a convenience type to help readability.

#+name: type:FQBN
#+begin_src haskell
type FQBN :: Type
type FQBN = T.Text
#+end_src

** Find code blocks to tangle

The function [[f:getSourceCode]] goes through the cells inside a [[id:e16dd5c7-0a63-4c52-afe9-744fdf853643::data:OrgDoc][data:OrgDoc]] to
populate [[data:SourceCode]].

#+name: f:getSourceCode
#+begin_src haskell
getSourceCode :: OrgDoc -> FilePath -> SourceCode
getSourceCode od odPath = foldl' f defaultSourceCode od.cells
  where
    f :: SourceCode -> Cell -> SourceCode
    f sc cell = case cell of
      CBlock b
        | Just name <- EM.lookup "name" b.meta,
          Just path <- EM.lookup "tangle" b.meta,
          Right filePath <- qualify path ->
            let fqbn1 = getFqbnByDocOID name
                fqbn2 = getFqbn b name
                newBlock1 = useQualifiedTanglePath filePath $ injectFqbn fqbn1 b
                newBlock2 = useQualifiedTanglePath filePath $ injectFqbn fqbn2 b
             in sc
                  { roots = fqbn1 : sc.roots,
                    fqbnToCodeBlock =
                      M.insert fqbn1 newBlock1
                        $ M.insert fqbn2 newBlock2 sc.fqbnToCodeBlock
                  }
        | Just path <- EM.lookup "tangle" b.meta,
          Right filePath <- qualify path ->
            let name = (T.pack filePath) <> "\NUL"
                fqbn1 = getFqbnByDocOID name
                fqbn2 = getFqbn b name
                newBlock1 = useQualifiedTanglePath filePath $ injectFqbn fqbn1 b
                newBlock2 = useQualifiedTanglePath filePath $ injectFqbn fqbn2 b
             in sc
                  { roots = fqbn1 : sc.roots,
                    fqbnToCodeBlock =
                      M.insert fqbn1 newBlock1
                        $ M.insert fqbn2 newBlock2 sc.fqbnToCodeBlock
                  }
        | Just name <- EM.lookup "name" b.meta ->
            let fqbn1 = getFqbnByDocOID name
                fqbn2 = getFqbn b name
                newBlock1 = injectFqbn fqbn1 b
                newBlock2 = injectFqbn fqbn2 b
             in sc
                  { fqbnToCodeBlock =
                      M.insert fqbn1 newBlock1
                        $ M.insert fqbn2 newBlock2 sc.fqbnToCodeBlock
                  }
        | otherwise -> sc
      CHeading {}
      CListItem {}
      CParagraph {}
      CMathFragment {}
      CFigure {}
      CTable {} -> sc
    getFqbn :: Block -> T.Text -> T.Text
    getFqbn b name = LU.mkFqcn b.parentOid name
    getFqbnByDocOID name = LU.mkFqcn od.oid name
    injectFqbn fqbn block =
      block
        { meta = M.insert "__fqbn" fqbn block.meta
        }
    tanglePathPrefix = P.takeDirectory $ P.unsafeEncodeUtf odPath
    qualify =
      P.decodeWith utf8 utf8
        . P.combine tanglePathPrefix
        . P.unsafeEncodeUtf
        . T.unpack
    useQualifiedTanglePath qualifiedFilePath block =
      block
        { meta = M.insert "tangle" (T.pack qualifiedFilePath) block.meta,
          body = block.body
        }
#+end_src

Most of the work is done by the ~f~ helper. It's important to note that we give
anonymous tangled blocks a default name with a ASCII NUL character. This is
because our tangling machinery in [[f:expandRootBlocks]] requires looking up blocks
(including root blocks) by their name. Anonymous blocks that are tangled are
still considered root blocks, and so we use the tangle path as the name, plus a
NUL character at the end to virtually guarantee that this does not conflict with
the name of another block (because Org files should not have any NUL character
in them).

The business around using two =FQBN= values (~fqbn1~ and ~fqbn2~) when populating
~fqbnToCodeBlock~ allows us to refer to blocks either by the OID of the Org file
enclosing them (this is used for [[id:d9b8b9d6-0334-4d9a-9146-d6bd158f0d77::f:oidReferenceParser][implicit Noweb links in
f:oidReferenceParser]], which know about the OID of the Org file's
metadata at the top-level but not about OIDs of other headings in the file), or
by the OID of the closest parent.

We need the latter case because the functions =org-store-link= and
=org-insert-last-stored-link= always refer to the closest OID of the nearest
parent heading; these Orgmode functions can be used to retrieve the OID easily,
and with minor modification, the inserted link can be tweaked to turn it into a
Noweb link inside a code block.

The ~useQualifiedTanglePath~ helper prefixes all tangle paths with the directory
that contains the Org file from which we generated the =OrgDoc=. Because the
~odPath~ is itself canonicalized in [[f:getSourceCodeFromPath]], this basically
results in a canonicalized path (because users aren't going to put in convoluted
paths for the ~:tangle~ header). This is more intuitive, because the tangle paths
should be relative to the location of the Org file, not the present working
directory from where the =lilac= binary is invoked.

The [[f:getSourceCode]] function can only extract code blocks from a single Org
document. However, unlike vanilla Orgmode, we allow users to specify code
blocks that refer to other code blocks in *other* (external) documents. So we need
a way to get the full ~SourceCode~ we need, across /multiple files/ if necessary.
The [[f:getSourceCodeMulti]] function calls ~getSourceCode~ first on the initial Org
file, and then calls ~growBlockUniverse~ to augment it with all code blocks from
external files as needed.

#+name: f:getSourceCodeMulti
#+begin_src haskell
getSourceCodeMulti ::
  OrgDoc ->
  FilePath ->
  M.Map OID P.OsPath ->
  IO SourceCode
getSourceCodeMulti od odPath goids = do
  let sc = getSourceCode od odPath
  bu <- growBlockUniverse Set.empty Set.empty goids sc.fqbnToCodeBlock sc.roots
  pure
    $ sc
      { roots = sc.roots,
        fqbnToCodeBlock = bu
      }
#+end_src

Most of the heavy lifting here (of detecting external Org files, and then
parsing them to grow the "block universe") is done inside [[f:growBlockUniverse]],
which we examine in the next section.

*** Blocks from external files
:PROPERTIES:
:ID:       e6ffbd65-9dbf-4806-beab-65d8af82794e
:END:

Code blocks themselves can reference other blocks. Most of the time, these other
blocks are in the same file and can be "dereferenced" without any additional
parsing.

But what if a code block depends on a code block in /another file/, as we've seen
in [[id:d9b8b9d6-0334-4d9a-9146-d6bd158f0d77::f:oidReferenceParser][f:oidReferenceParser]]? We must bring those code blocks into our known
universe of code blocks. In a sense we are building up a "super" Org file with
all the code blocks we need for tangling.

As long as we build up a ~SourceCode~ data structure with all of the code blocks
we need (whether those code blocks come from a single Org file or multiple Org
files), we can perform tangling without any problems.

The tricky part here is parsing additional Org files, but also limiting the
search so that we are only parsing those Org files that we need to resolve
tangling the current file. That is, we only parse another Org file if a code
block /needed by a root block/ refers to a code block in that other Org file.

The [[f:growBlockUniverse]] function builds up the critical ~M.Map FQBN Block~ portion
of a [[data:SourceCode]], teaching it all about the code blocks from relevant
external files. It does this by doing a breadth-first search of the code blocks,
starting from each root block in the [[data:SourceCode]] as a starting point (where
a root block is a block that we want to tangle). We skip the search if the code
block cannot be found in the block universe; this is the ~otherwise~ case in
[[f:growBlockUniverse]] and can happen if we get a nonsensical Noweb link.

Whenever we encounter a Noweb link that refers to another Org file, we parse
that file if we haven't already and call [[f:getSourceCode]] to get the code blocks
from that file. We have to use ~newFqbns~ to keep track of which code blocks have
been visited; otherwise we'll end up in an infinite loop if there are any
cycles.

This last bit is done in the ~f~ helper function for [[f:growBlockUniverse]].

#+name: f:growBlockUniverse
#+begin_src haskell
growBlockUniverse ::
  Set.Set OID ->
  Set.Set FQBN ->
  M.Map OID P.OsPath ->
  M.Map FQBN Block ->
  [FQBN] ->
  IO (M.Map FQBN Block)
growBlockUniverse _ _ _ blockUniverse [] = pure blockUniverse
growBlockUniverse parsedOids seenFqbns goids blockUniverse (root : roots)
  | Just block <- EM.lookup root blockUniverse = do
      let nowebLinks = catMaybes $ map getLinkTarget block.body
          fqbns = map T.show nowebLinks
          newFqbns = filter (\fqbn -> not $ Set.member fqbn seenFqbns) fqbns
      (newlyParsedOids, grownBlockUniverse, toGrowFrom) <-
        foldlM f (parsedOids, blockUniverse, []) nowebLinks
      growBlockUniverse
        newlyParsedOids
        (Set.union seenFqbns $ Set.fromList newFqbns)
        goids
        grownBlockUniverse
        (roots <> newFqbns <> toGrowFrom)
  | otherwise = growBlockUniverse parsedOids seenFqbns goids blockUniverse roots
  where
    f ::
      (Set.Set OID, M.Map FQBN Block, [FQBN]) ->
      LinkOid ->
      IO (Set.Set OID, M.Map FQBN Block, [FQBN])
    f (pu, bu, tgf) linkOid@(LinkOid oid _)
      | Set.member (T.show linkOid) seenFqbns = pure (pu, bu, tgf)
      | Set.member oid pu = pure (pu, bu, (T.show linkOid) : tgf)
      | Just oidOsPath <- EM.lookup oid goids = do
          input <- LU.readFileRobustly oidOsPath
          case parseOrgDoc input of
            Right od -> do
              oidFilePath <- P.decodeUtf oidOsPath
              let sc = getSourceCode od oidFilePath
              pure
                ( Set.insert oid pu,
                  M.union bu sc.fqbnToCodeBlock,
                  (T.show linkOid) : tgf
                )
            Left err -> do
              putStrLn $ show err
              pure (pu, bu, tgf)
      | otherwise = pure (pu, bu, tgf)
    getLinkTarget = \case
      (BTokenLink (Link _ (LinkTargetOid linkOid))) ->
        Just linkOid
      BTokenLink {}
      BTokenPadding {}
      BTokenString {} -> Nothing
#+end_src

The ~f~ helper does quite a lot. The main concern it has is to avoid performing
the parse of the external Org file more than once:

  - If we've seen this link before from a previous iteration, skip it (because
    we must've already done everything we needed in the previous iteration).

  - If we haven't seen this link before, but we've seen the Org doc containing
    it before, record that the link needs to be explored further, but do not
    parse the Org doc containing this link (because we're already parsed it
    previously).

  - If we haven't seen this link before, nor the Org doc containing it, only
    then parse this new (external) Org doc to grow the block universe.

  - If we cannot figure out how to locate the external Org doc, skip it.

These four cases are encoded in the ~f~ helper above.

Note that [[f:growBlockUniverse]] leaves out edge generation and does not build up a
dependency graph like we do in our existing function [[f:findCycles]]. This is
because we want to keep things simple.

** Expand blocks for tangling

For tangling, we can't use the graph information from [[f:buildGraph]] directly
because it doesn't handle the case where we have multiple links to the same code
block. Instead we look at all of the root blocks, and expand each one in turn in
[[f:expandRootBlocks]]. The output is a list of tuples, where each tuple encodes the
filesystem path where we want to write some text (as a result of tangling), and
the contents of the text itself which we want to write there --- hence the type
is ~(P.OsPath, T.Text)~.

The call to ~maybeAddShebang~ adds a special shebang line at the beginning of the
file, if one was specified using the ~:shebang~ header. See [[id:caa38bf7-52ae-4246-8be0-8b2c9e58ccc2::unit-test.sh][unit-test.sh]] for an
example.

We also trim lines with only spaces in them (in ~trimTrailingSpaces~), because
these can happen from the ~prependExistingPrefix~ function in [[f:expandBlock]].

#+name: f:expandRootBlocks
#+begin_src haskell
expandRootBlocks :: SourceCode -> [(P.OsPath, T.Text)]
expandRootBlocks sc = catMaybes $ map expandRootBlock sc.roots
  where
    expandRootBlock :: T.Text -> Maybe (P.OsPath, T.Text)
    expandRootBlock rootFqbn
      | Just rootBlock <- EM.lookup rootFqbn sc.fqbnToCodeBlock =
          Just
            ( tanglePathOf rootBlock,
              maybeAddShebang rootBlock
                . trimTrailingSpaces
                $ expandBlock sc rootBlock ""
            )
      | otherwise = Nothing
    trimTrailingSpaces :: T.Text -> T.Text
    trimTrailingSpaces text =
      T.unlines
        . map (T.dropWhileEnd (== ' '))
        $ T.lines text
    tanglePathOf :: Block -> P.OsPath
    tanglePathOf block
      | Just path <- EM.lookup "tangle" block.meta = P.unsafeEncodeUtf $ T.unpack path
      | otherwise = error "programmer error"
    maybeAddShebang :: Block -> T.Text -> T.Text
    maybeAddShebang rootBlock text
      | Just shebang <- EM.lookup "shebang" rootBlock.meta =
          shebang <> "\n" <> text
      | otherwise = text
#+end_src

In [[f:expandBlock]], we recursively expand all Noweb links until there are none.

#+name: f:expandBlock
#+begin_src haskell
expandBlock :: SourceCode -> Block -> T.Text -> T.Text
expandBlock sc block existingPrefix =
  let acc = "" :: T.Text
      prefix = "" :: T.Text
   in fst $ foldl' expand (acc, prefix) block.body
  where
    expand (acc, _) BTokenPadding =
      (acc <> "\n", "")
    expand (acc, _) (BTokenString text) =
      (acc <> prependExistingPrefix text, getPrefix text)
    expand (acc, prefix) (BTokenLink (Link _ (LinkTargetOid linkOid)))
      | Just targetBlock <-
          EM.lookup
            (T.show linkOid)
            sc.fqbnToCodeBlock =
          ( acc <> (expandBlock sc targetBlock $ existingPrefix <> prefix),
            prefix
          )
      | otherwise = (acc, prefix)
    expand (acc, prefix) _ = (acc, prefix)
    getPrefix text = T.takeWhileEnd (/= '\n') text
    prependExistingPrefix text =
      T.intercalate "\n"
        . reverse
        . fst
        . foldl' prefixTailLines ([], True)
        $ T.split (== '\n') text
    prefixTailLines (acc, isFirstLine) line
      | isFirstLine = (line : acc, False)
      | otherwise = (T.append existingPrefix line : acc, False)
#+end_src

The ~expand~ function recursively calls ~expandBlock~ if it detects a ~LinkOid~ type
link. Otherwise, for ~BTokenString~ tokens it searches for a prefix with
~getPrefix~. We need the prefix because we want to indent entire blocks if the
name of the link referring to it is indented. See [[t:0101-block-expansion-prefix]]
and [[t:0101-block-expansion-prefix-nested]] for examples.

The ~getPrefix~ function is simple and uses any characters it finds, not just
spaces, looking backwards and stopping at a newline. See
[[t:0101-block-expansion-prefix-nonspace]] and
[[t:0101-block-expansion-prefix-nonspace-nested]] for examples.

The ~prependExistingPrefix~ function splits up the given text, and injects the
prefix on every line in the text except the very first line. This is because
given the text

#+header: :noweb off
#+begin_src txt
xx<<a>>
#+end_src

where ~xx~ is the prefix, we only want to give this prefix to the lines in ~<<a>>~
except the first line (because the first line of ~<<a>>~ is already prefixed (from
the outer block) with ~xx~); so only the lines after the first line in ~<<a>>~ need
the ~xx~ prefix. This is what we do in ~prefixTailLines~, where we avoid adding the
prefix to the "head", and instead only add it to the "tail."

We use ~T.intercalate~ and ~T.split~ in ~prependExistingPrefix~ to avoid losing any
information about the exact locations of newlines. If we used ~T.lines~ we would
lose information about whether the last line actually had a trailing newline,
because ~T.lines "a\nb"~ and ~T.lines "a\nb\n"~ both give ~["a", "b"]~.

#+name: t:lines-unlines-info-loss
#+begin_src haskell

      withNewline = T.lines "a\nb\n"
  T.unlines withoutNewline `shouldBe` T.unlines withNewline
#+end_src

** Tangle files

In [[f:tangle]] we naively tangle each file, one at a time, in serial fashion. It
does not write to the file if what would be written is the same as what's
already there. This way, file modification timestamps can remain the same and
tools like GNU Make won't get confused by timestamps that have been needlessly
updated. However, we always do write the file if it doesn't exist on disk.

#+name: f:tangle
#+begin_src haskell
tangle :: SourceCode -> IO ()
tangle sc = do
  let blocks = sort $ expandRootBlocks sc
  putStrLn $ "Blocks to process: " <> (show $ length blocks)
  (tangled, tangledPaths, skipped) <- foldlM f (0, [], 0) blocks
  putStrLn $ "Tangled: " <> (show tangled)
  when (tangled > 0) $ mapM_ printTangled $ reverse tangledPaths
  putStrLn $ "Skipped: " <> (show skipped)
  where
    f :: (Int, [P.OsPath], Int) -> (P.OsPath, T.Text) -> IO (Int, [P.OsPath], Int)
    f (tangled, tangledPaths, skipped) (path, contentToWrite) = do
      alreadyExists <- D.doesPathExist path
      existingContent <- LU.readFileRobustly path
      let g
            | (alreadyExists && existingContent /= contentToWrite)
                || not alreadyExists = do
                LU.writeFileRobustly path contentToWrite
                pure (tangled + 1, path : tangledPaths, skipped)
            | otherwise = pure (tangled, tangledPaths, skipped + 1)
       in g
    printTangled :: P.OsPath -> IO ()
    printTangled path = putStrLn $ "  " <> show path
#+end_src

We sort the paths first so that the output is less confusing. Only tangled paths
are printed, because otherwise the output can be overly verbose.

The function [[id:85a464eb-e220-40d7-ae49-5edc349ee6b4::f:readFileRobustly][f:readFileRobustly]] will return the empty string if there was any
error encountered while reading the file. One common scenario is if the file
does not exist yet. Returning the empty string in this (or other error-raising
scenarios) is fine because it will most likely result in the comparison
~existingContent /= contentToWrite~ in [[f:tangle]] failing (assuming the
~contentToWrite~ is not empty), resulting in the file being marked for tangling.

The [[data:SourceCode]] data structure is critical for tangling. The function
[[f:getSourceCodeFromPath]] reads a complete Org document from disk and converts it
to a [[data:SourceCode]] type. It requires a map of global Org IDs (GOIDs), to mimic
the behavior of tangling ([[id:27b05a30-83ff-4c47-b320-f53747424a68::f:lilacTangle][f:lilacTangle]]) which also requires it.

#+name: f:getSourceCodeFromPath
#+begin_src haskell
getSourceCodeFromPath ::
  FilePath ->
  FilePath ->
  IO (Either T.Text LT.SourceCode)
getSourceCodeFromPath path orgIdLocationsFile = do
  goids <- LP.runGoidsParser orgIdLocationsFile
  input <- LU.readFrom "test/Lilac/TangleSpec/" path
  case LP.parseOrgDoc input of
    Left errMsg -> pure $ Left errMsg
    Right od -> do
      sc <- LT.getSourceCodeMulti od ("test/Lilac/TangleSpec/" <> path) goids
      pure $ Right sc
#+end_src

We pass on ~"test/Lilac/TangleSpec/" <> path~ to [[f:getSourceCode][LT.getSourceCode]] because if we
were to use the ~canonicalPath~ here, we would have to capture the absolute path
in our test case expectations, which would break portability of the test cases
(because the test case expectations would have to capture the absolute path,
meaning all developers would have to clone the Lilac repository into the same
path).

The [[f:checkExpansion]] function expands all source code blocks and compares them
with the expected output.

checkExpansion :: FilePath -> FilePath -> [(FilePath, T.Text)] -> Spec
checkExpansion path goidsFile expectedExpansions = do
  it path $ do
    (Right sc) <- getSourceCodeFromPath path goidsFile
    (LT.expandRootBlocks sc)
      `shouldBe` (fmap (first P.unsafeEncodeUtf) expectedExpansions)
