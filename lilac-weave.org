* Weaving

In most Literate Programming systems, /weaving/ is the act of generating a
human-readable document. This usually means writing a PDF or an HTML page.

For now, Lilac's main goal is to generate HTML pages. There are several
reasons:

  1) HTML is easier to consume on the web than PDFs.

  2) PDFs are obsessed with page numbers because they are designed to be printed
     on real physical paper; we don't care about those things.

  3) We want to eventually make our HTML pages interactive, and interactivity is
     easier in HTML.

** Architecture
:PROPERTIES:
:ID:       8f5752c0-6162-4de6-9ceb-f78ba584722c
:END:

Generating HTML ultimately means having three components: HTML elements,
CSS, and JavaScript (JS). HTML and CSS alone can be used to create a static
document, but JS is necessary for making things dynamic.

At this stage, the architecture we have in mind for weaving is the following:

  1) Convert the [[data:OrgDoc]] into HTML.

  2) Generate CSS separately.

  3) Sprinkle in some JS for interactivity.

Step 3 will be done with [[https://clojurescript.org/][ClojureScript]], which compiles to JS.

One main advantage of this model is that other "viewers" can be created, as long
as they understand the same JSON. While we would prefer to use something more
"typed" like [[https://protobuf.dev/][Protobufs]], [[https://github.com/cognitect/transit-clj][Transit]], or [[https://github.com/edn-format/edn][EDN]], we choose JSON for its universality.
Also, none of these alternative formats support both Haskell and ClojureScript
well.

* Generate HTML
:PROPERTIES:

Weaving mainly means converting the [[data:OrgDoc]] into HTML, as part of "Step 1"
in [[id:8f5752c0-6162-4de6-9ceb-f78ba584722c][Architecture]].

The top-level function is [[f:weave]], which sets the overall structure. Most of the
content of [[id:442c807f-c9d9-45a7-88bf-d38cbbca09cf::data:OrgDoc][data:OrgDoc]] is made up of [[id:442c807f-c9d9-45a7-88bf-d38cbbca09cf::data:Cell][data:Cell]] values, which we iterate over
with [[f:weaveCell]].

#+name: f:weave
#+begin_src haskell
weave :: OrgDoc -> Bool -> H.Html
weave od watch = H.docTypeHtml $ do
  H.head $ do
    H.meta ! A.charset "utf-8"
    H.title
      $ H.text
      $ case EM.lookup "title" od.meta of
        Just title -> title
        Nothing -> "Untitled"
    <<Hot reload script>>
    <<Styles and fonts>>
  H.body $ do
    _ <- foldlM weaveCell M.empty od.cells
    pure ()

Weaving cells just means delegating to each of the weavers that know how to
handle each cell type.

#+name: f:weaveCell
#+begin_src haskell
weaveCell ::
  DomIDs ->
  Cell ->
  BI.MarkupM (DomIDs)
weaveCell domIDs cell = do
  newDomIDs <- case cell of
    CHeading heading -> do
      weaveHeading heading
      pure domIDs
    CListItem listMarkers -> do
      sequence_ $ map weaveListMarker listMarkers
      pure domIDs
    CParagraph prose -> do
      H.p $ do
        sequence_ $ map weavePToken prose
      pure domIDs
    CBlock block -> do
      weaveBlock block
      pure domIDs
    CMathFragment _ -> do
      H.p ""
      pure domIDs
    CFigure _ -> do
      H.p ""
      pure domIDs
    CTable _ -> do
      H.p ""
      pure domIDs
  pure newDomIDs
#+end_src

** Unique names

To weave unique HTML DOM IDs (for the ~id~ HTML attribute), we need to remember
previously-generated DOM IDs. For this, we use the [[type:DomIDs]] type. It is keyed
by a tuple representing the type of cell and the unique name we wanted to use
for it, and the value is a tuple showing how many uses of it we've had already.
So if two headings have the same name, then one will be assigned ~h-foo~ and the
other ~h-foo-2~.

#+name: type:DomIDs
#+begin_src haskell
type DomIDs :: Type
type DomIDs = M.Map T.Text Int
#+end_src

Generating a unique name suitable for being used as the ~id~ attribute value
requires us to convert some arbitrary text into a DOM ID-friendly name. For this
purpose we have [[f:toSafeHtmlId]].

[[https://www.w3.org/TR/html4/types.html][This page]] says:

#+begin_quote
ID and NAME tokens must begin with a letter ([A-Za-z]) and may be followed by
any number of letters, digits ([0-9]), hyphens ("-"), underscores ("_"), colons
(":"), and periods (".").
#+end_quote

#+name: f:toSafeHtmlId
#+begin_src haskell
toSafeHtmlId :: T.Text -> T.Text
toSafeHtmlId = T.map onlyKeepSomeChars
  where
    onlyKeepSomeChars c
      | isAsciiLower c || isAsciiUpper c = c
      | isDigit c = c
      | T.elem c "-_:." = c
      | otherwise = '-'
#+end_src

** Weave headings

Headings might sound simple, but because they are made up of arbitrary text,
it's fairly involved. The body of a heading is made up of a list of [[id:c8616126-215d-49be-8874-c2aca7d93a54::data:PToken][data:PToken]]
values. So, we have to weave each type of token separately.

#+name: f:weaveHeading
#+begin_src haskell
weaveHeading :: Heading -> H.Html
weaveHeading heading = hN ! (A.id $ H.textValue desiredDomID) $ do
  H.a ! (A.href . H.textValue $ "#" <> desiredDomID) $ do
    H.text $ sectionText <> " "
    sequence_ $ map weavePToken heading.body
  where
    hN =
      maybeAssignId heading.meta
        $ case heading.level of
          1 -> H.h1
          2 -> H.h2
          3 -> H.h3
          4 -> H.h4
          5 -> H.h5
          _ -> H.h6
    sectionText =
      T.intercalate "."
        . map T.show
        . reverse
        $ heading.section
    desiredDomID =
      T.intercalate
        "-"
        [ "h",
          sectionText,
          toSafeHtmlId $ getProseContents heading.body
        ]
#+end_src

The ~sectionText~ already makes the heading unique amongst the other ones in the
Org file, but for human-friendliness we also extract the textual part of it with
[[f:getProseContents]] (which is fed through [[f:toSafeHtmlId]] for safety).

#+name: f:getProseContents
#+begin_src haskell
getProseContents :: [PToken] -> T.Text
getProseContents = join . foldl' f []
  where
    join = T.intercalate "" . reverse
    f acc = \case
      PTokenStyledText styledText -> styledText.body : acc
      PTokenLink link ->
        let linkText =
              join
                $ foldl'
                  (\acc' n -> n.body : acc')
                  []
                  link.name
         in linkText : acc
      PTokenMathFragment mathFragment -> mathFragment.body : acc
#+end_src

The [[f:maybeAssignId]] function assigns an =id= HTML attribute if it detects the "ID"
tag in the given metadata.

#+name: f:maybeAssignId
#+begin_src haskell
maybeAssignId :: M.Map T.Text T.Text -> (H.Html -> H.Html) -> (H.Html -> H.Html)
maybeAssignId meta elt = case EM.lookup "ID" meta of
  Just uuidText -> elt ! (A.id $ H.textValue uuidText)
  Nothing -> elt
#+end_src

Each [[id:c8616126-215d-49be-8874-c2aca7d93a54::data:PToken][data:PToken]] value has its own weaver.

#+name: f:weavePToken
#+begin_src haskell
weavePToken :: PToken -> H.Html
weavePToken = \case
  PTokenStyledText styledText -> weaveStyledText styledText
  PTokenLink _ -> H.text ""
  PTokenMathFragment _ -> H.text ""
#+end_src

** Weave styled text

#+name: f:weaveStyledText
#+begin_src haskell
weaveStyledText :: StyledText -> H.Html
weaveStyledText styledText = do
  if styles == []
    then H.text $ styledText.body
    else
      H.span
        ! A.class_ (H.textValue $ T.unwords styles)
        $ H.text
        $ styledText.body
  where
    styles = foldl' styleToClasses [] $ maskToStyles styledText.style
    styleToClasses :: [T.Text] -> Style -> [T.Text]
    styleToClasses acc = \case
      Bold -> "bold" : acc
      Italic -> "italic" : acc
      Underline -> "underline" : acc
      Verbatim -> "verbatim" : acc
      Code -> "code" : acc
#+end_src

** Weave list markers

The =blaze-html= library we use expects to take care of the starting and closing
tags for us automatically when we use its HTML tag functions. However, for
list items we cannot use these functions (~H.ol~, ~H.ul~, ~H.li~) because they
require our existing data structure to be nested as well (like a tree).

But the cells we have are flat, and so we cannot use those functions. On the
other hand, we already know exactly where to start and close the various tags,
so it's actually very easy to insert the tags manually. This is what we do in
[[f:weaveListMarker]].

#+name: f:weaveListMarker
#+begin_src haskell
weaveListMarker :: ListMarker -> H.Html
weaveListMarker =
  H.preEscapedToMarkup . \case
    LOrderedStart -> "<ol>" :: T.Text
    LOrderedEnd -> "</ol>"
    LUnorderedStart -> "<ul>"
    LUnorderedEnd -> "</ul>"
    LItemStart -> "<li>"
    LItemEnd -> "</li>"
#+end_src

** Weave code blocks

Weaving code blocks requires us to be able to handle both regular text
(~BTokenString~) and also links (~BTokenLink~). There is some additional work for
supporting syntax highlighting (see [[f:colorizeText]]).

#+name: f:weaveBlock
#+begin_src haskell
weaveBlock :: Block -> H.Html
weaveBlock block = do
  H.div ! A.class_ "code-block-container" $ do
    maybeAssignName
    let bodyBorder = case EM.lookup "name" block.meta of
          Just _ -> ""
          Nothing -> " fully-rounded"
    H.pre ! A.class_ ("code-block-body" <> bodyBorder) $ do
      let bodyText = getBlockContentsWithoutLinks block.body
      case EM.lookup "__src_language" block.meta of
        Just lang ->
          let colorized = TL.toStrict . renderHtml $ colorizeText lang bodyText
              getLink = \case
                BTokenLink l -> Just l
                BTokenString {}
                BTokenPadding {} -> Nothing
              links = catMaybes $ map getLink block.body
           in H.preEscapedText $ spliceLinks colorized links
        Nothing -> H.code $ H.text bodyText
  where
    maybeAssignName =
      case EM.lookup "name" block.meta of
        Just name ->
          H.div ! A.class_ "code-block-name" $ do
            H.code $ H.text name
        Nothing -> pure ()
    getBlockContentsWithoutLinks :: [BToken] -> T.Text
    getBlockContentsWithoutLinks = T.concat . map bTokenToText
      where
        bTokenToText :: BToken -> T.Text
        bTokenToText = \case
          BTokenString text -> text
          BTokenPadding -> ""
          BTokenLink (Link _name (LinkTargetNoweb _)) -> "\NUL"
          BTokenLink {} -> ""
#+end_src

The first thing we do is to get the contents of the block with
~getBlockContentsWithoutLinks~. This function is similar to [[id:51f2edd8-5f8e-4c63-841f-da6c5c41680a::f:getBlockContents][f:getBlockContents]]
from =Lilac.Parse=, but does not encode the links information directly into the
text. Instead, links are replaced with the ~\NUL~ character. This is because the
text is fed into [[f:colorizeText]], and we don't want the links to be dealt with in
any special way yet. The ~BTokenPadding~ token is ignored in
~getBlockContentsWithoutLinks~ because ~BTokenPadding~ is only meant to be used for
tangling.

#+name: f:colorizeText
#+begin_src haskell
colorizeText :: T.Text -> T.Text -> H.Html
colorizeText lang txt
  | Just syntax <- Sky.lookupSyntax lang Sky.defaultSyntaxMap,
    Just lines <- foldMap' Just $ Sky.tokenize defaultTokeniserConfig syntax txt =
      Sky.formatHtmlInline Sky.defaultFormatOpts lines
  | otherwise = H.code $ H.text txt
  where
    defaultTokeniserConfig = Sky.TokenizerConfig Sky.defaultSyntaxMap False
#+end_src

Block colorization relies on the [[https://hackage.haskell.org/package/skylighting][=skylighting=]] syntax highlighting library. This
library ignores the ~\NUL~ character, which is what we want. Once we have the
colorized text, we splice in the links with ~spliceLinks~, which relies on
[[f:weaveLink]] for constructing HTML for each link. The splicing works by splitting
on the ~\NUL~ character and manually "zipping" up the colorized substrings with
the woven link HTML fragments.

#+name: f:spliceLinks
#+begin_src haskell
spliceLinks :: T.Text -> [Link] -> T.Text
spliceLinks colorized links =
  let colorizedStrs = T.splitOn "\NUL" colorized
      f :: ([T.Text], [Link]) -> T.Text -> ([T.Text], [Link])
      f (acc, []) colorizedStr = (colorizedStr : acc, [])
      f (acc, link : links') colorizedStr =
        ( colorizedStr : (TL.toStrict . renderHtml $ weaveLink link) : acc,
          links'
        )
   in T.intercalate ""
        . reverse
        . fst
        . foldl' f (take 1 colorizedStrs, links)
        $ drop 1 colorizedStrs
#+end_src

Weaving links is not yet fully supported (we just have a stub "~h~" target for the
URL).

** Write to disk

Weaving to disk is used when we want to choose where to write the HTML. It's
just a thin wrapper around [[f:weave]] which does most of the work.

for the horizontal and vertical parts. E.g., instead of calling

#+begin_src haskell
padding (px 6) (px 10) (px 6) (px 10)
#+end_src

you can do

#+begin_src haskell
vh padding (px 6) (px 10)
#+end_src

to save some keystrokes and decrease the chance of typos.

#+name: f:vh
#+begin_src haskell
vh :: (Size sz -> Size sz -> Size sz -> Size sz -> Css) -> Size sz -> Size sz -> Css
vh f x y = f x y x y
#+end_src

[[f:ev]] is like [[f:vh]], but uses the same size for *everything*.

#+name: f:ev
#+begin_src haskell
ev :: (Size sz -> Size sz -> Size sz -> Size sz -> Css) -> Size sz -> Css
ev f x = f x x x x
#+end_src

[[f:rgbHex]] converts a hex number into a CSS ~Color~ value.

#+name: f:rgbHex
#+begin_src haskell
rgbHex :: Int -> Color
rgbHex rgb'
  | rgb' > 0xffffff = rgbHex 0xffffff
  | rgb' < 0 = rgbHex 0
  | otherwise = rgb rr gg bb
  where
    rr = fromIntegral $ shiftR rgb' 16 .&. 0xFF
    gg = fromIntegral $ shiftR rgb' 8 .&. 0xFF
    bb = fromIntegral $ rgb' .&. 0xFF
#+end_src
