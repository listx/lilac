#+title: Release Notes

* Versions

** v0.2.0.0 WIP

Changes:

  - Glossary terms are both more strictly parsed, but also more flexible.

    The most notable difference is that they must be written inside unordered
    list items; if they are written anywhere else, they are parsed as regular
    paragraphs. COMMIT

    Glossary terms may no longer be nested.

    If the first item of an unordered list is a glossary term, then all
    subsequent items at that list level must also be glossary terms. Conversely
    if the first item is not a glossary term, then none of the list items at
    that level may be a glossary term. This is called the uniformity rule, see
    [[id:5a7a9462-83e3-4096-b65e-18b33420f528][Uniformity of list items that define glossary terms]].

    Glossary terms are also more flexible now, because you can use multiple
    cells to define them (this is unlike before where we only allowed a single
    paragraph). The inspiration comes from our work on rich blocks in v0.1.0.8.
    COMMIT

    When glossary terms are first woven (at the site where they are defined), we
    no longer weave the unordered list bullets next to them (no more weaving
    glossary terms inside singleton ~<dl>~ lists). This reduces unnecessary
    indentation. COMMIT

** v0.1.0.8

Improvements:

  - Support rich blocks. You can now do ~#+begin_note~ or ~#+begin_warn~ to enclose
    other cells (except headings) inside a box. These are also called alerts,
    callouts, admonition blocks, or advisory blocks in other systems. Only the
    note and warning types get different colors. If you add an unrecognized rich
    block like ~#+begin_hello~, it will look plain.

      - commit c048d2ab ("parser: support rich blocks", 2026-08-01)

      - commit b11b691d ("weave: support rich blocks", 2026-08-01)

  - Explain how to bring in Lilac into a Nix configuration. commit 4a440910
    ("user manual: explain how to install Lilac from a Nix config", 2026-07-24)

  - Stylize example, note, and warning blocks. commit 76249feb ("weave: stylize
    miscellaneous blocks", 2026-07-26)

Changes:

  - Prefer "block" instead of "code block" to refer to ~#+begin_...~ and ~#+end_...~
    constructs. commit 67ab56e2 ("rename "code-block" to just "block"",
    2026-07-25)

  - Slightly reduce indentation of list items. commit aa827501 ("css: slightly
    reduce indentation of list items", 2026-07-30)
