#+title: Release Notes

* Versions

** v0.3.0.0

Improvements:

  - Link to the repo in the navbar. ~repo~ was a required key in ~Lilac.toml~
    ([[id:f5938bb2-e769-4b55-805c-dee0360fccf8::data:RawProjectConf][data:RawProjectConf]]), but nothing ever read the ~repo~ field of
    [[id:f5938bb2-e769-4b55-805c-dee0360fccf8::data:ProjectConf][data:ProjectConf]]. Now the navbar links to it with a small branch icon,
    between the project name and the version, and the key is optional.
    a7068052 (weave: link to the repo in the navbar, 2026-11-04)

Changes:

  - Lists are parsed more strictly, as documented. Existing documents that break
    these rules will now fail to compile.

      - Top-level lists must use exactly 2 spaces of indentation. 0f304cfa
        (parse: require exactly 2 spaces for top-level lists, 2026-10-31)

      - A table cannot be on the same line as a list item head. 6fc6dbba (parse:
        reject tables on the list head line, 2026-10-31)

      - Setting ~lilac_maxListLevel~ to a negative value now prohibits lists.
        64867177 (parse: enforce lilac\_maxListLevel < 0, 2026-10-31)

  - Detect broken links in more cells.
    [[id:01da95fe-ba23-4481-9833-428423392f5f::f:findExternalOids][f:findExternalOids]] didn't look inside footnote bodies, glossary terms, or
    figure and table captions. A broken link in these places passed
    [[id:a9bad6d4-5b1c-48de-8f09-178724859381::f:findBrokenLinks][f:findBrokenLinks]] and was woven by [[id:a63d2021-2596-4c43-81e3-d08e90077f75::f:showBrokenLink][f:showBrokenLink]] as
    ~LILAC_BROKEN_LINK~. Now it looks in these places too. This didn't reveal any
    broken links in our docs, but other documents with such links now fail to
    compile. 2c29ca29 (compile: detect broken links in more cells, 2026-11-02)

  - Remove the TOC click handler. In
    [[id:c4c13ce7-23d9-49d9-8d3f-6faecf839afa::ns:lilac.toc-active-entries][ns:lilac.toc-active-entries]], the click handler for TOC links had
    ~#(reset! visible-headings #{})~, which only created a function and never
    called it. So the reset of the visible headings never ran. Removing the
    handler doesn't change behavior, because of this. We removed it instead of
    repairing it because the Intersection Observer only reports changes. A
    heading that stays visible would not get added back after a reset, so it
    would lose its highlight. f2607b77 (frontend: remove the TOC click handler,
    2026-11-02)

  - Contributors must now add a ~Co-Authored-by~ trailer naming the AI model
    they used, if AI wrote most of the code in a commit. bd97a3c3 (index: add an
    AI policy for contributors, 2026-11-02)

Fixes:

  - Make the files generated by ~lilac init~ work with ~make~, and don't fail at
    the end of ~lilac init~ because the generated files are not tracked by Git
    yet. ~lilac init~ now runs only the tangle and weave targets, and tells you to
    ~git add~ the generated files before running ~make~.

      - ac858305 (cli: fix files generated by lilac init, 2026-11-01)

      - a585df8d (cli: skip lint at the end of lilac init, 2026-11-01)

  - Escape blocks in languages that Skylighting doesn't know. When Skylighting
    didn't know a block's language (such as ~gitignore~ or ~haskell-cabal~),
    [[id:e4cc0d4f-b129-4d94-be1c-3c0212527ae7::f:colorizeText][f:colorizeText]] wrote the block text into the HTML without escaping it.
    So a ~gitignore~ block with ~a<b>c & d~ in it got a real ~<b>~ tag, and our
    own woven ~build.org~ had a raw ~base >=4.7 && <5~ in it. Now the fallback
    escapes the text, but keeps the Noweb links in it. 5550e8ea (weave: escape
    blocks in unknown languages, 2026-11-04)

  - Fix document links in archives with empty objects.
    [[id:b9c034c1-5499-44e6-855c-6c16e1693cb8::f:mkArchive][f:mkArchive]] dropped objects without any cells before
    [[id:b9c034c1-5499-44e6-855c-6c16e1693cb8::f:docOidsToSymbols][f:docOidsToSymbols]] gave each document its negative ~GCI~. But
    [[id:b9c034c1-5499-44e6-855c-6c16e1693cb8::f:gciToObjPath][f:gciToObjPath]] and [[id:e4cc0d4f-b129-4d94-be1c-3c0212527ae7::f:weaveLinkTargetLinkOid][f:weaveLinkTargetLinkOid]] turned a negative
    ~GCI~ back into a path by indexing into ~sort $ keys archive.objects~, which
    still had the empty objects. So if an archive had an empty ~a.org~, a link to
    all of ~b.org~ pointed to ~/a.html~ instead. Now every object gets its
    negative ~GCI~, including the empty ones, so links to an empty document work
    too. 8aa172e4 (compile: count empty objects in document symbols, 2026-11-04)

  - Report each Noweb cycle only once.
    [[id:b9c034c1-5499-44e6-855c-6c16e1693cb8::f:getBlocksFromArchive][f:getBlocksFromArchive]] went through ~elems archive.symbols~, so it
    returned a block once for every symbol that points to it (its name under the
    document OID, under the parent heading's OID, and every line label in it).
    [[id:b9c034c1-5499-44e6-855c-6c16e1693cb8::f:findCycles][f:findCycles]] then reported the same cycle several times; a block that
    refers to itself and has two line labels was reported 3 times. Now each
    block is only looked at once. 29d1c87a (compile: report each Noweb cycle
    only once, 2026-11-04)

  - Make styled text survive the round trip back to text. The prose for ~toText~
    in the ~CiteprocOutput~ instance for ~Prose~ says that there is no loss of
    information going from ~Text~ to ~Prose~ and back. But
    [[id:442c807f-c9d9-45a7-88bf-d38cbbca09cf::f:unparseStyledText][f:unparseStyledText]] did not escape backslashes, nor ~=~ inside verbatim
    text or ~\~~ inside code text, so such text did not survive the round trip.
    Now it escapes the same characters that the parser accepts after a
    backslash. 63aa52a2 (parse: escape backslashes when unparsing styled text,
    2026-11-04)

  - Only treat ~index.org~ as an index.
    [[id:b9c034c1-5499-44e6-855c-6c16e1693cb8::f:isIndexObjPath][f:isIndexObjPath]] only checked that the path ends in ~index.lobj~, so a
    file like ~appendix-index.org~ was treated as an index too, and then
    [[id:b9c034c1-5499-44e6-855c-6c16e1693cb8::f:getChildPaths][f:getChildPaths]] dropped the wrong prefix when it removed the last 10
    characters. Now it checks the file name instead. 577d6fb5 (compile: only
    treat index.org as an index, 2026-11-04)

  - Show links inside glossary terms in the backlink popup of their target.
    Before, such links were checked, but only links in the definition of a
    glossary term showed up there. ffd5846e (compile: record precise backlinks
    from glossary terms, 2026-11-04)

  - Make ~href->id~ use its argument.
    [[id:48d6dc87-f5fc-4a36-bef4-85b9d4207f05::f:href->id][f:href->id]] ignored its argument and read the anchor of the current URL.
    So when the URL had no anchor (or one that didn't match any element),
    clicking on a link didn't find an element, and the browser did its default
    jump. The page then scrolled even if the target was already visible, which
    is what lazy scrolling is supposed to prevent. Now it uses its argument. We
    also removed its ~#top~ fallback, which never applied, because
    [[id:48d6dc87-f5fc-4a36-bef4-85b9d4207f05::f:maybe-scroll-by-hash][f:maybe-scroll-by-hash]] calls this function on page load and woven pages
    have an element with the ~top~ ID. 2dbb383c (frontend: make href->id use its
    argument, 2026-11-02)

  - Make the collapse button label change.
    [[id:3d4c0326-ee40-43d5-b49b-ab72081ae91a::css:Block controls inline][css:Block controls inline]] changes the button label to "Collapse contents"
    if the button has the ~action-collapse~ class, but nothing ever set this
    class. So the button said "Expand contents" even when the block was
    expanded. Now [[id:9c8e1074-edfb-4f89-bedf-07527981835d::f:render-block!][f:render-block!]] sets it whenever the body is visible.
    8592882b (frontend: make the collapse button label change, 2026-11-02)

  - Keep link targets just below the navbar. The scroll padding still assumed
    the navbar was 4rem tall after it shrank to 3rem, so link targets ended up
    1rem lower than intended. c1ab26a4 (weave: use the navbar height for
    scroll-padding-top, 2026-11-04)

  - Avoid duplicate HTML IDs for figures.
    [[id:4eea4449-2418-42c5-86e4-af63c3b742e3::f:weaveFigure][f:weaveFigure]] gave both ~figure_~ and ~img_~ the same ~id~. We removed it
    from ~img_~. 852c3a5f (weave: avoid duplicate HTML IDs for figures,
    2026-11-01)

  - Make the footer link always lead to Lilac. The "Generated by Lilac" link in
    [[id:797b6f06-64e0-4bf7-946f-055994ff160f::f:weaveFooter][f:weaveFooter]] went to the project's own homepage if one was configured,
    and only fell back to Lilac's repo URL otherwise. So for other projects
    using Lilac, the link might not have led to Lilac. Now it always goes to
    Lilac's homepage. 5dc3c33f (weave: make the footer link always lead to
    Lilac, 2026-11-01)

  - Add the missing space in the names of anonymous blocks, which were woven
    as "Anonymous BlockCell 63". cf2cade1 (compile: add the missing space in
    anonymous block names, 2026-11-04)

  - Fix the grammar of two parse error messages. 2f785c8c (parse: fix the
    grammar of two error messages, 2026-11-04)

  - Stop ~tangle-loop.sh~ checks if tangling fails. The prose says that later
    steps abort if an earlier one fails, but in
    [[id:77786b08-6211-47b8-940d-6aaefc17ec47::f:tangle-loop:run_all_checks][f:tangle-loop:run\_all\_checks]] a failed tangle only skipped the tests and
    still went on to weave. Now a failed tangle skips the later steps, without
    ending the loop. 53553ae0 (tangle-loop: skip later checks if tangling fails,
    2026-11-01)

Changes:

  - Line labels now have a popup link next to them, such that clicking on it
    shows you a list of all references to it. This ended up being a surprising
    amount of work because it touched every part of the pipeline, from parsing
    to the frontend:

      - Create the concept of unique link indexes (similar to cell indexes)
        during parsing.

          - commit 3d017e44 ("parse: track the current link number (index) with
            linkNumber", 2026-09-25)

          - commit 61770c80 ("parser: PTokenLink: track link index (incrementing
            number)", 2026-09-25)

      - Construct OID aliases and precise backlinks during compilation. commit
        10cd3625 ("compile: generate fine-grained backlinks", 2026-09-26)

      - Embed precise backlink data into line labels during weaving. commit
        1b9c29e3 ("weave: encode precise backlinks for line labels", 2026-10-09)

      - Construct popups in frontend. commit 32fa69d4 ("frontend: fully render
        precise backlinks in popups", 2026-10-09)

    This work also exposed a design flaw with our data structures --- namely
    that we have a somewhat inadequate representation of links. Doing a larger
    refactor here is probably too much work (where if we decided to do this, we
    might consider rewriting the entire program).

  - Links from child blocks to parent blocks now target the exact location where
    the child block was referenced. Previously, the child block referenced the
    entire parent block, which meant that it could be hard to see where the
    child was used (especially for larger parent blocks with many different
    child blocks). commit 0baad1dc ("weave blocks: link back to parent blocks
    more precisely", 2026-08-17)

  - Glossary terms are both more strictly parsed, but also more flexible. See
    [[id:f6347c2d-e4fd-4741-8404-aa6a43784820][Multicell Glossary Items]].

    The most notable difference is that they must be written inside unordered
    list items; if they are written anywhere else, they are parsed as regular
    paragraphs. commit e88c1d94 ("glossary terms: only recognize them in
    unordered list items", 2026-08-11)

    Glossary terms may no longer be nested. commit 72e973c9 ("glossary: forbid
    nesting of glossary terms", 2026-08-11)

    If the first item of an unordered list is a glossary term, then all
    subsequent items at that list level must also be glossary terms. Conversely
    if the first item is not a glossary term, then none of the list items at
    that level may be a glossary term. This is called the uniformity rule, see
    [[id:5a7a9462-83e3-4096-b65e-18b33420f528][Uniformity of list items that define glossary terms]]. commit c94f41be
    ("glossary terms: implement uniformity rule", 2026-08-16)

    Glossary terms are also more flexible now, because you can use multiple
    cells to define them (this is unlike before where we only allowed a single
    paragraph). The inspiration comes from our work on rich blocks in v0.1.0.8.
    commit 2b38bfd3 ("weave: weave multicell glossary terms", 2026-08-16)

    When glossary terms are first woven (at the site where they are defined), we
    no longer weave the unordered list bullets next to them (no more weaving
    glossary terms inside singleton ~<dl>~ lists). This reduces unnecessary
    indentation. commit 2b38bfd3 ("weave: weave multicell glossary terms",
    2026-08-16)

Fixes:

  - Long breadcrumbs are truncated if needed. They no longer bleed over the
    navbar if they're too long. commit 8b6f6cb5 ("weave: optionally truncate
    long breadcrumbs", 2026-09-20)

  - Replace the correct extension for filenames in breadcrumbs. commit ce89e7f9
    ("weave: only replace the last extension of the breadcrumb", 2026-09-25)

** v0.1.0.8

Improvements:

  - Support rich blocks. You can now do ~#+begin_note~ or ~#+begin_warning~ to enclose
    other cells (except headings) inside a box. These are also called alerts,
    callouts, admonition blocks, or advisory blocks in other systems. Only the
    note and warning types get different colors. If you add an unrecognized rich
    block like ~#+begin_hello~, it will look plain.

      - commit c048d2ab ("parser: support rich blocks", 2026-08-01)

      - commit b11b691d ("weave: support rich blocks", 2026-08-01)

  - Explain how to bring in Lilac into a Nix configuration. commit 4a440910
    ("user manual: explain how to install Lilac from a Nix config", 2026-07-24)

  - Stylize example, note, and warning blocks. commit 76249feb ("weave: stylize
    miscellaneous blocks", 2026-07-26)

Changes:

    constructs. commit 67ab56e2 ("rename "code-block" to just "block"",
