* Tangling
:PROPERTIES:
:ID:       b449a097-d702-4fd6-98de-cb81f7e49177
:END:

In Literate Programming, /tangling/ is the act of extracting the source code out
of a literate document. It is the opposite of documentation generation found in
many programming language environments, such as =javadoc=, where documentation is
extracted from source code.

** Tangling overview

Tangling essentially boils down to the following:

  1) find all code blocks that need to get tangled (they have ~#+header: :tangle
     ...~ in their metadata), and

  2) for each of these code blocks expand any Noweb references in them until
     none are left, and finally

  3) write the files to disk (but only for those files that are different than
     what we already have on disk).

The first two steps are the bare minimum required in order to feed source code
to the computer for interpretation by it, while the third is a way to avoid
unnecessarily busting the modification timestamp cache for Makefiles (because
they use file modification timestamps to see whether we need to rerun a rule).

** Block expansion for tangling

We examine the given [[id:25827c17-2015-434b-b686-db3d72b2ee4d::data:Archive][data:Archive]] for all of the root blocks (blocks which
specify the ~:tangle~ header, and thus require writing to the file system) in it,
and expand each one in turn in [[f:expandRootBlocks]]. The output is a list of
tuples, where each tuple encodes the filesystem path where we want to write some
text (as a result of tangling), and the contents of the text itself which we
want to write there --- hence the type is ~(OsPath, Text)~.

The call to ~maybeAddShebang~ adds a special shebang line at the beginning of the
file, if one was specified using the ~:shebang~ header. See [[id:caa38bf7-52ae-4246-8be0-8b2c9e58ccc2::unit-test.sh][unit-test.sh]] for an
example.

We also trim lines with only spaces in them (in ~trimTrailingSpaces~), because
these can happen from the ~prependExistingPrefix~ function in [[f:expandBlock]].

#+name: f:expandRootBlocks
#+begin_src haskell
expandRootBlocks :: Archive -> OsPath -> [(OsPath, Text)]
expandRootBlocks archive outDir = map expandRootBlock rootBlocks
  where
    rootBlocks =
      concat $ foldl' getRootBlocksFromObject [] archive.objects
    getRootBlocksFromObject ::
      [[(OsPath, Block)]] ->
      Object ->
      [[(OsPath, Block)]]
    getRootBlocksFromObject acc object =
      foldl' getRootBlock [] object.symbols : acc
    getRootBlock acc cell = case cell of
      CBlock b
        | Just tPath <- lookup "tangle" b.meta,
          Just tOsPath <- P.encodeUtf $ T.unpack tPath ->
            (P.combine outDir tOsPath, b) : acc
        | otherwise -> acc
      CHeading {}
      CListItem {}
      CParagraph {}
      CMathFragment {}
      CFigure {}
      CTable {}
      CFootnote {}
      CBibliography {} -> acc
    expandRootBlock :: (OsPath, Block) -> (OsPath, Text)
    expandRootBlock (p, rootBlock) =
      ( P.combine outDir p,
        maybeAddShebang rootBlock
          . trimTrailingSpaces
          $ expandBlock archive rootBlock ""
      )
    trimTrailingSpaces :: Text -> Text
    trimTrailingSpaces text =
      T.unlines
        . map (T.dropWhileEnd (== ' '))
        $ T.lines text
    maybeAddShebang :: Block -> Text -> Text
    maybeAddShebang rootBlock text
      | Just shebang <- lookup "shebang" rootBlock.meta =
          shebang <> "\n" <> text
      | otherwise = text
#+end_src

In [[f:expandBlock]], we recursively expand all Noweb links until there are none.

#+name: f:expandBlock
#+begin_src haskell
expandBlock :: Archive -> Block -> Text -> Text
expandBlock archive block existingPrefix =
  let acc = "" :: Text
      prefix = "" :: Text
   in fst $ foldl' expand (acc, prefix) block.body
  where
    expand (acc, _) BTokenPadding =
      (acc <> "\n", "")
    expand (acc, _) (BTokenString text) =
      (acc <> prependExistingPrefix text, getPrefix text)
    expand (acc, prefix) (BTokenLink (Link _ (LinkTargetOid linkOid)))
      | Just (CBlock targetBlock) <- lookup linkOid archive.symbols =
          ( acc <> (expandBlock archive targetBlock $ existingPrefix <> prefix),
            prefix
          )
      | otherwise = (acc, prefix)
    expand (acc, prefix) _ = (acc, prefix)
    getPrefix text = T.takeWhileEnd (/= '\n') text
    prependExistingPrefix text =
      T.intercalate "\n"
        . reverse
        . fst
        . foldl' prefixTailLines ([], True)
        $ T.split (== '\n') text
    prefixTailLines (acc, isFirstLine) line
      | isFirstLine = (line : acc, False)
      | otherwise = (T.append existingPrefix line : acc, False)
#+end_src

The ~expand~ function recursively calls ~expandBlock~ if it detects a ~LinkOid~ type
link. Otherwise, for ~BTokenString~ tokens it searches for an indentation prefix
with ~getPrefix~. We need the prefix because we want to indent entire blocks if
the name of the link referring to it is indented. See
[[t:0101-block-expansion-prefix]] and [[t:0101-block-expansion-prefix-nested]] for
examples.

The ~getPrefix~ function is simple and uses any characters it finds, not just
spaces, looking backwards and stopping at a newline. See
[[t:0101-block-expansion-prefix-nonspace]] and
[[t:0101-block-expansion-prefix-nonspace-nested]] for examples.

The ~prependExistingPrefix~ function splits up the given text, and injects the
prefix on every line in the text except the very first line. This is because
given the text

#+header: :noweb off
#+begin_src txt
xx<<a>>
#+end_src

where ~xx~ is the prefix, we only want to give this prefix to the lines in ~<<a>>~
except the first line (because the first line of ~<<a>>~ is already prefixed (from
the outer block) with ~xx~); so only the lines after the first line in ~<<a>>~ need
the ~xx~ prefix. This is what we do in ~prefixTailLines~, where we avoid adding the
prefix to the "head", and instead only add it to the "tail."

We use ~T.intercalate~ and ~T.split~ in ~prependExistingPrefix~ to avoid losing any
information about the exact locations of newlines. If we used ~T.lines~ we would
lose information about whether the last line actually had a trailing newline,
because ~T.lines "a\nb"~ and ~T.lines "a\nb\n"~ both give ~["a", "b"]~.

#+name: t:lines-unlines-info-loss
#+begin_src haskell
it "loses information" $ do
  let withoutNewline = T.lines "a\nb"
      withNewline = T.lines "a\nb\n"
  T.unlines withoutNewline `shouldBe` T.unlines withNewline
#+end_src

The [[f:checkExpansion]] function expands all source code blocks (found in the
collection of Org documents, first converted into a [[id:25827c17-2015-434b-b686-db3d72b2ee4d::data:Archive][data:Archive]]) and compares
them with the expected output.

#+name: f:checkExpansion
#+begin_src haskell
checkExpansion :: [FilePath] -> [(FilePath, Text)] -> Spec
checkExpansion paths expectedExpansions = do
  pathObjs <- runIO $ LC.readObjectsFrom "test/Lilac/TangleSpec/" paths
  case LC.mkArchive pathObjs of
    Left errMsg -> it "programmer error" $ expectationFailure errMsg
    Right archive -> it (show paths) $ do
      (LT.expandRootBlocks archive mempty)
        `shouldBe` (fmap (first P.unsafeEncodeUtf) expectedExpansions)
#+end_src
