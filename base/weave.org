#+title: Weave

* Overview

In most Literate Programming systems, /weaving/ is the act of generating a
human-readable document. This usually means writing a PDF or an HTML page.

For now, Lilac's main goal is to generate *HTML pages*. There are several
reasons:

  1) HTML is easier to consume on the web than PDFs.

  2) PDFs are obsessed with page numbers because they are designed to be printed
     on real physical paper; we don't care about page numbers at all because you
     don't have to print web content in order to consume it.

  3) We want to make our HTML pages somewhat interactive, and interactivity is
     easier to accomplish in HTML.

Because we generate HTML, we also have to decorate it with CSS. Both concerns
are addressed in this doc. There is also a sprinkling of JavaScript (via
[[https://clojurescript.org/][ClojureScript]]) in [[id:6d407e24-fb34-460a-83bd-7b39cf7a56bb][Frontend]] for some interactivity.

The architecture for weaving looks like this:

  1) Convert the [[id:01da95fe-ba23-4481-9833-428423392f5f::data:Object][data:Object]] (found inside a [[id:25827c17-2015-434b-b686-db3d72b2ee4d::data:Archive][data:Archive]], which is just a JSON
     file) into HTML.

  2) Generate CSS separately.

  3) Add some JS for interactivity.

One main advantage of this model is that other "viewers" can be created, as long
as they understand the same JSON. While we would prefer to use something more
"typed" like [[https://protobuf.dev/][Protobufs]], [[https://github.com/cognitect/transit-clj][Transit]], or [[https://github.com/edn-format/edn][EDN]], we choose JSON for its universality.
Also, none of these alternative formats support both Haskell and ClojureScript
well.

** Project configuration
:PROPERTIES:
:ID:       df128041-ada8-4d77-a373-111416002dae
:END:

The starting point of weaving is the concept of /project configuration/. Project
configuration defines some global settings that apply to all weavable artifacts
found in a [[id:25827c17-2015-434b-b686-db3d72b2ee4d::data:Archive][data:Archive]], which itself is composed of a collection of [[id:01da95fe-ba23-4481-9833-428423392f5f::data:Object][data:Object]]
values. Project configuration is encoded in [[data:ProjectConf]].

#+name: data:ProjectConf
#+begin_src haskell
type ProjectConf :: Type
data ProjectConf = ProjectConf
  { name :: Text, -- (ref:data:ProjectConf-name)
    homepage :: Maybe N.URI, -- (ref:data:ProjectConf-homepage)
    repo :: Maybe N.URI, -- (ref:data:ProjectConf-repo)
    version :: Maybe Text -- (ref:data:ProjectConf-version)
  }
  deriving stock (Eq, Generic, Show)
  deriving anyclass (FromJSON, ToJSON)
#+end_src

The fields are:

  - name :: [[(data:ProjectConf-name)]] Name of the project. This is used in the
    [[id:35d768c0-3e2f-498a-8437-e4137c4500ba][Navigation bar]].

  - homepage :: [[(data:ProjectConf-homepage)]] URL of the homepage. This is used as
    the link target to describe the ~name~ in the navbar. It could very well be
    the case that this target merely points to one of the other woven object
    files.

  - repo :: [[(data:ProjectConf-repo)]] URL of the source code repository (the
    assumption being that the Org docs and tangled files are all open source and
    belonging to the same Git repo).

  - version :: [[(data:ProjectConf-version)]] Human-friendly version information.
    This is used in the [[id:35d768c0-3e2f-498a-8437-e4137c4500ba][Navigation bar]].

Project configuration isn't part of [[id:25827c17-2015-434b-b686-db3d72b2ee4d::data:Archive][data:Archive]] because it may be the case in
the future that a single project could be used for multiple archive files.

*** Simple project configuration
:PROPERTIES:
:ID:       a7de905c-03c8-4d4b-911c-b1f4435aea85
:END:

The [[data:ProjectConf]] would be very difficult to use if we expect users to write
the JSON version of it manually, because it is a precise type (e.g., writing the
value of a ~URI~ can be painful). So instead we let users write a simplified
version of it in JSON (as [[data:RawProjectConf]]), using plain ~Text~ values for the
fields. During weaving we parse this and convert it to [[data:ProjectConf]].

#+name: data:RawProjectConf
#+begin_src haskell
type RawProjectConf :: Type
data RawProjectConf = RawProjectConf
  { name :: Text,
    homepage :: Text,
    repo :: Text,
    version :: Text
  }
  deriving stock (Eq, Generic, Show)
  deriving anyclass (FromJSON, ToJSON)
#+end_src

#+name: f:parseRawProjectConf
#+begin_src haskell
parseRawProjectConf :: Text -> Either String RawProjectConf
parseRawProjectConf = eitherDecodeStrictText
#+end_src

[[f:parseProjectConf]] relies on [[f:parseRawProjectConf]] for the initial parse, and
some additional helpers like ~N.parseURI~.

#+name: f:parseProjectConf
#+begin_src haskell
parseProjectConf :: Text -> Either String ProjectConf
parseProjectConf input = case parseRawProjectConf input of
  Left errMsg -> Left errMsg
  Right rawProjectConf ->
    Right
      ProjectConf
        { name = rawProjectConf.name,
          homepage = N.parseURI $ T.unpack rawProjectConf.homepage,
          repo = N.parseURI $ T.unpack rawProjectConf.repo,
          version =
            if T.null rawProjectConf.version
              then Nothing
              else Just rawProjectConf.version
        }
#+end_src

** =HtmlWeaver= monad
:PROPERTIES:
:ID:       300d21e2-000b-4d65-971a-7a1452725d27
:END:

During the weaving process, we want to access various other settings that may
not be apparent at the [[id:ed81c307-9172-4436-8672-583ea8ecb1f9::data:Cell][data:Cell]] level. To capture these values in one place, we
use a [[data:WeaveConf]]. Instead of passing this around to all functions, we put it
inside a ~ReaderT~ so that it is available for all weave-related functions that
are using the [[type:HtmlWeaver]]. This is analogous to [[id:6cf4d5a5-ec4a-426e-8549-0a899ad77729::data:OrgParserState][data:OrgParserState]] which is
available to all parsing functions in [[id:e16dd5c7-0a63-4c52-afe9-744fdf853643::type:OrgParser][type:OrgParser]].

#+name: data:WeaveConf
#+begin_src haskell
type WeaveConf :: Type
data WeaveConf = WeaveConf
  { projectConf :: ProjectConf,
    archive :: Archive,
    originObjectPath :: GPath, -- (ref:data:WeaveConf-originObjectPath)
    outDir :: GPath,
    citeprocResult :: CP.Result Prose
  }
#+end_src

The ~originObjectPath~ [[(data:WeaveConf-originObjectPath)]] is used to check whether
a given [[id:f8254d58-7a3d-4595-a265-e0d6255e6ab5::data:LinkOid][data:LinkOid]] refers to a cell that exists in the current object being
woven in [[f:weaveObject]] (so we know whether to refer to the cell with just ~#...~
as the HTML ~id~ attribute, or whether as ~path/to/external/object.html#...~ because
the cell belongs to another object).

The [[type:HtmlWeaver]] is a monad. We stack ~ReaderT~ on top of Lucid's ~HtmlT~ to
create the monadic environment where we can read from [[data:WeaveConf]] whenever we
want.

#+name: type:HtmlWeaver
#+begin_src haskell
type HtmlWeaver :: Type -> Type
type HtmlWeaver a = HtmlT (ReaderT WeaveConf Identity) a
#+end_src

Note that the inner monad is the ~ReaderT~. This way we don't have to call ~lift~
every single time we want to use a Lucid combinator like ~head_~ or ~body_~.

Now we just need a starting point for using ~HtmlWeaver~. For weaving, the final
thing we want to generate is a ~Text~ value. Lucid gives us ~renderTextT~, which can
run inside a monad. This means we can use that to generate ~Text~ from
[[type:HtmlWeaver]]; this is what [[f:renderAsText]] does.

[[f:renderAsText]] takes a ~WeaveConf~ and an ~HtmlWeaver a~ action, and converts it to
a ~Text~ type. It's there because we cannot use any of the default rendering
functions that Lucid gives us (because they operate on Lucid's ~HtmlT~, not the
~HtmlWeaver~ we use).

#+name: f:renderAsText
#+begin_src haskell
renderAsText :: WeaveConf -> HtmlWeaver a -> Text
renderAsText weaveConf weaver =
  TL.toStrict
    . renderText
    $ hoistHtmlT (flip runReaderT weaveConf) weaver
#+end_src

The ~hoistHtmlT~ function is a convenience helper provided by Lucid, which is
equivalent to ~hoist~ from [[https://hackage.haskell.org/package/mmorph][=Control.Monad.Morph=]]. It applies a function to the
inner monad of ~HtmlT~ (recall that [[type:HtmlWeaver]] is just a ~HtmlT~ whose inner
monad is a ~ReaderT~). So in this case the inner monad is ~ReaderT WeaveConf
Identity~, and running ~runReaderT~ will result in ~Identity ()~ (where ~()~ is the ~a~
in the type signature for [[f:renderAsText]]). So then the call to ~hoistHtmlT~ gives
us ~HtmlT Identity a~, which is what Lucid's ~renderText~ expects.

** CSS generator
:PROPERTIES:
:ID:       7147b743-084d-4abc-8561-5417c7fe10b3
:END:

[[f:genCss]] is the main top-level function which generates the CSS. There are two
main parts: one is the syntax highlighting theme which uses a modified variation
of the ~kate~ theme from [[https://hackage.haskell.org/package/skylighting][=Skylighting=]] (see [[f:kateLilac]]), and the other is the
rest of Lilac ([[f:defaultCss]]) which uses the [[https://hackage.haskell.org/package/clay][Clay]] CSS preprocessor. These two
parts are concatenated together in [[f:genCss]], so that Lilac's settings take
precedence if there are any conflicts with the =Skylighting= parts.

#+name: f:genCss
#+begin_src haskell
genCss :: Text
genCss =
  T.unlines
    [ T.pack $ Sky.styleToCss kateLilac,
      TL.toStrict $ renderWith pretty [] defaultCss
    ]
#+end_src

We make a small tweak to =kate= to make some colors easier on the eyes. The
~ExtensionTok~ by default is too bright, so we darken it a bit here
[[(f:kateLilac-ExtensionTok)]].

#+name: f:kateLilac
#+begin_src haskell
kateLilac :: Sky.Style
kateLilac =
  Sky.kate
    { Sky.tokenStyles =
        insert
          Sky.ExtensionTok -- (ref:f:kateLilac-ExtensionTok)
          ( Sky.defStyle
              { Sky.tokenColor = Just (Sky.RGB 0 0x60 0xa4),
                Sky.tokenBold = True
              }
          )
          Sky.kate.tokenStyles
    }
#+end_src

** Sizing

We prefer to use ~rem~ (root element) over ~em~ (element), because ~rem~ doesn't
compound over nested elements like ~em~ does.

*** Helpers

[[f:yx]] is a horizontal/vertical size helper. It accepts a function and two sizes
for the horizontal and vertical parts. E.g., instead of calling

#+begin_src haskell
padding (px 6) (px 10) (px 6) (px 10)

** Colors

[[https://hackage.haskell.org/package/clay][Clay]] uses its own internal ~Color~ type, which can only be constructed from
integer values. However we want to talk about colors using strings because using
something like ~#22ffff~ can allow Emacs to colorize it in the buffer, aiding
visualization.

[[f:colorFrom]] converts a ~Text~ into a ~Color~, defaulting to ~#ff0000~ (red) if parsing
fails.

#+name: f:colorFrom
#+begin_src haskell
colorFrom :: Text -> Color
colorFrom input = fromMaybe (rgb 255 0 0) $ MP.parseMaybe hexColorParser input
#+end_src

This depends on [[f:hexColorParser]] which uses
~Text.Megaparsec.Char.Lexer.hexadecimal~ and checks the numeric bounds before
retrieving the red, green, and blue values from the number using bit masks.

#+name: f:hexColorParser
#+begin_src haskell
hexColorParser :: ColorParser Color
hexColorParser = do
  _ <- char '#'
  n <- hexadecimal
  let c
        | n > 0xffffff = rgb 255 255 255
        | n < 0 = rgb 0 0 0
        | otherwise = rgb rr gg bb
        where
          rr = 0xff .&. shiftR n 16
          gg = 0xff .&. shiftR n 8
          bb = 0xff .&. n
  pure c
#+end_src

The ~ColorParser~ is a type synonym for a "standard" Megaparsec type defined in
the [[https://hackage.haskell.org/package/megaparsec-9.7.0/docs/Text-Megaparsec.html][documentation]].

#+name: type:ColorParser
#+begin_src haskell
type ColorParser :: Type -> Type
type ColorParser = MP.Parsec Void Text
#+end_src

The [[f:weaveObject]] function sets up the main HTML bits (like the title, head,

#+name: f:weaveObject

  <<HTML head>>

    weaveNavbar

    weaveMain object.orgDoc.meta lciCellPairs

[[f:sortFootnoteCells]] sorts footnote definition cells by the order in which they
are referenced [[(f:sortFootnoteCells-getFootnoteNumber)]]. This way, users don't
have to keep them in order in the doc (users can freely change which ones are
referenced first, without having to manually reorder the footnote definitions).
In Orgmode users can already press ENTER on a footnote reference and Orgmode
will jump to the definition, so manual ordering doesn't matter much even in that
case.

#+name: f:sortFootnoteCells
#+begin_src haskell
sortFootnoteCells :: Object -> [(LCI, Cell)]
sortFootnoteCells object =
  beforeFootnotes
    <> sortedFootnotes
    <> afterFootnotes
  where
    lciCellPairs = zip (map LCI [0 :: Int ..]) object.orgDoc.cells
    beforeFootnotes = takeWhile (not . isFootnote) lciCellPairs
    afterFootnotes =
      dropWhile isFootnote
        $ dropWhile (not . isFootnote) lciCellPairs
    sortedFootnotes =
      sortOn (\(_, cell) -> getFootnoteNumber cell)
        $ takeWhile isFootnote
        $ dropWhile (not . isFootnote) lciCellPairs
    getFootnoteNumber cell -- (ref:f:sortFootnoteCells-getFootnoteNumber)
      | (CFootnote footnote) <- cell,
        Just (n, _) <- lookup footnote.name object.orgDoc.footnoteRefs =
          n
      | otherwise = maxBound :: Int
    isFootnote :: (LCI, Cell) -> Bool
    isFootnote (_, cell) = case cell of
      CFootnote {} -> True
      _ -> False
#+end_src

Weaving cells just means delegating to each of the weavers that know how to
handle each cell type.

It may sound a bit surprising to let MathJax perform the numbering when we
already have this numbering information on hand from the

way MathJax numbers equations is the same. In other words, we can let MathJax

should line up with what we have.

necessary for making it ignore verbatim and code styles from [[id:d6abea81-d620-4ede-9c2c-68f7ea07f847::f:weaveStyledText][f:weaveStyledText]].

}

* Unique names
:PROPERTIES:
:ID:       7ddbd51b-fbac-4bf7-a14e-982ab753c879
:END:

Generating a unique name suitable for being used as the ~id~ attribute value
requires us to convert some arbitrary text into a DOM ID-friendly name. For this
purpose we have [[f:toSafeHtmlId]].

[[https://www.w3.org/TR/html4/types.html][This page]] says:

#+begin_quote
ID and NAME tokens must begin with a letter ([A-Za-z]) and may be followed by
any number of letters, digits ([0-9]), hyphens ("-"), underscores ("_"), colons
(":"), and periods (".").
#+end_quote

#+name: f:toSafeHtmlId
#+begin_src haskell
toSafeHtmlId :: Text -> Text
toSafeHtmlId = T.map onlyKeepSomeChars
  where
    onlyKeepSomeChars c
      | isAsciiLower c || isAsciiUpper c = c
      | isDigit c = c
      | T.elem c "-_:." = c
      | otherwise = '-'
#+end_src

The [[f:getLinkAnchor]] function generates the unique, human-friendly ID of a
[[id:442c807f-c9d9-45a7-88bf-d38cbbca09cf::data:Cell][data:Cell]].

#+name: f:getLinkAnchor
#+begin_src haskell
getLinkAnchor :: Maybe LCI -> Cell -> Text
getLinkAnchor maybeLCI = \case
  CHeading heading ->
    T.intercalate
      "-"
      [ "h",
        getSectionNumber heading,
        toSafeHtmlId $ getProseContents heading.body
      ]
  CListItem {} -> ""
  CParagraph {} -> case maybeLCI of
    Just lci -> "c-" <> T.show lci.unLCI
    Nothing -> ""
  CBlock block ->
    let ref
          | Just name <- lookup "name" block.meta =
              name
          | Just anonBlockNum <- lookup "__anon_block_number" block.meta =
              anonBlockNum
          | otherwise = "anon-block-error"
     in T.intercalate
          "-"
          [ "b",
            toSafeHtmlId ref
          ]
  CMathFragment mathFragment ->
    let ref
          | Just name <- lookup "name" mathFragment.meta,
            Just eqNum <- lookup "__equation_number" mathFragment.meta =
              "eq-" <> eqNum <> "-" <> name
          | Just eqNum <- lookup "__equation_number" mathFragment.meta =
              "eq-" <> eqNum
          | Just eqNum <- lookup "__equation_anon_number" mathFragment.meta =
              "eq-anon-" <> eqNum
          | otherwise = "eq-num-error"
     in toSafeHtmlId ref
  CFigure figure ->
    let ref
          | Just name <- lookup "name" figure.meta,
            Just figureNum <- lookup "__figure_number" figure.meta =
              "fig-" <> figureNum <> "-" <> name
          | Just figureNum <- lookup "__figure_number" figure.meta =
              "fig-" <> figureNum
          | otherwise = "figure-num-error"
     in toSafeHtmlId ref
  CTable table ->
    let ref
          | Just name <- lookup "name" table.meta,
            Just tableNum <- lookup "__table_number" table.meta =
              "tbl-" <> tableNum <> "-" <> name
          | Just tableNum <- lookup "__table_number" table.meta =
              "tbl-" <> tableNum
          | otherwise = "table-num-error"
     in toSafeHtmlId ref
  CFootnote footnote ->
    let ref = "footnote-" <> footnote.name
     in toSafeHtmlId ref
  CGlossaryTerm glossaryTerm -> case maybeLCI of
    Just lci ->
      let ref =
            "glossary-"
              <> "c-"
              <> T.show lci.unLCI
              <> "-"
              <> toSafeHtmlId (CP.toText @Prose $ stripLinks glossaryTerm.term)
       in toSafeHtmlId ref
    Nothing -> ""
  CCommand {} -> ""
#+end_src

We don't generate link anchors for footnote cells (~CFootnote~) because the cell
does not have information about its number. This is because unlike things like
figures or tables, the order of appearance (of this footnote definition) may not
be the same as the order of usage (when the footnote definition is referenced).
This discrepancy makes automatic numbering slightly more difficult, and we
choose to not go through that exercise for the [[id:4127feee-755d-430e-8fef-192e95143790::data:Footnote][data:Footnote]] type, for ease of parsing.

The [[f:getSectionNumber]] function just retrieves the numeric heading section number,
as a ~Text~ value.

#+name: f:getSectionNumber
#+begin_src haskell

  T.intercalate "."
    . map T.show
    . reverse
    $ heading.section

** Unique cell IDs

Every cell has a local cell index. We can use this information to give every
cell a unique ID. This ID is not human friendly, but it's good for assigning
every cell a numeric ID so that we can refer to them easily from code (we also
assign all of these a class of ~cell-idx~ so that we can select them all at once;
see [[f:lciAttrs]]).

Originally we added this code to be used for [[f:genHeadingAncestry]], but then
realized that we actually don't need it there. To clarify, we don't need to
attach a unique ID to every cell and then add observers to all of them; instead
we can just group non-heading cells underneath each heading together into a
~<div>~ to check for the intersection of that overall ~<div>~ with the viewport.

This code is still here though because eventually we want to add keyboard-driven
navigation, and for that we'll need to highlight the "current" cell, identified
by its unique ID.

* Headings
:PROPERTIES:
:ID:       c036cf17-0f61-4f07-bf76-bbe8b4eeb12e
:END:

Headings might sound simple, but because they are made up of arbitrary text,
it's fairly involved. The body of a heading is made up of a list of [[id:c8616126-215d-49be-8874-c2aca7d93a54::data:PToken][data:PToken]]
values. So, we have to weave each type of token separately.

The heading creates and closes a ~heading-container-...~ ~<div>~ element, to
essentially group all non-heading cells up to the next heading together. This is
needed for [[id:c4c13ce7-23d9-49d9-8d3f-6faecf839afa][Active headings TOC indicator]]. Specifically, grouping up cells like
this lets us easily track which parts are being viewed (and we only have to keep
track of these ~<div>~ elements, instead of tracking each cell individually).

#+name: f:weaveHeading
#+begin_src haskell
weaveHeading :: LCI -> Heading -> HtmlWeaver ()
weaveHeading lci heading = do
  when (heading.section /= [1]) $ toHtmlRaw @Text "</div>"
  let containerId = "heading-container-" <> linkAnchor
  toHtmlRaw $ "<div id=\"" <> containerId <> "\" class=\"heading-container\">"
  hN [id_ linkAnchor] $ do
    wrapWith lci $ do
      a_ [href_ $ "#" <> linkAnchor] $ do
        toHtml sectionText
        toHtmlRaw ("&emsp;&thinsp;" :: Text)
        weaveProse heading.body
  where
    hN = case heading.level of
      1 -> h2_
      2 -> h3_
      3 -> h4_
      4 -> h5_
      _ -> h6_
    sectionText = getSectionNumber heading
    linkAnchor = getLinkAnchor Nothing $ CHeading heading
#+end_src

A well-formed document should only have one ~<h1>~ HTML element (for the title of
the document). We use ~h1_~ when weaving the title of the document (if any). This
is why we start from ~h2_~ for headings.

The ~sectionText~ already makes the heading unique amongst the other ones in the
Org file, but for human-friendliness we also extract the textual part of it with
[[f:getProseContents]] (which is fed through [[f:toSafeHtmlId]] for safety).

#+name: f:getProseContents
#+begin_src haskell
getProseContents :: Prose -> Text
getProseContents prose = join $ foldl' f [] prose.unProse
  where
    join = T.intercalate "" . reverse
    f acc = \case
      PTokenStyledText styledText -> styledText.body : acc
      PTokenLink link ->
        let linkText =
              join
                $ foldl'
                  (\acc' n -> n.body : acc')
                  []
                  link.name
         in linkText : acc
      PTokenMathFragment mathFragment -> mathFragment.body : acc
      PTokenCitation {}
      PTokenDivStart {}
      PTokenDivEnd {} -> acc
#+end_src

For weaving the [[id:c8616126-215d-49be-8874-c2aca7d93a54::newtype:Prose][newtype:Prose]], [[f:weaveProse]] delegates most of the work to
[[f:weavePToken]].

#+name: f:weaveProse
#+begin_src haskell
weaveProse :: Prose -> HtmlWeaver ()
weaveProse prose = sequence_ $ map weavePToken prose.unProse
#+end_src

Each [[id:c8616126-215d-49be-8874-c2aca7d93a54::data:PToken][data:PToken]] value has its own weaver.

#+name: f:weavePToken
#+begin_src haskell
weavePToken :: PToken -> HtmlWeaver ()
weavePToken = \case
  PTokenStyledText styledText -> weaveStyledText styledText
  PTokenLink link -> case link.target of
    LinkTargetFootnote {} -> do
      sup_ [class_ "footnote-link"] $ do
        weaveLink False link
    LinkTargetOid {}
    LinkTargetLineLabel {}
    LinkTargetFilePath {}
    LinkTargetURI {} -> weaveLink False link
  PTokenMathFragment mathFragment -> weaveMathFragmentInline mathFragment

[[f:weaveBlockAncestry]] looks at a block and sees if it's a dependency of any other
block, by using the ~ancestry~ field in [[id:25827c17-2015-434b-b686-db3d72b2ee4d::data:Archive][data:Archive]]. If other blocks do depend on
this block, we link back to those blocks, which we call "parents", with
[[f:weaveParentBlock]]. If the parent block itself does not have any parents, we
call it a "root" block.

#+name: f:weaveBlockAncestry
#+begin_src haskell
weaveBlockAncestry :: Block -> HtmlWeaver ()
weaveBlockAncestry block = case lookup "name" block.meta of
  Nothing -> pure () -- (ref:anonymous-orphan)
  Just name -> do
    weaveConf <- ask
    let archive = weaveConf.archive
        selfLinkOid = LinkOid block.parentOid name
        parentGCIs = do
          selfGCI <- lookup selfLinkOid archive.symbols
          lookup selfGCI archive.ancestry
        parents = mapMaybe f $ fromMaybe [] parentGCIs
        f :: GCI -> Maybe (GCI, [GCI], GPath, Block, Prose)
        f parentGCI = do
          grandParentGCIs <-
            pure . fromMaybe [] $ lookup parentGCI archive.ancestry
          (_, cell) <- gciToObjCell archive parentGCI
          parentBlock <-
            case cell of
              CBlock b -> Just b
              _ -> Nothing
          (offset, path) <- IntMap.lookupLE parentGCI.unGCI archive.offsets
          prose <- gciToName archive offset parentGCI
          pure (parentGCI, grandParentGCIs, path, parentBlock, prose)
        (roots, nonRoots) =
          partition (\(_, ancestors, _, _, _) -> null ancestors) parents
        getName :: (GCI, [GCI], GPath, Block, Prose) -> Text
        getName (_, _, _, b, _) =
          T.toLower . fromMaybe "" $ lookup "name" b.meta
        roots' = sortOn getName roots
        nonRoots' = sortOn getName nonRoots
    forM_ roots' weaveParentBlock
    forM_ nonRoots' weaveParentBlock

The first thing we do is to get the contents of the block with
~getBlockContentsWithoutLinks~. This function is similar to [[id:51f2edd8-5f8e-4c63-841f-da6c5c41680a::f:getBlockContents][f:getBlockContents]]

text is fed into [[f:colorizeText]], and we don't want the links to be dealt with in

Block colorization relies on the [[https://hackage.haskell.org/package/skylighting][=skylighting=]] syntax highlighting library. This
library ignores the ~\NUL~ character, which is what we want. Once we have the
colorized text, we splice in the links with ~spliceLinks~, which relies on
[[f:weaveLink]] for constructing HTML for each link. The splicing works by splitting
on the ~\NUL~ character and manually "zipping" up the colorized substrings with
the woven link HTML fragments.

#+name: f:spliceLinks
#+begin_src haskell
spliceLinks :: Text -> [Link] -> HtmlWeaver Text
spliceLinks colorized links = do
  weaveConf <- ask
  let colorizedStrs = T.splitOn "\NUL" colorized
      f :: ([Text], [Link]) -> Text -> ([Text], [Link])
      f (acc, []) colorizedStr = (colorizedStr : acc, [])
      f (acc, link : links') colorizedStr =
        ( colorizedStr
            : (renderAsText weaveConf $ weaveLink True link)
            : acc,
          links'
        )
  pure
    . T.intercalate ""
    . reverse
    . fst
    . foldl' f (take 1 colorizedStrs, links)
    $ drop 1 colorizedStrs
#+end_src

Weaving links is fairly straightforward. For external links, we set the ~target~
attribute to ~_blank~ to make the browser open them in a new tab. The ~noopener
noreferrer~ bit is a security measure to sever connections from the new tab and
the current window. This way, even if those external links get hijacked, they
will not have access to the current window.

#+name: f:weaveLink
#+begin_src haskell
weaveLink :: Bool -> Link -> HtmlWeaver ()
weaveLink insideBlock link = do
  weaveConf <- ask
  wovenLinkTarget <- weaveLinkTarget insideBlock link.target
  let attrs =
        [href_ wovenLinkTarget]
          <> linkCategory wovenLinkTarget
          <> lineLabelAttr
      lineLabelAttr =
        case link.target of
          LinkTargetLineLabel lineLabel ->
            if insideBlock
              then [id_ ("ib-" <> toSafeHtmlId lineLabel.name)] -- (ref:line label self-link)
              else []
          _ -> []
      linkDisplayName =
        case link.target of
          LinkTargetLineLabel lineLabel
            | Just gci <- lookup lineLabel weaveConf.archive.symbols,
              Just (obj, _) <- gciToObjCell weaveConf.archive gci,
              Just num <- lookup (T.drop 1 $ T.dropEnd 1 lineLabel.name) obj.orgDoc.lineLabels ->
                if
                  | Just originObj <-
                      lookup weaveConf.originObjectPath weaveConf.archive.objects,
                    originObj /= obj,
                    Just (offset, _) <- IntMap.lookupLE gci.unGCI weaveConf.archive.offsets,

                        <> [stext " → " [], stext (T.show num) [Bold]]
                  | otherwise ->
                      [stext (T.show num) [Bold]]
            | otherwise ->
                [stext "weaveLink error (line label display name)" []]
          _ -> link.name
  a_
    attrs
    $ sequence_
    $ map weaveStyledText linkDisplayName
  where
    linkCategory target
      | isExternalLink link.target =
          [ class_ "external-link",
            target_ "_blank",
            rel_ "noopener noreferrer"
          ]
      | "#ref-" `T.isPrefixOf` target = []
      | otherwise = [class_ "internal-link"]
    extractStyledText :: Prose -> [StyledText]
    extractStyledText prose = reverse $ foldl' f [] prose.unProse

Links to bibliographical entries (those starting with ~#ref-~ are not given an

Unlike Noweb links, line label links inside blocks point to themselves. That's
why [[(line label self-link)]] uses the ~id~ HTML attribute.

The part we need to put in the ~href="..."~ part is generated separately in
[[f:weaveLinkTarget]]. The ~docName == ""~ part at [[(link-target-is-internal-cell)]] is needed

this is the only way we can ensure that the ~linkOid~ is a local one internal to
the current document.

weaveLinkTarget :: Bool -> LinkTarget -> HtmlWeaver T.Text
weaveLinkTarget insideBlock linkTarget = do
  weaveConf <- ask
  case linkTarget of
    LinkTargetOid linkOid -> weaveLinkTargetLinkOid linkOid
    LinkTargetLineLabel linkOid

      | Just originObj <-
          lookup weaveConf.originObjectPath weaveConf.archive.objects,

For weaving the target to [[id:da4aa2a7-3896-4969-aa5e-5e3d842c35db][Line labels]], there are three cases:

  1) The actual labels themselves. This is where they are defined /inside/ a code
     block, where we have to make them link to themselves
     [[(f:weaveLinkTarget-self-link)]] (similar to how headings and code blocks can
     link to themselves for the user to easily save the link to it).

  2) Internal line labels [[(f:weaveLinkTarget-internal)]]. This is simple because
     we know that all line labels inside a document are unique, so we can just
     weave with the name of the label (modulo an ~ib-~ prefix to mean "inside
     block") [[(f:weaveLinkTarget-line-label-prefix)]].

  3) External line labels [[(f:weaveLinkTarget-external)]]. We can't use
     [[f:weaveLinkTargetLinkOid]] because it will try to do a coarse cell-level
     lookup. Line labels are finer-grained than cells. We need to get the
     external relative path, and then skip cell-wise operations and just slap on
     the name of the line label (modulo the ~ib-~ prefix) to the external path.

[[f:getRelativePathWithoutSymlinks]] takes two file paths. It tries to answer the
question "assuming I am in the directory in the first file, how can I go to the
directory containing the second file?" This assumes that the given paths have no
symlinks (to avoid the pitfall described at [[https://hackage.haskell.org/package/filepath-1.5.4.0/docs/System-OsPath.html#v:makeRelative][System.OsPath.makeRelative]] and [[https://neilmitchell.blogspot.com/2015/10/filepaths-are-subtle-symlinks-are-hard.html][this
blog post]]).

We use the following algorithm:

  1) If we're in the same directory, or if the destination is a child of the
     source directory, then drop the common prefix of the
     destination. ~a/b/c/src~ to ~a/b/c/dest~ is ~dest~. ~a/b/c/src~ to ~a/b/c/d/e/dest~
     is ~d/e/dest~.

  2) If we're not in the same directory, we have to go up N directories up until
     we get to the common prefix.

     - No common prefix: go up all the way to the root, then go to the
       destination. ~a/b/c/src~ to ~d/dest~ is ~../../../d/dest~.

     - Some common prefix: go up to the common prefix. ~a/b/c/dest~ to ~a/x/y/dest~
       is ~../../x/y/dest~ because ~a~ is the common prefix. ~a/b/c/d/e/src~ to ~a/dest~
       is ~../../../../dest~.

#+name: f:getRelativePathWithoutSymlinks
#+begin_src haskell
getRelativePathWithoutSymlinks :: OsPath -> OsPath -> OsPath
getRelativePathWithoutSymlinks src dest
  | dirsSrc == dirsDest || isDestChildOfSrc =
      P.joinPath $ remainingDest <> destFile
  | null commonPathPrefix =
      P.joinPath $ replicate (length dirsSrc) goUp <> destFile
  | otherwise =
      P.joinPath
        $ replicate (length dirsSrc - length commonPathPrefix) goUp
        <> drop (length commonPathPrefix) dirsDest
        <> destFile
  where
    goUp = P.unsafeEncodeUtf ".."
    destFile = [P.takeFileName dest]
    dirSrc = P.takeDirectory src
    dirDest = P.takeDirectory dest
    dirsSrc = P.splitDirectories dirSrc
    dirsDest = P.splitDirectories dirDest
    commonPathPrefix = commonPrefix dirsSrc dirsDest
    isDestChildOfSrc = dirsSrc == commonPathPrefix
    remainingDest = drop (length commonPathPrefix) dirsDest
#+end_src

[[id:d0f60631-8b30-4ae1-992d-49c7b0ea38fb][Tables]] are similar to figures, because they have some content (a table instead
of an image), and also have a caption.

#+name: f:weaveTable
#+begin_src haskell
weaveTable :: LCI -> Table -> HtmlWeaver ()
weaveTable lci table = do
  let captionPrefix =
        "Table "
          <> lookupDefault "table-number-error" "__table_number" table.meta
  figure_ [id_ linkAnchor] $ do
    figcaption_ [] $ do
      wrapWith lci $ do
        a_ [href_ $ "#" <> linkAnchor, class_ "self-link", class_ "caption-prefix"] $ do
          toHtml captionPrefix
        toHtml $ case table.caption.unProse of
          [] -> "." :: Text
          _ -> ". " :: Text
        weaveProse table.caption
    table_ [] $ do
      forM_ (zip [1 :: Int ..] getColgroups) $ \(groupIdx, numCols) -> do
        let colgroupAttrs =
              if groupIdx > 1
                then [class_ "table-vertical-line-colgroup"]
                else []
        colgroup_ colgroupAttrs $ do
          forM_ [1 .. numCols] $ \colNum -> do
            if (colNum > 1)
              then col_ [class_ "table-vertical-line-col"]
              else col_ []
      thead_ [] $ do
        tr_ [] $ do
          forM_ columnNames $ \prose -> do
            th_ [] $ weaveProse prose
      tbody_ [] $ do
        forM_ (rows visibleRows) $ \row ->
          if row == [Prose []]
            then do
              tr_ [class_ "table-horizontal-line"] $ do
                forM_ columnNames $ \_ -> do
                  td_ [] $ toHtml @Text ""
            else do
              tr_ [class_ "table-body-row"] $ do
                forM_ row $ \prose -> do
                  let tdAttrs =
                        if mostlyNumeric prose
                          then [class_ "table-cell-numeric"]
                          else []
                  td_ tdAttrs $ weaveProse prose
  where
    linkAnchor = getLinkAnchor Nothing $ CTable table
    hideMarkingCharInFirstColumn :: [((Int, Int), Prose)] -> [Prose]
    hideMarkingCharInFirstColumn = \case
      [] -> []
      (((_row, _col), prose) : cells)
        | prose == tableHorizontalLine -> [Prose []]
        | markingCharExistsInFirstColumn -> map snd cells
        | otherwise -> prose : map snd cells
    markingCharExistsInFirstColumn = any (not . visibleColumn) firstColumnCells
    tableCellsFromRow :: Int -> [Prose]
    tableCellsFromRow n =
      hideMarkingCharInFirstColumn
        . M.toList
        $ M.filterWithKey (\(row, _col) _ -> row == n) table.grid
    rowMax = foldl' max 0 . map fst $ keys table.grid
    rows rowNums = map tableCellsFromRow rowNums
    columnNames = tableCellsFromRow headerRowIndex
    firstColumnCells =
      M.toList
        $ M.filterWithKey (\(_row, col) _ -> col == 1) table.grid
    headerRowIndex = fromMaybe 1 $ foldl' f Nothing firstColumnCells
    f acc@(Just _) _ = acc
    f acc cell@((row, _col), _)
      | visibleColumn cell = Just row
      | otherwise = acc
    visibleColumn :: ((Int, Int), Prose) -> Bool
    visibleColumn (_, prose) = case prose.unProse of
      [] -> True
      [PTokenStyledText styledText] ->
        notElem styledText.body $ map T.singleton markingChars
      _ -> True
    visibleRow :: ((Int, Int), Prose) -> Bool
    visibleRow (_, prose) = case prose.unProse of
      [] -> True
      [PTokenStyledText styledText] ->
        notElem styledText.body $ map T.singleton markingCharsInvisible
      _ -> True
    visibleRows = filter (`notElem` invisibleRows) [(headerRowIndex + 1) .. rowMax]
    invisibleRows = foldl' g [] firstColumnCells
    g acc cell@((row, _col), _)
      | visibleRow cell = acc
      | otherwise = row : acc
    getColgroups :: [Int]
    getColgroups =
      maybe
        [rowMax]
        (reverse . foldl' getColgroupStarts [0] . tableCellsFromRow)
        getColgroupsRow
    getColgroupStarts :: [Int] -> Prose -> [Int]
    getColgroupStarts ns prose = case ns of
      [] -> []
      [0] -> [1]
      acc@(latest : rest)
        | proseHasColgroupStartMarker prose -> 1 : acc
        | otherwise -> latest + 1 : rest
    getColgroupsRow = foldl' h Nothing firstColumnCells
    h :: Maybe Int -> ((Int, Int), Prose) -> Maybe Int
    h acc ((row, _col), prose)
      | isJust acc = acc
      | proseHasNonExportMarker prose = Just row
      | otherwise = acc
    proseHas :: Text -> Prose -> Bool
    proseHas prefix prose = case prose.unProse of
      [] -> False
      (firstPToken : _) -> case firstPToken of
        PTokenStyledText styledText ->
          (maskToStyles styledText.style == [])
            && T.isPrefixOf prefix styledText.body
        PTokenLink {}
        PTokenMathFragment {}
        PTokenCitation {}
        PTokenDivStart {}
        PTokenDivEnd {} -> False
    proseHasColgroupStartMarker :: Prose -> Bool
    proseHasColgroupStartMarker = proseHas "<"
    proseHasNonExportMarker :: Prose -> Bool
    proseHasNonExportMarker = proseHas "/"
    mostlyNumeric :: Prose -> Bool
    mostlyNumeric prose =
      let rawText = T.concat $ map extractText prose.unProse
       in isNumericText rawText
    extractText = \case
      PTokenStyledText styledText -> styledText.body
      PTokenLink {}
      PTokenMathFragment {}
      PTokenCitation {}
      PTokenDivStart {}
      PTokenDivEnd {} -> ""
#+end_src

* Glossary terms
:PROPERTIES:
:ID:       eee95795-b51b-4de5-b39d-8dda436da451
:END:

[[id:73acf466-6941-4c3b-9d6d-e0843d9b0480][Description lists, aka glossary terms]] are similar to footnote definitions in
that they are mostly composed of paragraphs. So [[f:weaveProse]] again does most of
the work.

#+name: f:weaveGlossaryTerm
#+begin_src haskell
weaveGlossaryTerm :: LCI -> GlossaryTerm -> HtmlWeaver ()
weaveGlossaryTerm lci glossaryTerm = do
  weaveConf <- ask
  let dlStart :: HtmlWeaver ()
      dlStart = toHtmlRaw @Text "<dl>"
      dlEnd :: HtmlWeaver ()
      dlEnd = toHtmlRaw @Text "</dl>"
      isGlossaryTerm lci' -- (ref:isGlossaryTerm)
        | Just originObj <- lookup weaveConf.originObjectPath weaveConf.archive.objects,
          Just internalCell <- originObj.orgDoc.cells !!? lci'.unLCI,
          CGlossaryTerm _ <- internalCell =
            True
        | otherwise = False
      isFirstGlossaryTerm = not . isGlossaryTerm . LCI $ lci.unLCI - 1
      isLastGlossaryTerm = not . isGlossaryTerm . LCI $ lci.unLCI + 1
  when (isFirstGlossaryTerm) dlStart -- (ref:use-dlStart)
  wrapWithDiv lci $ do
    div_ [id_ linkAnchor, class_ "glossary-term"] $ do
      let maybeInnerVerticalMargin
            | isFirstGlossaryTerm = []
            | otherwise = [class_ "inner-dt"]
      dt_ maybeInnerVerticalMargin $ do
        weaveProse glossaryTerm.term
      dd_ $ do
        a_ [href_ $ "#" <> linkAnchor, class_ "glossary-term-anchor"] $ do
          toHtmlRaw @Text <<HTML link symbol>>
        weaveProse glossaryTerm.definition
  when (isLastGlossaryTerm) dlEnd -- (ref:use-dlEnd)
  where
    linkAnchor = getLinkAnchor (Just lci) $ CGlossaryTerm glossaryTerm
#+end_src

We don't wrap everything inside a ~<dl>~ tag because it may be the case that many
more glossary terms exist after this (current) cell being woven. In that case,
we want to close off the ~<dl>~ only at the very end. That's what [[(use-dlStart)]]
and [[(use-dlEnd)]] are for. The ~isGlossaryTerm~ helper at [[(isGlossaryTerm)]] checks if the
given cell index points to a glossary term cell inside the
current object being woven.

The ~dlStart~ and ~dlEnd~ bits don't really mean much if we have glossary terms
inside list items, because each list item marker in between each item will break
up the continuity of glossary terms. So we'll end up with multiple singleton
description lists (each with just one glossary term in it) instead of just one
description list tag.

For example, look at the HTML for the following:

  - a :: This is in its own ~<dl>~ tag.

  - b :: This is also in its own (separate) ~<dl>~ tag.

Contrast this with the following which share the same ~<dl>~ tag:

c :: x

d :: y

** Weaving all glossary terms

A user may want to have a combine list of all glossary terms defined in the
document, as discussed in [[id:e8ad30e5-5305-40e7-80ed-78bcec636ec1][Printing glossaries]].

#+name: f:weaveGlossary

  if

Sorting of glossary terms means sorting what's visible for the human user. So
for links, it means only using the display name, not the target of the link
which may have a long (random) UUID. This means using a custom comparing
function for the prose at [[(glossary-term-compare-visible)]], to remove all links
so that we only use the display text of links. We can do this with
[[id:730ad104-52c9-49df-bbb9-66d92363bfc1::f:stripLinks][f:stripLinks]], just like we did for [[f:getLinkAnchor]], in [[f:toNormalizedText]].

#+name: f:toNormalizedText
#+begin_src haskell
toNormalizedText :: Prose -> Text
toNormalizedText prose =
  T.toLower
    . CP.toText @Prose
    . stripStyles
    $ stripLinks prose
#+end_src

[[f:toNormalizedText]] also puts everything in lowercase, because otherwise capital
letters take precedence over lowercase ones, which can be confusing. It also
calls [[id:730ad104-52c9-49df-bbb9-66d92363bfc1::f:stripStyles][f:stripStyles]] because otherwise those (useless) style characters like ~*~
and ~/~ will interfere with the sorting.

In [[f:weaveCollectedGlossaryTerm]], because we only have the cell index, we first
pull out the glossary cell to find the ~CGlossaryTerm~ we want to weave. We also
insert a link back to the place where the glossary term was originally defined,
to give the user additional context.

#+name: f:weaveCollectedGlossaryTerm

The branch of code at [[(internal-term)]] weaves internal terms (terms that are

multiple identical terms (these are not allowed within a single document).

/another/ document). These may need disambiguation, so we weave the
~externalOrgDocName~ at [[(external-doc-name)]]. Getting the ~externalOrgDocName~ (and
the link to it) is handled by [[f:getRelativeOrgDocCellLink]].

[[f:getLinkToGCI]] is a basic building block for linking out to cells (whether
internal or external) based on their global cell index. It returns a tuple of
~(linkText, externalOrgDocName)~, where ~linkText~ is what we can put in the ~href~
(of the form ~#foo~ for internal cells and ~path/to/doc.html#foo~ for external
cells). The ~externalOrgDocName~ is blank for internal cells.

#+name: f:getLinkToGCI
#+begin_src haskell
getLinkToGCI :: WeaveConf -> GCI -> Maybe (Text, Text, Prose)
getLinkToGCI weaveConf gci
  | Just (offset, gpath) <-
      IntMap.lookupLE gci.unGCI weaveConf.archive.offsets,
    Just (_, cell) <- gciToObjCell weaveConf.archive gci,
    Just cellName <- gciToName weaveConf.archive offset gci =
      let lci = LCI $ gci.unGCI - offset
       in if gpath == weaveConf.originObjectPath
            then do
              let linkAnchor = getLinkAnchor (Just lci) cell
              Just ("", linkAnchor, cellName)
            else do
              (linkAnchor, docName) <-
                getRelativeOrgDocCellLink weaveConf gpath lci cell
              Just (docName, linkAnchor, cellName)
  | otherwise = Nothing

* Citations
:PROPERTIES:
:ID:       7874b9c5-ceac-4820-8804-7732e29f5c60
:END:

For weaving citations, we use a 4-step process:

  1) Convert the [[id:c8616126-215d-49be-8874-c2aca7d93a54::newtype:Prose][newtype:Prose]] contents of [[id:6fd068e3-cc95-41a4-8126-bc7bd17c79bb::data:Citation][data:Citation]] into ~CslJson Text~,
     while preserving the information of non-text things like links and math
     fragments by embedding them as ~CslLink~ for things that ~CslJson Text~ does
     not support.

  2) Call into =Citeproc.citeproc= to get the transformed ~CslJson Text~ back out.

  3) Convert back the ~CslJson Text~ into [[id:c8616126-215d-49be-8874-c2aca7d93a54::newtype:Prose][newtype:Prose]].

  4) Weave the [[id:c8616126-215d-49be-8874-c2aca7d93a54::newtype:Prose][newtype:Prose]] as usual.

We can't simply convert [[id:c8616126-215d-49be-8874-c2aca7d93a54::newtype:Prose][newtype:Prose]] into HTML first before calling
=Citeproc.citeproc= because then that would result in things like ~<a href=...>~ being
converted into ~&lt;a href=...&gt;~ (entity conversion of the given text).

For the first step, we need a function to convert [[id:c8616126-215d-49be-8874-c2aca7d93a54::newtype:Prose][newtype:Prose]] into ~CslJson
Text~. For that we have [[f:proseToCslJsonText]]. This function abuses the ~CslDiv~
constructor to encode information that cannot be represented natively in
~CslJson~.

#+name: f:proseToCslJsonText
#+begin_src haskell
proseToCslJsonText :: Prose -> CslJson Text
proseToCslJsonText prose = foldl' f CslEmpty prose.unProse
  where
    f :: CslJson Text -> PToken -> CslJson Text
    f acc pToken = case pToken of
      PTokenStyledText styledText ->
        let styles = maskToStyles styledText.style
            body = parseCslJson mempty styledText.body
         in acc <> applyStyles body styles
      PTokenLink link ->
        let encoded = CslLink ("LILAC_LINK\NUL" <> unparseLink link) CslEmpty
         in acc <> encoded
      PTokenMathFragment mathFragment ->
        let encoded = CslDiv ("LILAC_MATH_FRAGMENT\NUL" <> unparseMathFragment mathFragment) CslEmpty
         in acc <> encoded
      PTokenCitation {}
      PTokenDivStart {}
      PTokenDivEnd -> acc
    applyStyles :: CslJson Text -> [Style] -> CslJson Text
    applyStyles cslBody styles = foldl' applyStyle cslBody styles
    applyStyle :: CslJson Text -> Style -> CslJson Text
    applyStyle acc = \case
      Bold -> CslBold acc
      Italic -> CslItalic acc
      Underline -> CslUnderline acc
      Verbatim -> CslDiv "LILAC_STYLE_VERBATIM\NUL" acc
      Code -> CslDiv "LILAC_STYLE_CODE\NUL" acc
      Smallcaps -> CslSmallCaps acc
      Subscript -> CslSub acc
      Superscript -> CslSup acc
#+end_src

easily into a ~Maybe (CslJson Text)~. This is useful because the Citeproc library
uses this type for constructing its citation objects.

The individual [[id:6fd068e3-cc95-41a4-8126-bc7bd17c79bb::data:Cite][data:Cite]] items are converted into Citeproc's ~CitationItem~ type.
Orgmode has fancy styling capabilities for individual citation items (this is
~sv1~ in [[f:citeToCiteprocCitationItems]] below), but we only support the ~t~ and ~na~
style variants (we don't even look at the second element in the
~citation.styleVariation~ tuple). This is because we rely on CSL to do nearly all
of the styling for us. CSL itself [[https://citeproc-js.readthedocs.io/en/latest/csl-json/markup.html#cite-items][allows for just a handful of variations]],
namely:

  - ~suppress-author~: do not show the author name

  - ~author-only~: only show the author name

We achieve the semantic meaning of ~t~ (aka ~text~) and ~na~ (aka ~noauthor~) by using
combinations of the above. The ~na~ maps 1:1 to ~author-only~ so that's an easy one.
However the ~t~ style needs to inject the author name (as regular text) just
before the cite. In order to achieve this, we create two citations, using a
combination of ~suppress-author~ (~CP.SuppressAuthor~) and ~author-only~
(~CP.AuthorOnly~) to get what we want. Because we end up creating two citations in
place of one, the result type of [[f:citeToCiteprocCitationItems]] is a list.

#+name: f:citeToCiteprocCitationItems
#+begin_src haskell
citeToCiteprocCitationItems :: Maybe Text -> Cite -> [CP.CitationItem (CslJson Text)]
citeToCiteprocCitationItems sv cite =
  let citationItem =
        CP.CitationItem
          { CP.citationItemId = CP.ItemId cite.id,
            CP.citationItemLabel = term,
            CP.citationItemLocator = coord,
            CP.citationItemType = CP.NormalCite,
            CP.citationItemPrefix = proseToMaybeCslJsonText cite.prefix,
            CP.citationItemSuffix = proseToMaybeCslJsonText cite.suffix,
            CP.citationItemData = Nothing
          }
   in if
        | Just "t" <- sv ->
            [ citationItem
                { CP.citationItemType = CP.AuthorOnly,
                  CP.citationItemSuffix = Nothing
                },
              citationItem
                { CP.citationItemType = CP.SuppressAuthor,
                  CP.citationItemPrefix = Nothing
                }
            ]
        | Just "na" <- sv ->
            [citationItem {CP.citationItemType = CP.SuppressAuthor}]
        | otherwise -> [citationItem]
  where
    (term, coord) = case cite.locator of
      Just (t, c) -> (Just t, Just c)
      Nothing -> (Nothing, Nothing)
#+end_src

The last piece is the conversion of ~CslJson Text~ back into [[id:c8616126-215d-49be-8874-c2aca7d93a54::newtype:Prose][newtype:Prose]]. We
have to recursively traverse the nodes in the ~CslJson Text~ tree.

#+name: f:cslJsonTextToProse
#+begin_src haskell
cslJsonTextToProse :: CslJson Text -> Prose
cslJsonTextToProse cslJsonText = compressProse . Prose $ f [] cslJsonText
  where
    f :: [Style] -> CslJson Text -> [PToken]
    f s = \case
      CslEmpty -> []
      CslText t ->
        [ PTokenStyledText
            StyledText {body = t, style = styleMaskFrom s}
        ]
      CslConcat a CslEmpty -> f s a
      CslConcat (CslConcat a b) c -> f s (CslConcat a (CslConcat b c))
      CslConcat a b -> f s a <> f s b
      CslQuoted a -> f s a
      CslItalic a -> f (Italic : s) a
      CslNormal a -> f [] a
      CslBold a -> f (Bold : s) a
      CslUnderline a -> f (Underline : s) a
      CslNoDecoration a -> f (filter (/= Underline) s) a
      CslSmallCaps a -> f (Smallcaps : s) a
      CslBaseline a -> f (filter (`notElem` [Subscript, Superscript]) s) a
      CslSup a -> f (Superscript : s) a
      CslSub a -> f (Subscript : s) a
      CslNoCase a -> f s a
      CslDiv t a
        | t == "LILAC_STYLE_CODE\NUL" -> f (Code : s) a
        | t == "LILAC_STYLE_VERBATIM\NUL" -> f (Verbatim : s) a
        | "LILAC_MATH_FRAGMENT\NUL" `T.isPrefixOf` t ->
            (CP.fromText (T.drop 20 t) :: Prose).unProse
        | otherwise -> [PTokenDivStart t] <> f s a <> [PTokenDivEnd]
      CslLink t a
        | "LILAC_LINK\NUL" `T.isPrefixOf` t ->
            (CP.fromText (T.drop 11 t) :: Prose).unProse
        | "#ref-" `T.isPrefixOf` t ->
            let uri =
                  N.URI
                    { N.uriScheme = "",
                      N.uriAuthority = Nothing,
                      N.uriPath = T.unpack t,
                      N.uriQuery = "",
                      N.uriFragment = ""
                    }
                target = LinkTargetURI uri
                name = compressStyledText . getStyledText $ f s a
             in [PTokenLink Link {target = target, name = name}]
        | otherwise -> case (N.parseURI $ T.unpack t) of
            Nothing -> []
            Just uri ->
              let target = LinkTargetURI uri
                  name = compressStyledText . getStyledText $ f s a
               in [PTokenLink Link {target = target, name = name}]
    getStyledText [] = []
    getStyledText (pToken : rest) = case pToken of
      PTokenStyledText styledText -> styledText : getStyledText rest
      PTokenLink {}
      PTokenMathFragment {}
      PTokenCitation {}
      PTokenDivStart {}
      PTokenDivEnd {} -> []
#+end_src

The ~CslNoCase~ is fine to ignore because it's most likely used by =Citeproc= to
handle case-changing transformations, and is probably not meant to be used
directly by consumers.

The ~CslDiv~ is used to wrap bibliographical entries inside printed bibliography
for formatting purposes. We ignore them for now, except for those ~LILAC_STYLE...~
bits that we've encoded in [[f:proseToCslJsonText]].

Now we have all of the pieces needed to process citations. The idea is to
process all citations found inside an Org document at once, just before the
weaving begins in [[id:891f2674-2be9-4e63-b0f8-7ca43f1354fb::f:weaveObject][f:weaveObject]], by calling ~Citeproc.citeproc~ which will get us
a ~Result a~ which includes the formatted citations as well as the formatted
bibliography. This part is handled by [[f:prepareCitations]]. Then during the
weaving process we refer to these formatted citations (of type ~Prose~), before
finally converting them to HTML again.

#+name: f:prepareCitations
#+begin_src haskell
prepareCitations :: GPath -> Object -> Archive -> IO (CP.Result Prose)
prepareCitations objGPath object archive = do
  bibPathsRelative <- makeRelativeToObjectPath objGPath object.orgDoc.bibPaths
  cslPathRelative <- listToMaybe <$> (makeRelativeToObjectPath objGPath $ maybeToList object.orgDoc.cslPath)
  let bibRefsFromOrgDoc =
        filter neededByCitations
          . concat
          . catMaybes
          $ map (\bp -> lookup bp archive.bibs) bibPathsRelative
      CP.Result citations bibliography warnings =
        f bibRefsFromOrgDoc cslPathRelative
      resultWithProse =
        CP.Result
          { CP.resultCitations = map cslJsonTextToProse citations,
            CP.resultBibliography = map (\(k, cslJsonText) -> (k, cslJsonTextToProse cslJsonText)) bibliography,
            CP.resultWarnings = warnings
          }
  pure resultWithProse
  where
    citeprocOptions =
      CP.CiteprocOptions
        { linkCitations = True,
          linkBibliography = True
        }
    blankResult :: CP.Result (CslJson Text)
    blankResult =
      CP.Result
        { CP.resultCitations = [],
          CP.resultBibliography = [],
          CP.resultWarnings = ["BLANK CITATION RESULT"]
        }
    f bibRefs cslPathRelative
      | Just cslPath' <- cslPathRelative,
        Just rawXML <- lookup cslPath' archive.csls,
        Right citeprocStyle <- parseCitationStyle rawXML =
          CP.citeproc
            citeprocOptions
            citeprocStyle
            Nothing
            bibRefs
            (map citationToCiteprocCitation object.orgDoc.citations)
      | otherwise = blankResult
    neededByCitations bibRef =
      let citeIds =
            concatMap
              (\c -> map (\cite -> cite.id) c.cites)
              object.orgDoc.citations
       in bibRef.referenceId.unItemId `elem` citeIds
#+end_src

The ~neededByCitations~ helper filters out the bibliographical entries so that we
only print the bibliography that are actually used by the citations. See [[https://github.com/jgm/citeproc/issues/169][this
upstream issue]].

Now we can weave [[id:6fd068e3-cc95-41a4-8126-bc7bd17c79bb::data:Citation][data:Citation]] values into the HTML, with [[f:weaveCitation]].

#+name: f:weaveCitation
#+begin_src haskell
weaveCitation :: Int -> HtmlWeaver ()
weaveCitation n = do
  weaveConf <- ask
  let result = weaveConf.citeprocResult
      citations = result.resultCitations
  case maybeAt n citations of
    Just prose -> span_ [class_ "citation"] $ weaveProse prose
    Nothing -> pure ()

[[f:weaveBibliography]] weaves the ~#+print_bibliography~ part of the doc.

#+name: f:weaveBibliography
#+begin_src haskell
weaveBibliography :: LCI -> HtmlWeaver ()
weaveBibliography lci = do
  weaveConf <- ask
  let result = weaveConf.citeprocResult
      bibliography = result.resultBibliography
  div_ [class_ "bibliography"] $ do
    wrapWithDiv lci $ do
      forM_ bibliography $ \(key, prose) -> do
        let linkAnchor = "ref-" <> key
        div_ [class_ "bib-ref", id_ linkAnchor] $ do
          weaveProse prose

* Table of Contents (TOC)
:PROPERTIES:
:ID:       e38fb4d1-72e1-40e0-905e-95bc8be2bf0b
:END:

The /Table of Contents/ or TOC is automatically generated and inserted into the
left sidebar. It serves as a navigation menu of the first three levels of
headings.

Eventually we want to support collapsible headings inside the TOC. The
traditional way to do this is to toggle the visibility of child elements when
clicking to expand/collapse the parent heading. Selecting child elements is
easiest when there is a hierarchical (nested) structure. The simplest way to do
this is to use unordered list items.

So what we need to do is convert the flat heading cells into a nested structure.
The spirit of this is very similar to how we computed the section numbers for
each heading in [[id:16a68a74-d4cc-41a4-ac77-cbca77de2a31::f:headingParser][f:headingParser]]. Every time we enter a nesting level, we'll have
to create a new ordered list tag (~<ol>~), and every time we leave a level (and
we may leave more than one level at once), we have to close those unordered list
tags (with ~</ol>~).

#+name: f:weaveToc
#+begin_src haskell
weaveToc :: [Cell] -> HtmlWeaver ()
weaveToc cells = do
  nav_ [class_ "toc"] $ do
    p_ [class_ "widget-title"] $ do
      toHtml @Text "Contents"
    let (actions, lastHeadingLevel) = foldl' f ([], 0) cells
    sequence_ $ reverse actions
    when (lastHeadingLevel > 0) $ do
      closeHeadingLevels lastHeadingLevel
  where
    f :: ([HtmlWeaver ()], Int) -> Cell -> ([HtmlWeaver ()], Int)
    f (actions, prevLevel) = \case
      CHeading heading ->
        let weaveTocHeading :: HtmlWeaver ()
            weaveTocHeading = do
              toHtmlRaw ("<li class=\"toc-level-" <> show heading.level <> "\">" :: Text)
              div_ [class_ "toc-entry"] $ do
                span_ [class_ "toc-counter"] $ do
                  toHtml sectionText
                a_ [href_ $ "#" <> linkAnchor] $ do
                  weaveProse heading.body
            sectionText = getSectionNumber heading
            linkAnchor = getLinkAnchor Nothing $ CHeading heading
            action :: HtmlWeaver ()
            action
              | prevLevel < heading.level = do
                  weaveListMarker LOrderedStart
                  weaveTocHeading
              | prevLevel > heading.level = do
                  closeHeadingLevels (prevLevel - heading.level)
                  weaveListMarker LItemEnd
                  weaveTocHeading
              | otherwise = do
                  weaveListMarker LItemEnd
                  weaveTocHeading
         in (action : actions, heading.level)
      CFootnote {}
      CBlock {}
      CFigure {}
      CListItem {}
      CMathFragment {}
      CParagraph {}
      CGlossaryTerm {}
      CTable {}
      CCommand {} -> (actions, prevLevel)
    closeHeadingLevels :: Int -> HtmlWeaver ()
    closeHeadingLevels levelDiff =
      forM_ [1 .. levelDiff] $ \_ -> do
        weaveListMarker LItemEnd
        weaveListMarker LOrderedEnd
#+end_src

All of the business around using ~LItemEnd~ and ~LOrderedEnd~ is needed because when
we nest levels, we /cannot/ close the current list item (because nested list items
are technically children of the current list item). The top-level call to
~closeHeadingLevels~ is needed because the ~action~ helper only works to close nesting
levels when we encounter a heading that is less nested than the previous one. So
this means the last heading will always remain "open". We close off the last
heading level with ~closeHeadingLevels lastHeadingLevel~.

The ~closeHeadingLevels~ helper is called again inside the ~action~ helper to close
off heading levels when we jump from a nested heading to a less nested one.

** Heading ancestry
:PROPERTIES:
:ID:       4651cdd2-5f79-46e0-af4a-5344d71c7ea6
:END:

For [[id:c4c13ce7-23d9-49d9-8d3f-6faecf839afa][Active headings TOC indicator]] we want to highlight all visible headings as
well as all of their parent headings ("ancestor" headings) in the document. We
need to generate a "heading ancestry" map where the keys are individual
headings, and the values are lists of other headings which are considered its
ancestors.

To be a bit more precise though, we need ancestry information for all cells, not
just headings, because it could be the case that the viewport is not showing any
headings, but only the paragraphs (or other non-heading cells, such as a code
block or table) that belong to a heading. What we can do is group a heading and
all of its non-heading children into a single ~<div>~ wrapper. Then we can just
check for whether this wrapper is visible. So the heading ancestry should be
available for all heading wrappers in the document, where the keys are the
headings (and their children that the wrappers have grouped up together) and the
values are the headings we want to highlight in the TOC as being active.

In [[f:genHeadingAncestry]] we fold over all cells, but skip over any non-heading
cell. For headings, we get the unique ID of it by calling [[f:getLinkAnchor]]. This
is used as the map key. And whenever we detect [[id:16a68a74-d4cc-41a4-ac77-cbca77de2a31][Headings]] we update the list of
ancestor headings (also using [[f:getLinkAnchor]] to get the name), and use this as
the basis of the map value (with a minor tweak via ~ancestorsOf~).

Se update the heading ancestry as follows:

  1) If the list is empty, push the current heading into the list.

  2) Otherwise, compare current heading level with heading level of the first
     element (most nested) of the list:

     - If current one is higher, pop off elements until we see one that's even
       higher and push this one.

     - If they're equal, then pop off one element and push this one.

     - If current one is lower, then just push into the list (no popping).

#+name: f:genHeadingAncestry
#+begin_src haskell
genHeadingAncestry :: [Cell] -> Map Text [Text]
genHeadingAncestry = snd . foldl' f ([], mempty)
  where
    f ::
      ([Heading], Map Text [Text]) ->
      Cell ->
      ([Heading], Map Text [Text])
    f ([], m) cell@(CHeading heading) =
      let updatedAncestry = [heading]
          key = getLinkAnchor Nothing cell
          val = [] :: [Text]
       in (updatedAncestry, insert key val m)
    f (ancestry@(a : as), m) cell@(CHeading heading) =
      let updatedAncestry
            | heading.level < a.level =
                heading
                  : (dropWhile (\a' -> heading.level <= a'.level) ancestry)
            | heading.level > a.level = heading : ancestry
            | otherwise = heading : as
          key = getLinkAnchor Nothing cell
          val =
            map
              (getLinkAnchor Nothing . CHeading)
              $ ancestorsOf heading ancestry
       in (updatedAncestry, insert key val m)
    f acc _ = acc
    ancestorsOf :: Heading -> [Heading] -> [Heading]
    ancestorsOf leafHeading ancestry
      | null ancestry = []
      | otherwise = dropWhile (\a' -> leafHeading.level <= a'.level) ancestry
#+end_src

The ~ancestorsOf~ tweak is needed because we can't use either the existing
~ancestry~ (from the previous iteration) or the ~updatedAncestry~ as is. This is
because ~ancestry~ is simply outdated (it may have an elaborate hierarchy that is
not relevant to a new top-level heading), and ~updatedAncestry~ includes the
current heading (and the current heading cannot be its own ancestor).

We then convert this map into a JSON object and embed it into the document
directly, so that the frontend code can parse and reference it.

#+name: f:weaveHeadingAncestry
#+begin_src haskell
weaveHeadingAncestry :: [(LCI, Cell)] -> HtmlWeaver ()

  let headingAncestry = genHeadingAncestry $ map snd lciCellPairs

    toHtmlRaw . TLE.decodeUtf8 $ encode headingAncestry

One of the things in the navbar is the "breadcrumbs", which is the path that
points to the current document. This path is constructed by starting with the
project name, followed by the path to the object currently being woven, which is
taken from the ~originObjectPath~ field from [[data:WeaveConf]].

The breadcrumbs are made up of four pieces:

  1) project name

  2) (optional) project version

  3) middle

  4) Org document name

The middle part can be any number of intervening directory names (can be empty).
Only the project name and Org document name are guaranteed to exist. This is
because the project name comes from [[data:ProjectConf]], and the Org document name
comes from the ~originObjectPath~ from [[data:WeaveConf]].

The breadcrumbs are woven in [[f:weaveBreadcrumbs]].

#+name: f:weaveBreadcrumbs
#+begin_src haskell
weaveBreadcrumbs :: HtmlWeaver ()
weaveBreadcrumbs = do
  weaveConf <- ask
  weaveProjectName weaveConf.projectConf
  weaveProjectVersion weaveConf.projectConf
  let breadcrumbsTail =
        map osPathDecoder
          . P.splitDirectories
          . P.unsafeEncodeUtf
          $ decodeGPath weaveConf.originObjectPath
      breadcrumbsMiddle = reverse . drop 1 $ reverse breadcrumbsTail
      breadcrumbLast =
        convertObjectExtensionToOrg . take 1 $ reverse breadcrumbsTail
  forM_ breadcrumbsMiddle $ \breadcrumb -> do
    weaveBreadcrumbSeparator
    weaveBreadcrumb breadcrumb
  forM_ breadcrumbLast $ \breadcrumb -> do
    weaveBreadcrumbSeparator
    a_ [href_ "#top"] $ do
      weaveBreadcrumb breadcrumb
  where
    osPathDecoder osp = case P.decodeUtf osp :: Maybe FilePath of
      Nothing -> "LILAC_ERROR_INVALID_OSPATH"
      Just fp -> T.pack fp
    weaveProjectName :: ProjectConf -> HtmlWeaver ()
    weaveProjectName projectConf = case projectConf.homepage of
      Nothing -> do
        weaveBreadcrumb projectConf.name
      Just uri -> do
        let homepageLinkTarget = T.pack $ N.uriToString id uri ""
        a_ [href_ homepageLinkTarget] $ do
          weaveBreadcrumb projectConf.name
    weaveProjectVersion :: ProjectConf -> HtmlWeaver ()
    weaveProjectVersion projectConf = case projectConf.version of
      Nothing -> pure ()
      Just version -> toHtml $ " " <> version
    weaveBreadcrumb :: Text -> HtmlWeaver ()
    weaveBreadcrumb breadcrumb = do
      span_ [class_ "breadcrumb"] $ do
        toHtml breadcrumb
    weaveBreadcrumbSeparator :: HtmlWeaver ()
    weaveBreadcrumbSeparator = do
      toHtml @Text " "
      span_ [class_ "breadcrumb-separator"] $ do
        toHtml @Text "/"
      toHtml @Text " "
    convertObjectExtensionToOrg :: [Text] -> [Text]
    convertObjectExtensionToOrg [] = []
    convertObjectExtensionToOrg (objName : rest) =
      let parts = T.split (== '.') objName
          withoutObjectExtension = drop 1 $ reverse parts
          withOrgExtension = ".org" : withoutObjectExtension
       in (T.concat $ reverse withOrgExtension) : rest
#+end_src

The ~convertObjectExtensionToOrg~ function converts something like ~foo.lobj~ into
~foo.org~.

The reliance on ~originObjectPath~ assumes that the archive has object paths that
are relative to the repository root. It could be that this is not true, but we
don't bother to handle that edge case here.

** Backlinks
:PROPERTIES:
:ID:       b1057136-48d5-402e-8e55-5a7e6a08efe4
:END:

Backlinks are useful because they show additional context around the current
page. We basically want to know all of the other Org docs that refer to the
current one. This can be computed as follows:

  1) Filter the archive's edges (~symbolEdges~) so that we're only left with
     backlinks to the current object's range of cells.

  2) Filter again to only have backlinks from cells that belong to external
     objects, not the current object.

  3) Discard the target vertex (cell belonging to current object). This just
     leaves us with cells from other external objects.

  4) Group cells by object. This is ~backlinksByPath~ in [[f:weaveBacklinks]] below.

  5) List each object, sorted by most number of backlinks.

#+name: f:weaveBacklinks
#+begin_src haskell
weaveBacklinks :: HtmlWeaver ()
weaveBacklinks = do
  weaveConf <- ask
  div_ [class_ "backlinks"] $ do
    p_ [class_ "widget-title"] $ do
      toHtml @Text "Backlinks"
    case lookup weaveConf.originObjectPath weaveConf.archive.backlinks of
      Nothing -> do
        p_ [] $ do
          toHtml @Text "None"
      Just backlinksByPath -> do
        ol_ [] $ do
          let sorted =
                sortOn (\(_, links) -> -(length links))
                  $ toPairs backlinksByPath
          sequence_ $ map weaveBacklinksForExternalObj sorted
  where
    weaveBacklinksForExternalObj :: (GPath, [(GCI, GCI)]) -> HtmlWeaver ()
    weaveBacklinksForExternalObj (_, []) = toHtmlRaw @Text ""
    weaveBacklinksForExternalObj (externalObjGPath, edges) = do
      weaveConf <- ask
      let weight = T.show $ length edges
          f :: ([GCI], GCI) -> HtmlWeaver ()
          f ([], _) = pure ()
          f (externalGCIs@(externalGCI : _), internalGCI) = do
            let (internalLinkAnchor, internalName) =
                  (getInternalLinkAnchor internalGCI, getInternalName internalGCI)
            li_ [] $ do
              if (length externalGCIs > 1)
                then do
                  a_ [href_ internalLinkAnchor] $ do
                    weaveProse internalName
                    toHtml @Text $ " (" <> (T.show $ length externalGCIs) <> ")"
                  ol_ [] $ do
                    sequence_ $ map (linkToExternalCell True) externalGCIs
                else do
                  a_ [href_ internalLinkAnchor] $ do
                    weaveProse internalName
                  span_ [class_ "verbatim"] $ do
                    toHtmlRaw @Text " &#x2190; "
                  linkToExternalCell False externalGCI
          linkToExternalCell :: Bool -> GCI -> HtmlWeaver ()
          linkToExternalCell asListItem gci =
            case getLinkToGCI weaveConf gci of
              Nothing -> pure ()
              Just (_, externalLinkAnchor, externalCellName) -> do
                let externalLink =
                      a_ [href_ externalLinkAnchor] $ do
                        weaveProse externalCellName
                if asListItem
                  then li_ [] $ externalLink
                  else externalLink
          getInternalLinkAnchor gci
            | Just (_, internalCell) <- gciToObjCell weaveConf.archive gci =
                "#" <> (getLinkAnchor Nothing internalCell)
            | gci.unGCI < 0 = "#top"
            | otherwise = "#LINK_ERROR"
          getInternalName gci
            | Just name <- gciToName weaveConf.archive 0 gci =
                name
            | gci.unGCI < 0 = Prose [PTokenStyledText $ StyledText {body = "^ Top", style = styleMaskFrom []}]
            | otherwise = noName
          noName = Prose [PTokenStyledText $ StyledText {body = "???", style = styleMaskFrom []}]
          groupedByTarget :: [(GCI, GCI)] -> [([GCI], GCI)]
          groupedByTarget =
            let coalesce :: [(GCI, GCI)] -> [([GCI], GCI)]
                coalesce [] = []
                coalesce group@((_, target) : _) =
                  [(reverse $ map fst group, target)]
             in sortBy
                  ( comparing (negate . length . fst)
                      <> comparing (gciToName weaveConf.archive 0 . snd)
                  )
                  . concatMap coalesce
                  . groupBy ((==) `on` snd)
                  . sortOn snd
      case getRelativeOrgDocLink weaveConf externalObjGPath of
        Nothing -> pure ()
        Just (externalOrgDocName, externalOrgDocPath) -> do
          li_ [] $ do
            a_ [href_ externalOrgDocPath] $ do
              toHtml $ externalOrgDocName <> " (" <> weight <> ")"
            ol_ [] $ do
              forM_ (groupedByTarget edges) f
#+end_src

The ~groupedByTarget~ helper groups edges by the target, coalescing edges that
point to the same target together. So instead of ~[(1, 2), (5, 2), (4, 7)]~ we get
~[([1, 5], 2), ([4], 7)]~. It uses ~sortBy~ to first sort by the number of external
indices first, and then by the name of the internal cell being referenced.

For ~getInternalLinkAnchor~, it's OK to have ~Nothing~ as the first argument for
[[f:getLinkAnchor]] because it's only used for paragraph cells to name them, and
it's impossible to link to paragraphs and so we'll never end up with an internal
cell which is a paragraph cell.

[[f:searchOrderedNeedles]] looks through a haystack and searches for all given
needles to be in the haystack, in order.

#+name: f:searchOrderedNeedles
#+begin_src haskell
searchOrderedNeedles :: Text -> [Text] -> (String, [Expectation])
searchOrderedNeedles haystackRaw needles =
  (\expectations -> ("sees needles", expectations))
    . reverse
    . fst
    $ foldl' f ([], haystackRaw) needles
  where
    f ::
      ([Expectation], Text) ->
      Text ->
      ([Expectation], Text)
    f (testCases, haystack) needle =
      let (discardMe, foundAndRest) = T.breakOn needle haystack
          discardLen = T.length discardMe
          needleStr = T.unpack needle
          foundAndRestStr = T.unpack foundAndRest
          expectation = foundAndRestStr `shouldStartWith` needleStr
          expectationF =
            expectationFailure
              $ "could not find "
              <> (show $ needleStr)
              <> " in haystack:\n"
              <> (T.unpack haystack)
          remainingHaystack = T.drop discardLen haystack
       in if foundAndRest == T.empty
            then (expectationF : testCases, remainingHaystack)
            else (expectation : testCases, remainingHaystack)
#+end_src

In practice we will only need multiple needles if we are dealing with a
complicated haystack (with nested structures) and we only want to check some
key structures within it.

*** Ordered list items

Ordered list items get a right parenthesis, just like what we require when they
are written in the Org file (search for "parenthesis" in [[id:32d34523-2148-4f2f-b2f3-2a2543a7d57c][Detailed rules]]).

#+name: css:Ordered list items
#+begin_src haskell
main_ ? do
  ol ? do
    "list-style" -: "none" -- (ref:css:Ordered list items-disable-default-counter)
    "counter-reset" -: "custom-list-counter" -- (ref:css:Ordered list items-custom-list-counter)
  ol |> li ? do
    "counter-increment" -: "custom-list-counter" -- (ref:css:Ordered list items-custom-list-counter-increment)
    position relative
    before & do
      "content" -: "counter(custom-list-counter) \")\"" -- (ref:css:Ordered list items-parenthesis)
      position absolute
      left (rem (-2.4))
      width (rem 2)
      textAlign $ alignSide sideRight
#+end_src

We disable the default counter style for ordered lists at [[(css:Ordered list
items-disable-default-counter)]], and create a new custom counter at [[(css:Ordered
list items-custom-list-counter)]]. The ~custom-list-counter~ is scoped to each level
of ordered lists automatically by the browser. This counter is incremented upon
encountering each list item [[(css:Ordered list
items-custom-list-counter-increment)]]. The right parenthesis is used as the style
of the custom counter at [[(css:Ordered list items-parenthesis)]]. The rest of the
CSS is for positioning the custom counter.

We only use this custom style for ordered lists in the main content part of the
viewport. Ordered lists in other parts of the viewport (namely the [[id:c316d545-5f6c-4fea-8342-e6925be83dfe][Table of
contents (TOC)]] and [[id:6db7e0d7-67e1-45c1-9908-a8fb055ec535][Sidebar]]) are unaffected. This is purely for aesthetic reasons
(they look good enough as is).

*** Empty list items

If a list item is empty (has no content), the browser will collapse them onto a
single line. To prevent this, we set a minimum height for empty list items.

#+name: css:List item minimum height
#+begin_src haskell
main_ ? do
  ol ? do
    li ? do
      empty & do
        minHeight (rem 2.2)
#+end_src

Code blocks use a 2-column layout, with the first column being the
~.code-block-controls~ and the second column being all the rest.

#+name: css:Block grid layout
#+begin_src haskell
".code-block-container" & do
  display grid
  gridTemplateColumns [px 50, fr 1]
  margin (px 16) 0 (px 16) (px (-50))
  position relative
  fontSize (rem 0.9)
  a ? do
    fontSize (rem 0.9)
    display inlineBlock
    yx margin (px 2) 0
forM_
  [".code-block-meta", ".code-block-meta-raw", ".code-block-body"]
  $ \child -> do
    ".code-block-container" |> child ? do
      "grid-column" -: "2"
#+end_src

Initially, the ~.code-block-controls~ in the first column are hidden. On hovering
over it or the overall container we display it.

#+name: css:Block controls
#+begin_src haskell
".code-block-controls" & do
  padding (px 2) (px 5) 0 0
  width (px 50)
  textAlign $ alignSide sideRight
  boxSizing borderBox
  top (px 0)
  bottom (px 0)
  position absolute
  "grid-column" -: "1"
  "grid-row" -: "1"
  visibility hidden -- (ref:css-visibility)
  opacity 0 -- (ref:css-opacity)
  <<css:Block controls buttons>>
(".code-block-container" # hover) |> ".code-block-controls" ? do
  visibility visible
  opacity 1
#+end_src

We need to use both /visibility/ [[(css-visibility)]] and /opacity/ [[(css-opacity)]] to
hide/unhide the controls. Visibility hides the element without changing the
layout, while opacity hides it visually.

#+name: css:Block controls buttons
#+begin_src haskell
a # hover ? do
  textDecoration none
button # ".toggle-code-block-meta-raw" ? do
  "::before" & do
    "content" -: "\"M\""
  marginRight $ px 5
  "border" -: "0"
  "cursor" -: "pointer"
  ev borderRadius (px 2)
  border (px 1) solid colorCodeBorder
#+end_src

The rest of the block has three parts (these are evident from [[f:weaveBlock]]):

  1) ~.code-block-meta~ :: The name or tangle path. These attributes are so common
     (and important) that we always display them where possible.

  2) ~.code-block-meta-raw~ :: Other metadata such as the programming language
     syntax of the code block. These attributes are typically not as
     interesting, and so require the user to press a button (labeled ~M~) in the
     ~.code-block-controls~ container to reveal them.

  3) ~.code-block-body~ :: Main body of the block, which contains the actual code
     that have been fenced by ~#+begin_...~ and ~#+end_...~.

#+begin_src haskell

** Glossary terms

For glossary terms, we want to place the definition (~<dd>~) on the /same line/ as
the term (~<dt>~). To do this we place a newline character (the string ~\a~ in CSS)
after a ~<dd>~ at [[(newline-after-dd)]].

#+name: css:Glossary terms
#+begin_src haskell
dl ? do
  marginTop $ rem 1
dt ? do
  display inlineBlock
  fontWeight bold
  fontSans
  ".inner-dt" & do
    marginTop $ rem 1
dd ? do
  display inline
  marginLeft (rem 0.5)
  "::after" & do
    "content" -: "\"\\a\"" -- (ref:newline-after-dd)
    whiteSpace ClayText.pre
  a # ".glossary-term-anchor" ? do
    fontSize (em 0.7)
    ":hover" & do
      textDecoration none
div # ".glossary-term" ? do
  border (px 1) solid colorBg
  yx padding (px 0) (px 5)
  ".active" & do
    border (px 1) solid colorActiveBorder
    backgroundColor colorActiveBg
    ev borderRadius (px 5)
span # ".glossary-external-source" ? do
  fontSans
#+end_src
