* Weaving

In most Literate Programming systems, /weaving/ is the act of generating a
human-readable document. This usually means writing a PDF or an HTML page.

For now, Lilac's main goal is to generate HTML pages. There are several
reasons:

  1) HTML is easier to consume on the web than PDFs.

  2) PDFs are obsessed with page numbers because they are designed to be printed
     on real physical paper; we don't care about those things.

  3) We want to eventually make our HTML pages interactive, and interactivity is
     easier in HTML.

** Project configuration
:PROPERTIES:
:ID:       df128041-ada8-4d77-a373-111416002dae
:END:

The starting point of weaving is the concept of /project configuration/. Project
configuration defines some global settings that apply to all weavable artifacts
found in a [[id:25827c17-2015-434b-b686-db3d72b2ee4d::data:Archive][data:Archive]], which itself is composed of a collection of [[id:01da95fe-ba23-4481-9833-428423392f5f::data:Object][data:Object]]
values. Project configuration is encoded in [[data:ProjectConf]].

#+name: data:ProjectConf
#+begin_src haskell
type ProjectConf :: Type
data ProjectConf = ProjectConf
  { name :: Text,
    homepage :: Maybe N.URI,
    repo :: Maybe N.URI,
    version :: Maybe Text
  }
  deriving stock (Eq, Generic, Show)
  deriving anyclass (FromJSON, ToJSON)
#+end_src

The fields are:

  - name :: Name of the project. This is used in the [[id:35d768c0-3e2f-498a-8437-e4137c4500ba][Navigation bar]].

  - homepage :: URL of the homepage. This is used as the link target to describe
    the ~name~ in the navbar. It could very well be the case that this target
    merely points to one of the other woven object files.

  - repo :: URL of the source code repository (the assumption being that the Org
    docs and tangled files are all open source and belonging to the same Gt
    repo).

  - version :: Human-friendly version information. This is used to describe the
    version of the Org source code used for weaving; if possible, the ~repo~ field
    should also reference the same version. If this is ~Nothing~, version
    information is omitted from the woven output.

Project configuration isn't part of [[id:25827c17-2015-434b-b686-db3d72b2ee4d::data:Archive][data:Archive]] because it may be the case in
the future that a single project could be used for multiple archive files.

*** Simple project configuration

The [[data:ProjectConf]] would be very difficult to use if we expect users to write
the JSON version of it manually, because it is a precise type. So instead we let
users write a simplified, "simple" version of it in JSON (as
[[data:RawProjectConf]]). During weaving we parse this and convert it to
[[data:ProjectConf]].

#+name: data:RawProjectConf
#+begin_src haskell
type RawProjectConf :: Type
data RawProjectConf = RawProjectConf
  { name :: Text,
    homepage :: Text,
    repo :: Text,
    version :: Text
  }
  deriving stock (Eq, Generic, Show)
  deriving anyclass (FromJSON, ToJSON)
#+end_src

#+name: f:parseRawProjectConf
#+begin_src haskell
parseRawProjectConf :: Text -> Either String RawProjectConf
parseRawProjectConf = eitherDecodeStrictText
#+end_src

#+name: f:parseProjectConf
#+begin_src haskell
parseProjectConf :: Text -> Either String ProjectConf
parseProjectConf input = case parseRawProjectConf input of
  Left errMsg -> Left errMsg
  Right rawProjectConf ->
    Right
      ProjectConf
        { name = rawProjectConf.name,
          homepage = N.parseURI $ T.unpack rawProjectConf.homepage,
          repo = N.parseURI $ T.unpack rawProjectConf.repo,
          version =
            if T.null rawProjectConf.version
              then Nothing
              else Just rawProjectConf.version
        }
#+end_src

** Architecture
:PROPERTIES:
:ID:       8f5752c0-6162-4de6-9ceb-f78ba584722c
:END:

Generating HTML ultimately means having three components: HTML elements,
CSS, and JavaScript (JS). HTML and CSS alone can be used to create a static
document, but JS is necessary for making things dynamic.

At this stage, the architecture we have in mind for weaving is the following:

  1) Convert the [[id:01da95fe-ba23-4481-9833-428423392f5f::data:Object][data:Object]] (found inside a [[id:25827c17-2015-434b-b686-db3d72b2ee4d::data:Archive][data:Archive]]) into HTML.

  2) Generate CSS separately.

  3) Sprinkle in some JS for interactivity.

Step 3 will be done with [[https://clojurescript.org/][ClojureScript]], which compiles to JS.

One main advantage of this model is that other "viewers" can be created, as long
as they understand the same JSON. While we would prefer to use something more
"typed" like [[https://protobuf.dev/][Protobufs]], [[https://github.com/cognitect/transit-clj][Transit]], or [[https://github.com/edn-format/edn][EDN]], we choose JSON for its universality.
Also, none of these alternative formats support both Haskell and ClojureScript
well.

* Generate HTML
:PROPERTIES:
:ID:       3592f24a-dc14-4ae6-8c06-5680ee7eb9aa
:END:

Weaving mainly means converting the [[id:01da95fe-ba23-4481-9833-428423392f5f::data:Object][data:Object]] into HTML, as part of "Step 1"
in [[id:8f5752c0-6162-4de6-9ceb-f78ba584722c][Architecture]].

** =HtmlWeaver= monad

During the weaving process, we want to access various other settings that may
not be apparent at the [[id:ed81c307-9172-4436-8672-583ea8ecb1f9::data:Cell][data:Cell]] level. To capture these values in one place, we
use a [[data:WeaveConf]]. Instead of passing this around to all functions, we put it
inside a ~ReaderT~ so that it is available for all weave-related functions that
are using the [[type:HtmlWeaver]]. This is analogous to [[id:e16dd5c7-0a63-4c52-afe9-744fdf853643::data:OrgParserState][data:OrgParserState]] which is
available to all parsing functions in [[id:e16dd5c7-0a63-4c52-afe9-744fdf853643::type:OrgParser][type:OrgParser]].

#+name: data:WeaveConf
#+begin_src haskell
type WeaveConf :: Type
data WeaveConf = WeaveConf
  { projectConf :: ProjectConf,
    archive :: Archive,
    originObjectPath :: GPath,
    citeprocResult :: CP.Result Prose,
    watch :: Bool
  }
#+end_src

The ~originObjectPath~ is used to check whether a given [[id:f8254d58-7a3d-4595-a265-e0d6255e6ab5::data:LinkOid][data:LinkOid]] refers to a
cell that exists in the current object being woven in [[f:weaveObject]] (so we know
whether to refer to the cell with just ~#...~ as the HTML =id= attribute, or whether
as ~path/to/external/object.html#...~ because the cell belongs to another object).

The [[type:HtmlWeaver]] is a monad that can compute any ~a~ value. We stack ~ReaderT~ on
top of Lucid's ~HtmlT~ to create the monadic environment where we can read from
[[data:WeaveConf]] whenever we want.

#+name: type:HtmlWeaver
#+begin_src haskell
type HtmlWeaver :: Type -> Type
type HtmlWeaver a = HtmlT (ReaderT WeaveConf Identity) a
#+end_src

Note that the inner monad is the ~ReaderT~. This way we don't have to call ~lift~
every single time we want to use a Lucid combinator like ~head_~ or ~body_~.

Now we just need our starting point for using ~HtmlWeaver~. In our case, the final
thing we want to generate is a ~Text~ value. Lucid gives us ~renderTextT~, which can
run inside a monad. This means we can use that to generate ~Text~ from
[[type:HtmlWeaver]]; this is what [[f:renderAsText]] does.

[[f:renderAsText]] takes a ~WeaveConf~ and an ~HtmlWeaver a~ action, and converts it to
a ~Text~ type. It's there because we cannot use any of the default rendering
functions that Lucid gives us (because they operate on Lucid's ~HtmlT~, not the
~HtmlWeaver~ we use).

#+name: f:renderAsText
#+begin_src haskell
renderAsText :: WeaveConf -> HtmlWeaver a -> Text
renderAsText weaveConf weaver =
  TL.toStrict
    . renderText
    $ hoistHtmlT (flip runReaderT weaveConf) weaver
#+end_src

The ~hoistHtmlT~ function is a convenience helper provided by Lucid, which is
equivalent to ~hoist~ from [[https://hackage.haskell.org/package/mmorph][=Control.Monad.Morph=]]. It applies a function to the
inner monad of ~HtmlT~ (recall that [[type:HtmlWeaver]] is just a ~HtmlT~ whose inner
monad is a ~ReaderT~). So in this case the inner monad is ~ReaderT WeaveConf
Identity~, and running ~runReaderT~ will result in ~Identity ()~ (where ~()~ is the ~a~
in the type signature for [[f:renderAsText]]). So then the call to ~hoistHtmlT~ gives
us ~HtmlT Identity a~, which is what Lucid's ~renderText~ expects.

** Top-level (Object) weaver
:PROPERTIES:
:ID:       891f2674-2be9-4e63-b0f8-7ca43f1354fb
:END:

The top-level weaving function is [[f:weaveObject]], which weaves a [[id:01da95fe-ba23-4481-9833-428423392f5f::data:Object][data:Object]]
value.

The [[f:weaveObject]] function sets up the main HTML bits (like the title, head,
style sheets, etc), before finally delegating to [[f:weaveCell]] for the bulk of the
work.

#+name: f:weaveObject
#+begin_src haskell
weaveObject :: Object -> HtmlWeaver ()
weaveObject object = do
  weaveConf <- ask
  let title' = toHtml $ case lookup "title" object.orgDoc.meta of
        Just title -> title
        Nothing -> "Untitled"
  doctypehtml_ $ do
    <<HTML head>>
    body_ $ do
      div_ [class_ "navbar"] $ do
        weaveNavbar
      nav_ [class_ "toc"] $ do
        ul_ $ do
          weaveToc object.orgDoc.cells
      main_ $ do
        weaveDocMeta object.orgDoc.meta
        forM_ rearrangedCells weaveCell
      aside_ [class_ "sidebar"] $ do
        toHtml @Text "SIDEBAR"
      footer_ $ do
        toHtml @Text "FOOTER"
  where
    rearrangedCells = beforeFootnotes <> sortedFootnotes <> afterFootnotes
    beforeFootnotes = takeWhile (not . isFootnote) object.orgDoc.cells
    afterFootnotes =
      dropWhile isFootnote
        $ dropWhile (not . isFootnote) object.orgDoc.cells
    sortedFootnotes =
      sortOn getSortingKey
        $ takeWhile isFootnote
        $ dropWhile (not . isFootnote) object.orgDoc.cells
    getSortingKey cell
      | (CFootnote footnote) <- cell,
        Just n <- lookup footnote.name object.orgDoc.footnoteNumbers =
          n
      | otherwise = maxBound :: Int
    isFootnote = \case
      CFootnote {} -> True
      CBlock {}
      CFigure {}
      CHeading {}
      CListItem {}
      CMathFragment {}
      CParagraph {}
      CTable {}
      CBibliography {} -> False
#+end_src

The use of ~toHtml~ is to help Haskell infer the correct type. This is because
Lucid will think that regular strings are of type ~Html ()~ (this is how Lucid
automatically escapes strings to be HTML-safe). The ~title_~ function expects a
~Html ()~ type, so we have to manually convert the ~Text~ we get out of ~lookup~
with ~toHtml~.

The cells are rearranged (for footnotes) in ~rearrangedCells~. This way, users
don't have to keep them in order in the doc (users can freely change which ones
are referenced first, without having to manually reorder the footnote
definitions). In Orgmode users can already press ENTER on a footnote reference
and Orgmode will jump to the definition, so manual ordering doesn't matter much
even in that case.

Weaving cells just means delegating to each of the weavers that know how to
handle each cell type.

#+name: f:weaveCell
#+begin_src haskell
weaveCell :: Cell -> HtmlWeaver ()
weaveCell = \case
  CHeading heading -> weaveHeading heading
  CListItem listMarkers -> sequence_ $ map weaveListMarker listMarkers
  CParagraph prose -> p_ $ weaveProse prose
  CBlock block -> weaveBlock block
  CMathFragment mathFragment -> weaveMathFragmentStandalone mathFragment
  CFigure figure -> weaveFigure figure
  CTable table -> weaveTable table
  CFootnote footnote -> weaveFootnote footnote
  CBibliography _ -> weaveBibliography
#+end_src

*** MathJax

We use [[https://www.mathjax.org][MathJax]] to render mathematical expressions (what we encode as the
[[id:d1064535-5c98-4c80-a901-5cdc1fd5297f::data:MathFragment][data:MathFragment]]). The MathJax JS import is a Lucid port of the [[https://www.mathjax.org/#gettingstarted][official
instructions]].

#+name: MathJax script
#+begin_src haskell
script_
  [ id_ "MathJax-script",
    async_ "",
    src_ "https://cdn.jsdelivr.net/npm/mathjax@3.0.1/es5/tex-mml-chtml.js"
  ]
  ("" :: Text)
#+end_src

MathJax is configurable.

#+name: MathJax customization
#+begin_src haskell
let s :: Text
    s =
      """
      window.MathJax = {
        <<Automatic equation numbering>>
        <<Ignore certain HTML element classes>>
      };
      """
script_ [] s
#+end_src

To turn on numbering, we have to run a script with a special ~'ams'~ parameter.

#+name: Automatic equation numbering
#+begin_src javascript
tex: {
    tags: 'ams'
},
#+end_src

It may sound a bit surprising to let MathJax perform the numbering when we
already have this numbering information on hand from the
[[id:d1064535-5c98-4c80-a901-5cdc1fd5297f::f:mathFragmentNumberedParser][f:mathFragmentNumberedParser]]. The thing that MathJax solves for us is the
automatic placement of the numbers themselves on the pages, so that we don't
have to do that part. The parsers we use already conform to the behavior that
MathJax expects when numbering equations (namely, that ~\begin{equation}~ and ~\[~
start numbered and unnumbered equations), so the way we number equations and the
way MathJax numbers equations is the same. In other words, we can let MathJax
number equations for us and those automatically generated equation numbers
should line up with what we have.

We can prohibit MathJax from acting on certain HTML element classes. This is
necessary for making it ignore verbatim and code styles from [[id:d6abea81-d620-4ede-9c2c-68f7ea07f847::f:weaveStyledText][f:weaveStyledText]].

#+name: Ignore certain HTML element classes
#+begin_src javascript
options: {
    ignoreHtmlClass: 'verbatim|code'
}
#+end_src

** Unique names

Generating a unique name suitable for being used as the ~id~ attribute value
requires us to convert some arbitrary text into a DOM ID-friendly name. For this
purpose we have [[f:toSafeHtmlId]].

[[https://www.w3.org/TR/html4/types.html][This page]] says:

#+begin_quote
ID and NAME tokens must begin with a letter ([A-Za-z]) and may be followed by
any number of letters, digits ([0-9]), hyphens ("-"), underscores ("_"), colons
(":"), and periods (".").
#+end_quote

#+name: f:toSafeHtmlId
#+begin_src haskell
toSafeHtmlId :: Text -> Text
toSafeHtmlId = T.map onlyKeepSomeChars
  where
    onlyKeepSomeChars c
      | isAsciiLower c || isAsciiUpper c = c
      | isDigit c = c
      | T.elem c "-_:." = c
      | otherwise = '-'
#+end_src

The [[f:getLinkAnchor]] function generates the unique, human-friendly ID of a

choose to not go through that exercise for the [[id:4127feee-755d-430e-8fef-192e95143790::data:Footnote][data:Footnote]] type, for ease of parsing.

Headings might sound simple, but because they are made up of arbitrary text,
it's fairly involved. The body of a heading is made up of a list of [[id:c8616126-215d-49be-8874-c2aca7d93a54::data:PToken][data:PToken]]
values. So, we have to weave each type of token separately.

#+name: f:weaveHeading
#+begin_src haskell
weaveHeading :: Heading -> HtmlWeaver ()
weaveHeading heading =
  hN [id_ linkAnchor] $ do
    a_ [href_ $ "#" <> linkAnchor] $ do
      toHtml sectionText
      toHtmlRaw ("&emsp;&ensp;" :: Text)
      weaveProse heading.body
  where
    hN = case heading.level of
      1 -> h2_
      2 -> h3_
      3 -> h4_
      4 -> h5_
      _ -> h6_

    linkAnchor = getLinkAnchor $ CHeading heading

A well-formed document should only have one ~<h1>~ HTML element (for the title of
the document). We use ~h1_~ when weaving the title of the document (if any). This
is why we start from ~h2_~ for headings.

The ~sectionText~ already makes the heading unique amongst the other ones in the
Org file, but for human-friendliness we also extract the textual part of it with
[[f:getProseContents]] (which is fed through [[f:toSafeHtmlId]] for safety).

#+name: f:getProseContents
#+begin_src haskell

Weaving code blocks requires us to be able to handle both regular text
(~BTokenString~) and also links (~BTokenLink~). There is some additional work for
supporting syntax highlighting (see [[f:colorizeText]]).

#+name: f:weaveBlock
#+begin_src haskell
weaveBlock :: Block -> HtmlWeaver ()
weaveBlock block = do
  weaveConf <- ask
  div_ [class_ "code-block-container", id_ linkAnchor] $ do
    div_ [class_ "side-popup"] $ do
      a_ [href_ $ "#" <> linkAnchor] $ do
        toHtmlRaw (<<HTML link symbol>> :: String)
    maybeAssignName
    let bodyBorder = case lookup "name" block.meta of
          Just _ -> ""

                BTokenLink l -> Just l
                BTokenString {}
                BTokenPadding {} -> Nothing

        Nothing -> code_ $ toHtml bodyText

    maybeAssignName =
      case lookup "name" block.meta of
        Just name ->
          div_ [class_ "code-block-name"] $ do
            code_ $ toHtml name
        Nothing -> pure ()
    getBlockContentsWithoutLinks :: [BToken] -> Text

      where
        bTokenToText :: BToken -> Text
        bTokenToText = \case
          BTokenString text -> text
          BTokenPadding -> ""
          BTokenLink (Link _name (LinkTargetOid _)) -> "\NUL"
          BTokenLink {} -> ""
    linkAnchor = getLinkAnchor $ CBlock block
#+end_src

The first thing we do is to get the contents of the block with
~getBlockContentsWithoutLinks~. This function is similar to [[id:51f2edd8-5f8e-4c63-841f-da6c5c41680a::f:getBlockContents][f:getBlockContents]]
from =Lilac.Parse=, but does not encode the links information directly into the
text. Instead, links are replaced with the ~\NUL~ character. This is because the
text is fed into [[f:colorizeText]], and we don't want the links to be dealt with in
any special way yet. The ~BTokenPadding~ token is ignored in
~getBlockContentsWithoutLinks~ because ~BTokenPadding~ is only meant to be used for
tangling.

#+name: f:colorizeText
#+begin_src haskell
colorizeText :: Text -> Text -> HtmlWeaver ()
colorizeText lang txt
  | Just syntax <- Sky.lookupSyntax lang Sky.defaultSyntaxMap,
    Just lines <- foldMap' Just $ Sky.tokenize defaultTokeniserConfig syntax txt =
      toHtmlRaw
        . Text.Blaze.Html.Renderer.Text.renderHtml
        $ Sky.formatHtmlInline Sky.defaultFormatOpts lines
  | otherwise = code_ $ toHtml txt
  where
    defaultTokeniserConfig = Sky.TokenizerConfig Sky.defaultSyntaxMap False
#+end_src

Block colorization relies on the [[https://hackage.haskell.org/package/skylighting][=skylighting=]] syntax highlighting library. This
library ignores the ~\NUL~ character, which is what we want. Once we have the
colorized text, we splice in the links with ~spliceLinks~, which relies on
[[f:weaveLink]] for constructing HTML for each link. The splicing works by splitting
on the ~\NUL~ character and manually "zipping" up the colorized substrings with
the woven link HTML fragments.

#+name: f:spliceLinks
#+begin_src haskell
spliceLinks :: Text -> [Link] -> HtmlWeaver Text
spliceLinks colorized links = do
  weaveConf <- ask
  let colorizedStrs = T.splitOn "\NUL" colorized
      f :: ([Text], [Link]) -> Text -> ([Text], [Link])
      f (acc, []) colorizedStr = (colorizedStr : acc, [])
      f (acc, link : links') colorizedStr =
        ( colorizedStr
            : (renderAsText weaveConf $ weaveLink link)
            : acc,
          links'
        )
  pure
    . T.intercalate ""
    . reverse
    . fst
    . foldl' f (take 1 colorizedStrs, links)
    $ drop 1 colorizedStrs
#+end_src

#+name: f:weaveLinkTarget
#+begin_src haskell
weaveLinkTarget :: LinkTarget -> HtmlWeaver T.Text
weaveLinkTarget linkTarget = do
  weaveConf <- ask
  pure $ case linkTarget of
    LinkTargetOid linkOid
      | Just originObj <- lookup weaveConf.originObjectPath weaveConf.archive.objects,
        Just internalCell <- lookup linkOid originObj.symbols ->
          "#" <> getLinkAnchor internalCell
      | Just externalCell <- lookup linkOid weaveConf.archive.symbols,
        Just externalObjGPath <- lookup linkOid weaveConf.archive.symbolPath,
        Just toObjPath <- P.encodeUtf $ decodeGPath externalObjGPath,
        Just fromObjPath <- P.encodeUtf $ decodeGPath weaveConf.originObjectPath,
        Right str <-
          P.decodeWith utf8 utf8
            $ P.replaceExtension (getRelativePathWithoutSymlinks fromObjPath toObjPath) htmlExt ->
          (T.pack str) <> "#" <> getLinkAnchor externalCell
      | otherwise -> "#LILAC_BROKEN_LINK-" <> show linkOid
      where
        htmlExt = P.unsafeEncodeUtf "html"
    LinkTargetFootnote name
      | Just originObj <- lookup weaveConf.originObjectPath weaveConf.archive.objects,
        Just footnoteNumber <- lookup name originObj.orgDoc.footnoteNumbers ->
          (T.pack "#footnote-") <> (T.show footnoteNumber)
      | otherwise -> "#LILAC_BROKEN_LINK"
    LinkTargetFilePath path -> T.pack $ N.escapeURIString N.isUnescapedInURI path
    LinkTargetURI uri -> T.pack $ N.uriToString id uri ""
#+end_src

[[f:getRelativePathWithoutSymlinks]] takes two file paths. It tries to answer the
question "assuming I am in the directory in the first file, how can I go to the
directory containing the second file?" This assumes that the given paths have no
symlinks (to avoid the pitfall described at [[https://hackage.haskell.org/package/filepath-1.5.4.0/docs/System-OsPath.html#v:makeRelative][System.OsPath.makeRelative]] and [[https://neilmitchell.blogspot.com/2015/10/filepaths-are-subtle-symlinks-are-hard.html][this
blog post]]).

We use the following algorithm:

  1) If we're in the same directory, or if the destination is a child of the
     source directory, then drop the common prefix of the
     destination. ~a/b/c/src~ to ~a/b/c/dest~ is ~dest~. ~a/b/c/src~ to ~a/b/c/d/e/dest~
     is ~d/e/dest~.

  2) If we're not in the same directory, we have to go up N directories up until
     we get to the common prefix.

     - No common prefix: go up all the way to the root, then go to the
       destination. ~a/b/c/src~ to ~d/dest~ is ~../../../d/dest~.

     - Some common prefix: go up to the common prefix. ~a/b/c/dest~ to ~a/x/y/dest~
       is ~../../x/y/dest~ because ~a~ is the common prefix. ~a/b/c/d/e/src~ to ~a/dest~
       is ~../../../../dest~.

#+name: f:getRelativePathWithoutSymlinks
#+begin_src haskell
getRelativePathWithoutSymlinks :: OsPath -> OsPath -> OsPath
getRelativePathWithoutSymlinks src dest
  | dirsSrc == dirsDest || isDestChildOfSrc =
      P.joinPath $ remainingDest <> destFile
  | null commonPathPrefix =
      P.joinPath $ replicate (length dirsSrc) goUp <> destFile
  | otherwise =
      P.joinPath
        $ replicate (length dirsSrc - length commonPathPrefix) goUp
        <> drop (length commonPathPrefix) dirsDest
        <> destFile
  where
    goUp = P.unsafeEncodeUtf ".."
    destFile = [P.takeFileName dest]
    dirSrc = P.takeDirectory src
    dirDest = P.takeDirectory dest
    dirsSrc = P.splitDirectories dirSrc
    dirsDest = P.splitDirectories dirDest
    commonPathPrefix = commonPrefix dirsSrc dirsDest
    isDestChildOfSrc = dirsSrc == commonPathPrefix
    remainingDest = drop (length commonPathPrefix) dirsDest
#+end_src

The [[f:commonPrefix]] helper returns the common prefix found in two lists.

Math fragments come in two types, standalone and inline. Standalone fragments

#+name: f:weaveMathFragmentStandalone
#+begin_src haskell
weaveMathFragmentStandalone :: MathFragment -> HtmlWeaver ()
weaveMathFragmentStandalone mathFragment = do
  let (begMarker, endMarker)
        | Just _ <- lookup "__equation_number" mathFragment.meta =
            ("\\begin{equation}", "\\end{equation}")
        | otherwise = ("\\[", "\\]")
  p_ [id_ linkAnchor] $ do
    a_ [href_ $ "#" <> linkAnchor, class_ "self-link"] $ do

#+name: f:weaveTable
#+begin_src haskell
weaveTable :: Table -> HtmlWeaver ()
weaveTable table = do
  let captionPrefix =
        "Table "
          <> lookupDefault "table-number-error" "__table_number" table.meta
  figure_ [id_ linkAnchor] $ do
    figcaption_ [] $ do
      a_ [href_ $ "#" <> linkAnchor, class_ "self-link"] $ do
        toHtml captionPrefix
      toHtml $ case table.caption.unProse of
        [] -> "." :: Text
        _ -> ": " :: Text
      weaveProse table.caption
    table_ [] $ do
      forM_ (zip [1 :: Int ..] getColgroups) $ \(groupIdx, numCols) -> do
        let colgroupAttrs =
              if groupIdx > 1
                then [class_ "table-vertical-line-colgroup"]
                else []
        colgroup_ colgroupAttrs $ do
          forM_ [1 .. numCols] $ \colNum -> do
            if (colNum > 1)
              then col_ [class_ "table-vertical-line-col"]
              else col_ []
      thead_ [] $ do
        tr_ [] $ do
          forM_ columnNames $ \prose -> do
            th_ [] $ weaveProse prose
      tbody_ [] $ do
        forM_ (rows visibleRows) $ \row ->
          if row == [Prose []]
            then do
              tr_ [class_ "table-horizontal-line"] ""
            else do
              tr_ [] $ do
                forM_ row $ \prose -> do
                  let tdAttrs =
                        if mostlyNumeric prose
                          then [class_ "table-cell-numeric"]
                          else []
                  td_ tdAttrs $ weaveProse prose
  where
    linkAnchor = getLinkAnchor $ CTable table
    hideMarkingCharInFirstColumn :: [((Int, Int), Prose)] -> [Prose]
    hideMarkingCharInFirstColumn = \case
      [] -> []
      (((_row, _col), prose) : cells)
        | prose == tableHorizontalLine -> [Prose []]
        | markingCharExistsInFirstColumn -> map snd cells
        | otherwise -> prose : map snd cells
    markingCharExistsInFirstColumn = any (not . visibleColumn) firstColumnCells
    tableCellsFromRow :: Int -> [Prose]
    tableCellsFromRow n =
      hideMarkingCharInFirstColumn
        . M.toList
        $ M.filterWithKey (\(row, _col) _ -> row == n) table.grid
    rowMax = foldl' max 0 . map fst $ keys table.grid
    rows rowNums = map tableCellsFromRow rowNums
    columnNames = tableCellsFromRow headerRowIndex
    firstColumnCells =
      M.toList
        $ M.filterWithKey (\(_row, col) _ -> col == 1) table.grid
    headerRowIndex = fromMaybe 1 $ foldl' f Nothing firstColumnCells
    f acc@(Just _) _ = acc
    f acc cell@((row, _col), _)
      | visibleColumn cell = Just row
      | otherwise = acc
    visibleColumn :: ((Int, Int), Prose) -> Bool
    visibleColumn (_, prose) = case prose.unProse of
      [] -> True
      [PTokenStyledText styledText] ->
        notElem styledText.body $ map T.singleton markingChars
      _ -> True
    visibleRow :: ((Int, Int), Prose) -> Bool
    visibleRow (_, prose) = case prose.unProse of
      [] -> True
      [PTokenStyledText styledText] ->
        notElem styledText.body $ map T.singleton markingCharsInvisible
      _ -> True
    visibleRows = filter (`notElem` invisibleRows) [(headerRowIndex + 1) .. rowMax]
    invisibleRows = foldl' g [] firstColumnCells
    g acc cell@((row, _col), _)
      | visibleRow cell = acc
      | otherwise = row : acc
    getColgroups :: [Int]
    getColgroups =
      maybe
        [rowMax]
        (reverse . foldl' getColgroupStarts [0] . tableCellsFromRow)
        getColgroupsRow
    getColgroupStarts :: [Int] -> Prose -> [Int]
    getColgroupStarts ns prose = case ns of
      [] -> []
      [0] -> [1]
      acc@(latest : rest)
        | proseHasColgroupStartMarker prose -> 1 : acc
        | otherwise -> latest + 1 : rest
    getColgroupsRow = foldl' h Nothing firstColumnCells
    h :: Maybe Int -> ((Int, Int), Prose) -> Maybe Int
    h acc ((row, _col), prose)
      | isJust acc = acc
      | proseHasNonExportMarker prose = Just row
      | otherwise = acc
    proseHas :: Text -> Prose -> Bool
    proseHas prefix prose = case prose.unProse of
      [] -> False
      (firstPToken : _) -> case firstPToken of
        PTokenStyledText styledText ->
          (maskToStyles styledText.style == [])
            && T.isPrefixOf prefix styledText.body
        PTokenLink {}
        PTokenMathFragment {}
        PTokenCitation {}
        PTokenDivStart {}
        PTokenDivEnd {} -> False
    proseHasColgroupStartMarker :: Prose -> Bool
    proseHasColgroupStartMarker = proseHas "<"
    proseHasNonExportMarker :: Prose -> Bool
    proseHasNonExportMarker = proseHas "/"
    mostlyNumeric :: Prose -> Bool
    mostlyNumeric prose =
      let rawText = T.concat $ map extractText prose.unProse
       in isNumericText rawText
    extractText = \case
      PTokenStyledText styledText -> styledText.body
      PTokenLink {}
      PTokenMathFragment {}
      PTokenCitation {}
      PTokenDivStart {}
      PTokenDivEnd {} -> ""
#+end_src

** Citations
:PROPERTIES:

:END:

For weaving citations, we use a 4-step process:

  1) Convert the [[id:c8616126-215d-49be-8874-c2aca7d93a54::newtype:Prose][newtype:Prose]] contents of [[id:6fd068e3-cc95-41a4-8126-bc7bd17c79bb::data:Citation][data:Citation]] into ~CslJson Text~,
     while preserving the information of non-text things like links and math
     fragments by embedding them as ~CslLink~ for things that ~CslJson Text~ does
     not support.

  2) Call into =Citeproc.citeproc= to get the transformed ~CslJson Text~ back out.

  3) Convert back the ~CslJson Text~ into [[id:c8616126-215d-49be-8874-c2aca7d93a54::newtype:Prose][newtype:Prose]].

  4) Weave the [[id:c8616126-215d-49be-8874-c2aca7d93a54::newtype:Prose][newtype:Prose]] as usual.

We can't simply convert [[id:c8616126-215d-49be-8874-c2aca7d93a54::newtype:Prose][newtype:Prose]] into HTML first before calling
=Citeproc.citeproc= because then that would result in things like ~<a href=...>~ being
converted into ~&lt;a href=...&gt;~ (entity conversion of the given text).

For the first step, we need a function to convert [[id:c8616126-215d-49be-8874-c2aca7d93a54::newtype:Prose][newtype:Prose]] into ~CslJson
Text~. For that we have [[f:proseToCslJsonText]]. This function abuses the ~CslDiv~
constructor to encode information that cannot be represented natively in
~CslJson~.

#+name: f:proseToCslJsonText
#+begin_src haskell
proseToCslJsonText :: Prose -> CslJson Text
proseToCslJsonText prose = foldl' f CslEmpty prose.unProse
  where
    f :: CslJson Text -> PToken -> CslJson Text
    f acc pToken = case pToken of
      PTokenStyledText styledText ->
        let styles = maskToStyles styledText.style
            body = parseCslJson mempty styledText.body
         in acc <> applyStyles body styles
      PTokenLink link ->
        let encoded = CslLink ("LILAC_LINK\NUL" <> unparseLink link) CslEmpty
         in acc <> encoded
      PTokenMathFragment mathFragment ->
        let encoded = CslDiv ("LILAC_MATH_FRAGMENT\NUL" <> unparseMathFragment mathFragment) CslEmpty
         in acc <> encoded
      PTokenCitation {}
      PTokenDivStart {}
      PTokenDivEnd -> acc
    applyStyles :: CslJson Text -> [Style] -> CslJson Text
    applyStyles cslBody styles = foldl' applyStyle cslBody styles
    applyStyle :: CslJson Text -> Style -> CslJson Text
    applyStyle acc = \case
      Bold -> CslBold acc
      Italic -> CslItalic acc
      Underline -> CslUnderline acc
      Verbatim -> CslDiv "LILAC_STYLE_VERBATIM\NUL" acc
      Code -> CslDiv "LILAC_STYLE_CODE\NUL" acc
      Smallcaps -> CslSmallCaps acc
      Subscript -> CslSub acc
      Superscript -> CslSup acc
#+end_src

[[f:proseToMaybeCslJsonText]] is a wrapper around [[f:proseToCslJsonText]] to convert it
easily into a ~Maybe (CslJson Text)~. This is useful because the Citeproc library
uses this type for constructing its citation objects.

#+name: f:proseToMaybeCslJsonText
#+begin_src haskell
proseToMaybeCslJsonText :: Prose -> Maybe (CslJson Text)

  case proseToCslJsonText prose of
    CslEmpty -> Nothing
    cslJson -> Just cslJson
#+end_src

For calling =Citeproc.citeproc=, we have to convert our internal [[id:6fd068e3-cc95-41a4-8126-bc7bd17c79bb::data:Citation][data:Citation]]
into Citeproc's own citation type.

#+name: f:citationToCiteprocCitation
#+begin_src haskell
citationToCiteprocCitation :: Citation -> CP.Citation (CslJson Text)
citationToCiteprocCitation citation =
  CP.Citation
    { CP.citationId = Nothing,
      CP.citationNoteNumber = citation.noteNumber,
      CP.citationPrefix = proseToMaybeCslJsonText citation.prefix,
      CP.citationSuffix = proseToMaybeCslJsonText citation.suffix,
      CP.citationItems = concatMap (citeToCiteprocCitationItems sv) citation.cites
    }
  where
    (sv, _) = citation.styleVariation
#+end_src

The individual [[id:6fd068e3-cc95-41a4-8126-bc7bd17c79bb::data:Cite][data:Cite]] items are converted into Citeproc's ~CitationItem~ type.
Orgmode has fancy styling capabilities for individual citation items (this is
~sv1~ in [[f:citeToCiteprocCitationItems]] below), but we only support the ~t~ and ~na~
style variants (we don't even look at the second element in the
~citation.styleVariation~ tuple). This is because we rely on CSL to do nearly all
of the styling for us. CSL itself [[https://citeproc-js.readthedocs.io/en/latest/csl-json/markup.html#cite-items][allows for just a handful of variations]],
namely:

  - ~suppress-author~: do not show the author name

  - ~author-only~: only show the author name

We achieve the semantic meaning of ~t~ (aka ~text~) and ~na~ (aka ~noauthor~) by using
combinations of the above. The ~na~ maps 1:1 to ~author-only~ so that's an easy one.
However the ~t~ style needs to inject the author name (as regular text) just
before the cite. In order to achieve this, we create two citations, using a
combination of ~suppress-author~ (~CP.SuppressAuthor~) and ~author-only~
(~CP.AuthorOnly~) to get what we want. Because we end up creating two citations in
place of one, the result type of [[f:citeToCiteprocCitationItems]] is a list.

#+name: f:citeToCiteprocCitationItems
#+begin_src haskell
citeToCiteprocCitationItems :: Maybe Text -> Cite -> [CP.CitationItem (CslJson Text)]
citeToCiteprocCitationItems sv cite =
  let citationItem =
        CP.CitationItem
          { CP.citationItemId = CP.ItemId cite.id,
            CP.citationItemLabel = term,
            CP.citationItemLocator = coord,
            CP.citationItemType = CP.NormalCite,
            CP.citationItemPrefix = proseToMaybeCslJsonText cite.prefix,
            CP.citationItemSuffix = proseToMaybeCslJsonText cite.suffix,
            CP.citationItemData = Nothing
          }
   in if
        | Just "t" <- sv ->
            [ citationItem
                { CP.citationItemType = CP.AuthorOnly,
                  CP.citationItemSuffix = Nothing
                },
              citationItem
                { CP.citationItemType = CP.SuppressAuthor,
                  CP.citationItemPrefix = Nothing
                }
            ]
        | Just "na" <- sv ->
            [citationItem {CP.citationItemType = CP.SuppressAuthor}]
        | otherwise -> [citationItem]
  where
    (term, coord) = case cite.locator of
      Just (t, c) -> (Just t, Just c)
      Nothing -> (Nothing, Nothing)
#+end_src

The last piece is the conversion of ~CslJson Text~ back into [[id:c8616126-215d-49be-8874-c2aca7d93a54::newtype:Prose][newtype:Prose]]. We
have to recursively traverse the nodes in the ~CslJson Text~ tree.

#+name: f:cslJsonTextToProse
#+begin_src haskell
cslJsonTextToProse :: CslJson Text -> Prose
cslJsonTextToProse cslJsonText = compressProse . Prose $ f [] cslJsonText
  where
    f :: [Style] -> CslJson Text -> [PToken]
    f s = \case
      CslEmpty -> []
      CslText t -> [PTokenStyledText StyledText {body = t, style = styleMaskFrom s}]
      CslConcat a CslEmpty -> f s a
      CslConcat (CslConcat a b) c -> f s (CslConcat a (CslConcat b c))
      CslConcat a b -> f s a <> f s b
      CslQuoted a -> f s a
      CslItalic a -> f (Italic : s) a
      CslNormal a -> f [] a
      CslBold a -> f (Bold : s) a
      CslUnderline a -> f (Underline : s) a
      CslNoDecoration a -> f (filter (/= Underline) s) a
      CslSmallCaps a -> f (Smallcaps : s) a
      CslBaseline a -> f (filter (`notElem` [Subscript, Superscript]) s) a
      CslSup a -> f (Superscript : s) a
      CslSub a -> f (Subscript : s) a
      CslNoCase a -> f s a
      CslDiv t a
        | t == "LILAC_STYLE_CODE\NUL" -> f (Code : s) a
        | t == "LILAC_STYLE_VERBATIM\NUL" -> f (Verbatim : s) a
        | "LILAC_MATH_FRAGMENT\NUL" `T.isPrefixOf` t ->
            (CP.fromText (T.drop 20 t) :: Prose).unProse
        | otherwise -> [PTokenDivStart t] <> f s a <> [PTokenDivEnd]
      CslLink t a
        | "LILAC_LINK\NUL" `T.isPrefixOf` t ->
            (CP.fromText (T.drop 11 t) :: Prose).unProse
        | "#ref-" `T.isPrefixOf` t ->
            let uri =
                  N.URI
                    { N.uriScheme = "",
                      N.uriAuthority = Nothing,
                      N.uriPath = T.unpack t,
                      N.uriQuery = "",
                      N.uriFragment = ""
                    }
                target = LinkTargetURI uri
                name = compressStyledText . getStyledText $ f s a
             in [PTokenLink Link {target = target, name = name}]
        | otherwise -> case (N.parseURI $ T.unpack t) of
            Nothing -> []
            Just uri ->
              let target = LinkTargetURI uri
                  name = compressStyledText . getStyledText $ f s a
               in [PTokenLink Link {target = target, name = name}]
    getStyledText [] = []
    getStyledText (pToken : rest) = case pToken of
      PTokenStyledText styledText -> styledText : getStyledText rest
      PTokenLink {}
      PTokenMathFragment {}
      PTokenCitation {}
      PTokenDivStart {}
      PTokenDivEnd {} -> []
#+end_src

The ~CslNoCase~ is fine to ignore because it's most likely used by =Citeproc= to
handle case-changing transformations, and is probably not meant to be used
directly by consumers.

The ~CslDiv~ is used to wrap bibliographical entries inside printed bibliography
for formatting purposes. We ignore them for now, except for those ~LILAC_STYLE...~
bits that we've encoded in [[f:proseToCslJsonText]].

Now we have all of the pieces needed to process citations. The idea is to
process all citations found inside an Org document at once, just before the
weaving begins in [[id:891f2674-2be9-4e63-b0f8-7ca43f1354fb::f:weaveObject][f:weaveObject]], by calling ~Citeproc.citeproc~ which will get us
a ~Result a~ which includes the formatted citations as well as the formatted
bibliography. This part is handled by [[f:prepareCitations]]. Then during the
weaving process we refer to these formatted citations (of type ~Prose~), before
finally converting them to HTML again.

#+name: f:prepareCitations
#+begin_src haskell
prepareCitations :: GPath -> Object -> Archive -> IO (CP.Result Prose)
prepareCitations objGPath object archive = do
  bibPathsRelative <- makeRelativeToObjectPath objGPath object.orgDoc.bibPaths
  cslPathRelative <- listToMaybe <$> (makeRelativeToObjectPath objGPath $ maybeToList object.orgDoc.cslPath)
  let bibRefsFromOrgDoc =
        filter neededByCitations
          . concat
          . catMaybes
          $ map (\bp -> lookup bp archive.bibs) bibPathsRelative
      CP.Result citations bibliography warnings =
        f bibRefsFromOrgDoc cslPathRelative
      resultWithProse =
        CP.Result
          { CP.resultCitations = map cslJsonTextToProse citations,
            CP.resultBibliography = map (\(k, cslJsonText) -> (k, cslJsonTextToProse cslJsonText)) bibliography,
            CP.resultWarnings = warnings
          }
  pure resultWithProse
  where
    citeprocOptions =
      CP.CiteprocOptions
        { linkCitations = True,
          linkBibliography = True
        }
    blankResult :: CP.Result (CslJson Text)
    blankResult =
      CP.Result
        { CP.resultCitations = [],
          CP.resultBibliography = [],
          CP.resultWarnings = ["BLANK CITATION RESULT"]
        }
    f bibRefs cslPathRelative
      | Just cslPath' <- cslPathRelative,
        Just rawXML <- lookup cslPath' archive.csls,
        Right citeprocStyle <- parseCitationStyle rawXML =
          CP.citeproc
            citeprocOptions
            citeprocStyle
            Nothing
            bibRefs
            (map citationToCiteprocCitation object.orgDoc.citations)
      | otherwise = blankResult
    neededByCitations bibRef =
      let citeIds =
            concatMap
              (\c -> map (\cite -> cite.id) c.cites)
              object.orgDoc.citations
       in bibRef.referenceId.unItemId `elem` citeIds
#+end_src

The ~neededByCitations~ helper filters out the bibliographical entries so that we
only print the bibliography that are actually used by the citations. See [[https://github.com/jgm/citeproc/issues/169][this
upstream issue]].

** Table of Contents

The /Table of Contents/ or TOC is automatically generated and inserted into the
left sidebar. It serves as a navigation menu of the first three levels of
headings.

Eventually we want to support collapsible headings inside the TOC. The
traditional way to do this is to toggle the visibility of child elements when
clicking to expand/collapse the parent heading. Selecting child elements is
easiest when there is a hierarchical (nested) structure. The simplest way to do
this is to use unordered list items.

So what we need to do is convert the flat heading cells into a nested structure.
The spirit of this is very similar to how we computed the section numbers for
each heading in [[id:16a68a74-d4cc-41a4-ac77-cbca77de2a31::f:headingParser][f:headingParser]]. Every time we enter a nesting level, we'll have
to create a new unordered list tag (~<ul>~), and every time we leave a level (and
we may leave more than one level at once), we have to close those unordered list
tags (with ~</ul>~).

#+name: f:weaveToc
#+begin_src haskell
weaveToc :: [Cell] -> HtmlWeaver ()
weaveToc cells =
  let actions = reverse . fst $ foldl' f ([], 1) cells
   in sequence_ actions
  where
    f :: ([HtmlWeaver ()], Int) -> Cell -> ([HtmlWeaver ()], Int)
    f (actions, prevLevel) = \case
      CHeading heading ->
        let weaveTocHeading :: HtmlWeaver ()
            weaveTocHeading =
              li_ [class_ $ "toc-level-" <> show heading.level] $ do
                a_ [href_ $ "#" <> linkAnchor] $ do
                  toHtml sectionText
                  toHtmlRaw ("&ensp;" :: Text)
                  weaveProse heading.body
            sectionText = getSectionText heading
            linkAnchor = getLinkAnchor $ CHeading heading
            unnestLevel :: Int -> HtmlWeaver ()
            unnestLevel levelDiff =
              forM_ [1 .. levelDiff] $ \_ -> weaveListMarker LUnorderedEnd
            action :: HtmlWeaver ()
            action
              | prevLevel < heading.level = do
                  weaveListMarker LUnorderedStart
                  weaveTocHeading
              | prevLevel > heading.level = do
                  unnestLevel (prevLevel - heading.level)
                  weaveTocHeading
              | otherwise = weaveTocHeading
         in (action : actions, heading.level)
      CFootnote {}
      CBlock {}
      CFigure {}
      CListItem {}
      CMathFragment {}
      CParagraph {}
      CTable {}
      CBibliography {} -> (actions, prevLevel)
#+end_src

** Navigation bar

The navigation bar is at the top of the page as a horizontal bar.

#+name: f:weaveNavbar
#+begin_src haskell
weaveNavbar :: HtmlWeaver ()
weaveNavbar = do
  div_ [class_ "breadcrumbs"] $ do
    weaveBreadcrumbs
#+end_src

One of the things in the navbar is the "breadcrumbs", which is the path that
points to the current document. This path is constructed by starting with the
project name, followed by the path to the object currently being woven, which is
taken from the ~originObjectPath~ field from [[data:WeaveConf]].

The breadcrumbs are made up of three pieces:

  1) project name

  2) middle

  3) Org document name

The middle part can be any number of intervening directory names (can be empty).
Only the project name and Org document name are guaranteed to exist. This is
because the project name comes from [[data:ProjectConf]], and the Org document name
comes from the ~originObjectPath~ from [[data:WeaveConf]].

The breadcrumbs are woven in [[f:weaveBreadcrumbs]].

#+name: f:weaveBreadcrumbs
#+begin_src haskell
weaveBreadcrumbs :: HtmlWeaver ()
weaveBreadcrumbs = do
  weaveConf <- ask
  weaveProjectName weaveConf.projectConf
  let breadcrumbsTail =
        map osPathDecoder
          . P.splitDirectories
          . P.unsafeEncodeUtf
          $ decodeGPath weaveConf.originObjectPath
      breadcrumbsMiddle = reverse . drop 1 $ reverse breadcrumbsTail
      breadcrumbLast =
        convertObjectExtensionToOrg . take 1 $ reverse breadcrumbsTail
  forM_ breadcrumbsMiddle $ \breadcrumb -> do
    weaveBreadcrumbSeparator
    weaveBreadcrumb breadcrumb
  forM_ breadcrumbLast $ \breadcrumb -> do
    weaveBreadcrumbSeparator
    a_ [href_ "#"] $ do
      weaveBreadcrumb breadcrumb
  where
    osPathDecoder osp = case P.decodeUtf osp :: Maybe FilePath of
      Nothing -> "LILAC_ERROR_INVALID_OSPATH"
      Just fp -> T.pack fp
    weaveProjectName :: ProjectConf -> HtmlWeaver ()
    weaveProjectName projectConf = case projectConf.homepage of
      Nothing -> do
        weaveBreadcrumb projectConf.name
      Just uri -> do
        let homepageLinkTarget = T.pack $ N.uriToString id uri ""
        a_ [href_ homepageLinkTarget] $ do
          weaveBreadcrumb projectConf.name
    weaveBreadcrumb :: Text -> HtmlWeaver ()
    weaveBreadcrumb breadcrumb = do
      span_ [class_ "breadcrumb"] $ do
        toHtml breadcrumb
    weaveBreadcrumbSeparator :: HtmlWeaver ()
    weaveBreadcrumbSeparator = do
      toHtml @Text " "
      span_ [class_ "breadcrumb-separator"] $ do
        toHtml @Text "/"
      toHtml @Text " "
    convertObjectExtensionToOrg :: [Text] -> [Text]
    convertObjectExtensionToOrg [] = []
    convertObjectExtensionToOrg (objName : rest) =
      let parts = T.split (== '.') objName
          withoutObjectExtension = drop 1 $ reverse parts
          withOrgExtension = ".org" : withoutObjectExtension
       in (T.concat $ reverse withOrgExtension) : rest
#+end_src

The ~convertObjectExtensionToOrg~ function converts something like ~foo.lobj~ into
~foo.org~.

The reliance on ~originObjectPath~ assumes that the archive has object paths that

[[f:getWovenPrettyFromPath]] weaves the given Org file to a =Text=, by first compiling
it to an object. Then in our test cases we can check for expected substrings
inside it. Note how it uses =renderHtml= from the =Text.Blaze.Html.Renderer.Pretty=
module, because we want to be able to write test cases where we write expected
HTML substrings in a prettified way (for readability).

#+name: f:getWovenPrettyFromPath
#+begin_src haskell
getWovenPrettyFromPath :: FilePath -> IO (Either String Text)
getWovenPrettyFromPath path = do
  inputOrgFileGPath <- encodeGPath $ "test/Lilac/WeaveSpec/" <> path
  inputOrgFile <- LU.readFrom "test/Lilac/WeaveSpec/" path
  let parseResult =
        MP.runParser
          (runStateT LP.orgDocParser defaultOrgParserState)
          path
          (nilOidOrgDoc <> inputOrgFile)
  case parseResult of
    Left errBundle -> pure . Left $ MP.errorBundlePretty errBundle
    Right (orgDoc, _) -> do
      object <- LC.mkObject orgDoc
      maybeArchive <- LC.mkArchive [(inputOrgFileGPath, object)]
      case maybeArchive of
        Left errMsg -> pure $ Left errMsg
        Right archive -> do
          result <- LW.prepareCitations inputOrgFileGPath object archive
          let projectConf =
                ProjectConf
                  { name = "Test Project",
                    homepage = Nothing,
                    repo = Nothing,
                    version = Nothing
                  }
              weaveConf =
                WeaveConf
                  { projectConf = projectConf,
                    archive = archive,
                    originObjectPath = inputOrgFileGPath,
                    citeprocResult = result,
                    watch = True
                  }
          pure
            . Right
            . LW.renderAsText weaveConf
            $ LW.weaveObject object

[[f:searchOrderedNeedles]] looks through a haystack and searches for all given
needles to be in the haystack, in order.

#+name: f:searchOrderedNeedles
#+begin_src haskell
searchOrderedNeedles :: Text -> [Text] -> (String, [Expectation])
searchOrderedNeedles haystackRaw needles =
  (\expectations -> ("sees needles", expectations))
    . reverse
    . fst
    $ foldl' f ([], haystackRaw) needles
  where
    f ::
      ([Expectation], Text) ->
      Text ->
      ([Expectation], Text)
    f (testCases, haystack) needle =
      let (discardMe, foundAndRest) = T.breakOn needle haystack
          discardLen = T.length discardMe
          needleStr = T.unpack needle
          foundAndRestStr = T.unpack foundAndRest
          expectation = foundAndRestStr `shouldStartWith` needleStr
          expectationF =
            expectationFailure
              $ "could not find "
              <> (show $ needleStr)
              <> " in haystack:\n"
              <> (T.unpack haystack)
          remainingHaystack = T.drop discardLen haystack
       in if foundAndRest == T.empty
            then (expectationF : testCases, remainingHaystack)
            else (expectation : testCases, remainingHaystack)
#+end_src

In practice we will only need multiple needles if we are dealing with a
complicated haystack (with nested structures) and we only want to check some
key structures within it.

[[f:weaveExpect]] takes a path to an Org file, the global Org ID locations file, and

** Generic helpers

[[f:noMargin]] removes all margins.

#+name: f:noMargin
#+begin_src haskell
noMargin :: Css
noMargin = ev margin $ px 0
#+end_src

[[f:yx]] is a horizontal/vertical size helper. It accepts a function and two sizes
for the horizontal and vertical parts. E.g., instead of calling

#+begin_src haskell
padding (px 6) (px 10) (px 6) (px 10)
#+end_src

you can do

#+begin_src haskell
yx padding (px 6) (px 10)
#+end_src

to save some keystrokes and decrease the chance of typos.

#+name: f:yx
#+begin_src haskell
yx :: (Size sz -> Size sz -> Size sz -> Size sz -> Css) -> Size sz -> Size sz -> Css
yx f x y = f x y x y
#+end_src

[[f:ev]] is like [[f:yx]], but uses the same size for *everything*.

#+name: f:ev
#+begin_src haskell
ev :: (Size sz -> Size sz -> Size sz -> Size sz -> Css) -> Size sz -> Css
ev f x = f x x x x
#+end_src

[[f:rgbHex]] converts a hex number into a CSS ~Color~ value. While this can be used
directly as in [[css:Headings]], its is used more often indirectly via [[f:colorFrom]]
which relies depends on this helper.

#+name: f:rgbHex
#+begin_src haskell
rgbHex :: Int -> Color
rgbHex rgb'
  | rgb' > 0xffffff = rgbHex 0xffffff
  | rgb' < 0 = rgbHex 0
  | otherwise = rgb rr gg bb
  where
    rr = fromIntegral $ shiftR rgb' 16 .&. 0xFF
    gg = fromIntegral $ shiftR rgb' 8 .&. 0xFF
    bb = fromIntegral $ rgb' .&. 0xFF
#+end_src

** Colors

[[https://hackage.haskell.org/package/clay][Clay]] uses its own internal ~Color~ type, which can only be constructed from
integer values. However we want to talk about colors using strings because using
something like "#22ffff" can allow Emacs to colorize it in the buffer, aiding
visualization.

[[f:colorFrom]] converts a ~Text~ into a ~Color~, defaulting to "#ff0000" if parsing
fails.

#+name: f:colorFrom
#+begin_src haskell
colorFrom :: Text -> Color
colorFrom input = case MP.parseMaybe isHexColorParser input of
  Nothing -> rgbHex 0xff0000
  Just color' -> color'
#+end_src

This depends on [[f:isHexColorParser]] which is mostly a wrapper around
~Text.Megaparsec.Char.Lexer.hexadecimal~.

#+name: f:isHexColorParser
#+begin_src haskell
isHexColorParser :: Parser Color
isHexColorParser = do
  _ <- char '#'
  n <- hexadecimal
  pure $ rgbHex n
#+end_src

The ~Parser~ is a type synonym for a "standard" Megaparsec type defined in the
[[https://hackage.haskell.org/package/megaparsec-9.7.0/docs/Text-Megaparsec.html][documentation]].

#+name: type:Parser
#+begin_src haskell
type Parser :: Type -> Type
type Parser = MP.Parsec Void Text
#+end_src
