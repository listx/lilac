* Object generation
:PROPERTIES:
:ID:       01da95fe-ba23-4481-9833-428423392f5f
:END:

The [[data:Object]] encodes information which we want to reuse when building up
either the "block universe" for tangling, or "cell universe" when weaving. Both
of these concepts are essentially the same thing (the "block universe" is a
special case of the "cell universe", such that all cells are code blocks).

#+name: data:Object
#+begin_src haskell
type Object :: Type
data Object = Object
  { orgDoc :: OrgDoc,
    symbols :: Map LinkOid Int,
    externalOids :: [LinkOid]
  }
  deriving stock (Eq, Ord, Generic, Show)
  deriving anyclass (FromJSON, ToJSON)
#+end_src

The ~symbols~ houses all links that point to cells inside the current ~OrgDoc~. We
have to use [[id:f8254d58-7a3d-4595-a265-e0d6255e6ab5::data:LinkOid][data:LinkOid]] as a key, and for this we need to define at least a
~ToJSONKey~ instance and ~FromJSONKey~ instance. Otherwise, =Data.Aeson= can give an
unrelated error message like

#+begin_quote
Error in $.symbols: parsing Map failed, expected Array, but encountered Object
#+end_quote

when trying to parse the JSON for symbols (~"symbols":{}~), such that ~"symbols":[]~
won't give an error (strange!).

Marshaling to JSON is straightforward, because we can just reuse the [[id:f8254d58-7a3d-4595-a265-e0d6255e6ab5::instance:Show
 LinkOid][instance:Show LinkOid]], which already knows how to convert a ~LinkOid~ to a ~String~
value.

Unmarshaling is tricky because we have to inform =Data.Aeson= how to convert a
~Text~ to ~LinkOid~. This is what we do in [[f:parseJSONLinkOid]].

#+name: f:parseJSONLinkOid
#+begin_src haskell
parseJSONLinkOid :: Text -> Parser LinkOid
parseJSONLinkOid t = do
  oidAndNameText <- maybe (fail "invalid LinkOid") pure (T.stripPrefix "id:" t)
  let oidText = T.take 36 oidAndNameText
      maybeNameText = T.drop 36 oidAndNameText
      name =
        if T.length maybeNameText > 2
          then T.drop 2 maybeNameText
          else ""
  case Lilac.Types.fromText oidText of
    Nothing -> fail "invalid LinkOid"
    Just oid -> pure $ LinkOid oid name
#+end_src

This function is not very strict (it only implicitly checks for the ~::~ separator
between the UUID and the name (if any)), because it's good enough.

Now we're ready to define the boilerplate for doing the round trip to and back
from JSON. The [[instance:ToJSON LinkOid]] converts the ~LinkOid~ to a JSON ~Value~ type
(one of the constructors being a JSON string, or ~Data.Aeson.Types.String~).

#+name: instance:ToJSON LinkOid
#+begin_src haskell
instance ToJSON LinkOid where
  toJSON linkOid = Data.Aeson.Types.String (T.show linkOid)
#+end_src

The [[instance:ToJSONKey LinkOid]] is simpler, because it just expects a type that
can be a key. The use of ~toJSONKeyText~ is important because it results in
encoding the surrounding map as a JSON object ~{...}~ instead of an array of
key-value pairs ~[...]~ (see the [[https://hackage.haskell.org/package/aeson-2.2.3.0/docs/Data-Aeson-Types.html#t:ToJSONKeyFunction][upstream docs here]]).

#+name: instance:ToJSONKey LinkOid
#+begin_src haskell
instance ToJSONKey LinkOid where
  toJSONKey = toJSONKeyText show
#+end_src

The instances for both ~FromJSON~ and ~FromJSONKey~ rely on the [[f:parseJSONLinkOid]]
we defined above.

#+name: instance:FromJSON LinkOid
#+begin_src haskell
instance FromJSON LinkOid where
  parseJSON = withText "LinkOid" parseJSONLinkOid
#+end_src

#+name: instance:FromJSONKey LinkOid
#+begin_src haskell
instance FromJSONKey LinkOid where
  fromJSONKey = FromJSONKeyTextParser parseJSONLinkOid
#+end_src

In [[f:mkObject]], the ~externalOids~ captures all links that point to some other cell
in another Org file. A consistent "cell universe" can be constructed when all
external links are resolved, by getting all other =Object= values for other Org
files we depend on.

#+name: f:mkObject
#+begin_src haskell
mkObject :: OrgDoc -> IO Object
mkObject orgDoc = do
  pure
    Object
      { orgDoc = orgDoc,
        symbols = mkSymbols orgDoc,
        externalOids = findExternalOids orgDoc
      }
#+end_src

[[f:mkSymbols]] generates a mapping of all OIDs to their cells (via the cell index),
and also any OID and name combinations to their cells.

#+name: f:mkSymbols
#+begin_src haskell
mkSymbols :: OrgDoc -> Map LinkOid Int
mkSymbols orgDoc = fromList . concatMap f $ zip [0 ..] orgDoc.cells
  where
    f (localCellIdx, cell) = case cell of
      CBlock block -> getSymbols block.parentOid block.meta localCellIdx
      CHeading heading
        | Just oidText <- lookup "ID" heading.meta,
          Just oid <- LP.validateOidText oidText ->
            [ ( LinkOid
                  { oid = oid,
                    name = T.empty
                  },
                localCellIdx
              )
            ]
        | otherwise -> []
      CFigure figure -> getSymbols figure.parentOid figure.meta localCellIdx
      CMathFragment mathFragment -> getSymbols mathFragment.parentOid mathFragment.meta localCellIdx
      CTable table -> getSymbols table.parentOid table.meta localCellIdx
      CFootnote {}
      CListItem {}
      CParagraph {}
      CGlossaryTerm {}
      CCommand {} -> []
    getSymbols :: OID -> Map Text Text -> Int -> [(LinkOid, Int)]
    getSymbols parentOid cellMeta localCellIdx =
      let oids =
            if parentOid /= orgDoc.oid
              then [parentOid, orgDoc.oid]
              else [orgDoc.oid]
       in concatMap requireName oids
      where
        requireName oid
          | Just name <- lookup "name" cellMeta =
              [ ( LinkOid
                    { oid = oid,
                      name = name
                    },
                  localCellIdx
                )
              ]
          | Just tanglePath <- lookup "tangle" cellMeta =
              [ ( LinkOid
                    { oid = oid,
                      name = tanglePath <> "\NUL"
                    },
                  localCellIdx
                )
              ]
          | otherwise = []
#+end_src

The ~(name, cell)~ tuple is important, because otherwise Org links that
look like ~[[foo bar]]~ will be returned from [[f:findExternalOids]]. Links
like ~[[foo bar]]~ shouldn't be considered external, because they refer to cells
that have been named like ~foo bar~ inside the current Org file, not an external
Org file.

* External symbol (OID) detection

[[f:findExternalOids]] looks for ~LinkTargetOid~ links that point to cells that are
not inside the current Org file. We just look at all
links and see if any of them point to an OID that is not accounted for in the
=symbols= (symbols that are local to the current [[id:e16dd5c7-0a63-4c52-afe9-744fdf853643::data:OrgDoc][data:OrgDoc]]).

#+name: f:findExternalOids
#+begin_src haskell
findExternalOids :: OrgDoc -> [LinkOid]
findExternalOids orgDoc =
  sort
    . Set.toList
    . fromList
    $ concatMap f orgDoc.cells
  where
    f cell = case cell of
      CBlock block -> foldl' g [] block.body
      CHeading heading -> foldl' h [] heading.body.unProse
      CParagraph prose -> foldl' h [] prose.unProse
      CGlossaryTerm glossaryTerm -> foldl' h [] glossaryTerm.definition.unProse
      CTable table -> foldl' (\acc prose -> foldl' h acc prose.unProse) [] table.grid
      CFigure {}
      CFootnote {}
      CListItem {}
      CMathFragment {}
      CCommand {} -> []
    g acc = \case
      BTokenLinkTarget linkTarget -> getExternal acc linkTarget
      BTokenString {}
      BTokenPadding -> acc
    h acc = \case
      PTokenLink link -> getExternal' acc link
      PTokenStyledText {}
      PTokenCitation {}
      PTokenMathFragment {}
      PTokenDivStart {}
      PTokenDivEnd {} -> acc
    getExternal acc linkTarget = case linkTarget of
      LinkTargetOid linkOid ->
        if member linkOid symbols
          then acc
          else linkOid : acc
      LinkTargetLineLabel {}
      LinkTargetFootnote {}
      LinkTargetFilePath {}
      LinkTargetURI {} -> acc
    getExternal' acc link = getExternal acc link.target
    symbols = mkSymbols orgDoc
#+end_src

* Archives
:PROPERTIES:
:ID:       25827c17-2015-434b-b686-db3d72b2ee4d
:END:

When dealing with multiple [[data:Object]] files at a time, we have to answer the
question, "is this collection of objects able to resolve all internal
[[id:f8254d58-7a3d-4595-a265-e0d6255e6ab5::data:LinkOid][data:LinkOid]] values"? Essentially this is the same question as asking if there
are any broken links, as far as [[id:f8254d58-7a3d-4595-a265-e0d6255e6ab5::data:LinkOid][data:LinkOid]] targets are concerned.

The above question also has two different "flavors", depending on what we want
to do:

  1) For tangling, we only care about broken Noweb links for those code blocks
     that have the ~:tangle~ metadata key set (aka "root" blocks). That is, if a
     code block depends on another block but is not itself something that a root
     block depends on, we don't care because such blocks are ignored for
     tangling purposes.

  2) For weaving, we care about any broken link ([[id:f8254d58-7a3d-4595-a265-e0d6255e6ab5::data:LinkOid][data:LinkOid]]) to a cell,
     because otherwise we will not be able to generate the correct HTML link tag
     (~href=...~ attribute) for it.

#+name: data:Archive
#+begin_src haskell
type Archive :: Type
data Archive = Archive
  { objects :: Map GPath Object,
    symbols :: Map LinkOid Int,
    glossary :: Map (Text, GPath) Int,
    backlinks :: Map GPath (Map GPath [G.Edge]),
    offsets :: IntMap GPath,
    csls :: Map FilePath Text,
    bibs :: Map FilePath [CP.Reference (CslJson Text)]
  }
  deriving stock (Eq, Generic, Show)
  deriving anyclass (FromJSON, ToJSON)
#+end_src

A [[data:Archive]] is just a collection of [[data:Object]] values. The ~objects~ field
holds this collection, where the [[id:2d98229c-e318-434b-916b-364c04021306::newtype:GPath][newtype:GPath]] is the key of where that object
was found. We have to use ~GPath~ because there is no ~ToJSONKey~ instance for
~P.OsPath~ (which would otherwise have been our first choice).

The other fields in [[data:Archive]] are based on the ~objects~:

  - The ~symbols~ is a table for finding the cell (in one of the objects found in
    the archive) that corresponds to a [[id:f8254d58-7a3d-4595-a265-e0d6255e6ab5::data:LinkOid][data:LinkOid]]. It contains a globally
    unique index of the cell, which can be used with ~offsets~ to find the actual
    cell we are interested in.

    Now it could be the case that the user decides to link to the top-level UUID
    of the document. These require special treatment because they do not
    correspond to any given cell. So instead, we use negative numbers so as not
    to collide with the regular cell index numbers. The negative numbers encode
    which object we are referring to, and require special handling.

  - The ~backlinks~ is a map where the keys are the paths (of objects) and the
    values are the backlinks to that object. The backlinks are themselves a map
    because we want to organize all of the backlinks by the document they are
    starting out from. The actual backlinks are just edges between cells
    (vertices) where the edges are created by a reference (via [[id:f8254d58-7a3d-4595-a265-e0d6255e6ab5::data:LinkOid][data:LinkOid]])
    from one cell to another. They are based on [[id:e16dd5c7-0a63-4c52-afe9-744fdf853643::newtype:PseudoEdge][newtype:PseudoEdge]] which are
    constructed in [[id:dabccd5e-930e-4571-899f-1bfbdeab3d5e::f:oidLinkParser][f:oidLinkParser]]. See [[id:b1057136-48d5-402e-8e55-5a7e6a08efe4::f:weaveBacklinks][f:weaveBacklinks]] for how they are used
    during weaving.

  - The ~offsets~ is the offset of each object's cells, in relation to the global
    (flattened) list of all cells in the archive. For example, if the object is
    the first one in the list, the offset is 0. The offset grows depending on
    how many cells each object has. So if the first object has 100 cells, the
    offset for the second object in the list is 100.

To construct the archive, [[f:mkArchive]] reads a list of paths and the objects that
are found on those paths. The main check that is performed is to see that there
are no broken links within this collection of objects. The term "broken" here
mainly means any internal link (to a cell) that cannot be resolved; we do not go
over the network to check for broken HTTP links.

[[f:mkArchive]] also reads in any [[id:15706715-c648-4866-b757-ea4a1aad0570][CSL style file (XML)]] and also corresponding [[id:909c5265-065a-412c-9305-2cff398ad233][CSL
JSON (bibliographical entries)]] files, as these are needed for processing
citations and [[id:e24de101-bf1d-418b-a18f-b1a98fea9696][printing bibliographies]]. If there is any problem with parsing
these inputs, we return an error. This area around citations is discussed
separately in [[id:4194fc81-a28d-451f-b4bd-f2f522b5a750][Citation dependencies]]. For the CSL style file, we have to store
the information as a ~Text~ value, because there is no ~ToJSON~ instance for the
~Citeproc.Types.Style~ type.

#+name: f:mkArchive
#+begin_src haskell
mkArchive :: [(GPath, Object)] -> IO (Either String Archive)
mkArchive pathObjs = do
  let (objects, symbolsWithoutTopLevelUUIDs, glossary) =
        foldl' concatObjs (mempty, mempty, mempty) offsetsFull
      symbols = topLevelUUIDs <> symbolsWithoutTopLevelUUIDs
      backlinks =
        mkBacklinks pathObjs offsets
          $ foldl' (finalizeEdges symbols) [] offsetsFull
      brokenLinks = findBrokenLinks objects symbols
  allBibPaths <-
    concat
      <$> mapM (\(gp, o) -> makeRelativeToObjectPath gp o.orgDoc.bibPaths) pathObjs
  allCslPaths <-
    concat
      <$> mapM (\(gp, o) -> makeRelativeToObjectPath gp $ maybeToList o.orgDoc.cslPath) pathObjs
  bibs <- getBibliographies allBibPaths
  cslRawXMLs <- map fst <$> getCitationStyles allCslPaths
  let csls = zip allCslPaths cslRawXMLs
  if
    | brokenLinks /= [] ->
        pure
          . Left
          $ "Found broken links:\n"
          <> intercalate
            "\n"
            (map showBrokenLink brokenLinks)
    | otherwise ->
        pure
          $ Right
            Archive
              { objects = objects,
                symbols = symbols,
                glossary = glossary,
                backlinks = backlinks,
                offsets = offsets,
                csls = fromList csls,
                bibs = fromList bibs
              }
  where
    topLevelUUIDs :: Map LinkOid Int
    topLevelUUIDs =
      let topLevelLinkOids =
            fromList
              $ zip (map (mkLinkOid . snd) $ sort pathObjs) [-1, -2 ..]
          mkLinkOid :: Object -> LinkOid
          mkLinkOid obj =
            LinkOid
              { oid = obj.orgDoc.oid,
                name = ""
              }
       in topLevelLinkOids
    offsets :: IntMap GPath
    offsets =
      IntMap.fromList
        $ map (\(offset, (path, _obj)) -> (offset, path)) offsetsFull
    offsetsFull :: [(Int, (GPath, Object))]
    offsetsFull =
      cumulativeOffsets
        . filter (\(numCells, _) -> numCells > 0)
        . map (\(path, obj) -> (length obj.orgDoc.cells, (path, obj)))
        $ sort pathObjs
    concatObjs ::
      (Map GPath Object, Map LinkOid Int, Map (Text, GPath) Int) ->
      (Int, (GPath, Object)) ->
      (Map GPath Object, Map LinkOid Int, Map (Text, GPath) Int)
    concatObjs (accObjs, accSyms, accGloss) (offset, (path, obj)) =
      ( insert path obj accObjs,
        (M.map (+ offset) obj.symbols) <> accSyms,
        (M.mapKeys (\term -> (term, path)) obj.orgDoc.glossary) <> accGloss
      )
    findBrokenLinks ::
      Map GPath Object ->
      Map LinkOid Int ->
      [(GPath, LinkOid)]
    findBrokenLinks objs syms =
      foldl' (getBrokenLink syms) []
        $ allExternalOids objs
    getBrokenLink ::
      Map LinkOid Int ->
      [(GPath, LinkOid)] ->
      (GPath, LinkOid) ->
      [(GPath, LinkOid)]
    getBrokenLink syms acc (gPath, linkOid) = case lookup linkOid syms of
      Just _ -> acc
      Nothing -> (gPath, linkOid) : acc
    allExternalOids :: Map GPath Object -> [(GPath, LinkOid)]
    allExternalOids objs =
      M.foldlWithKey'
        (\acc gPath obj -> (zip (repeat gPath) obj.externalOids) <> acc)
        []
        objs
    showBrokenLink :: (GPath, LinkOid) -> String
    showBrokenLink (gPath, link) =
      "  " <> (T.unpack $ show link) <> " (" <> (decodeGPath gPath) <> ")"
#+end_src

[[f:finalizeEdges]] looks at each object's ~pseudoEdges~ into edges using symbols (~Map
LinkOid Int~) and offsets. Each ~PseudoEdge~ links from the object's local cell
index (without any offsets) into a ~LinkOid~ target. We need to perform two transformations:

  1) Convert the local index into a global one, by adding the offset to it.

  2) Convert the ~LinkOid~ target into a global cell index, by looking it up in
     the global symbols (~Map LinkOid Int~).

#+name: f:finalizeEdges
#+begin_src haskell
finalizeEdges ::
  Map LinkOid Int ->
  [G.Edge] ->
  (Int, (GPath, Object)) ->
  [G.Edge]
finalizeEdges syms acc (offset, (_, obj)) =
  let f (PseudoEdge (localCellIdx, linkOid)) = case lookup linkOid syms of
        Nothing -> Nothing
        Just targetCellIdx -> Just (localCellIdx + offset, targetCellIdx)
   in (catMaybes $ map f obj.orgDoc.pseudoEdges) <> acc
#+end_src

[[f:mkBacklinks]] takes the edges which contain global cell index information for

shape ~Map GPath (Map GPath [G.Edge])~:

      |          |       |
      |          |       `---> List of edges (source cell idx, target cell idx)
      |          `---> Source object path
      `----> Target object path

#+name: f:mkBacklinks
#+begin_src haskell
mkBacklinks ::
  [(GPath, Object)] ->
  IntMap GPath ->
  [G.Edge] ->
  Map GPath (Map GPath [G.Edge])
mkBacklinks pathObjs offsets symbolEdges =
  let f acc (from, to)
        | Just (_, fromPath) <- IntMap.lookupLE from offsets,
          Just (_, toPath) <- IntMap.lookupLE to offsets,
          fromPath /= toPath =
            M.insertWith (<>) toPath [(fromPath, [(from, to)])] acc
        | Just (_, fromPath) <- IntMap.lookupLE from offsets,
          to < 0,
          Just toPath <- (sort $ map fst pathObjs) !!? (abs to - 1),
          fromPath /= toPath =
            M.insertWith (<>) toPath [(fromPath, [(from, to)])] acc
        | otherwise = acc
   in M.map (M.fromListWith (<>)) $ foldl' f mempty symbolEdges

* Cycle detection for Noweb links
:PROPERTIES:
:ID:       ff5876bf-a144-4a08-bba4-15638e3590d5
:END:

All Noweb links (for code blocks) inside an [[data:Archive][Archive]] must be such that they do
not form a cycle. This is because we have to expand (replace with the actual
text) Noweb links during the tangling process, and we don't want to be in the
position of expanding things forever.

We want to build up a graph using the Noweb link information embedded in each
block. Using a graph data structure allows us to easily detect cycles, which are
not allowed for tangling because they cannot be resolved.

You may think we could avoid using graphs entirely, and just use an algorithm
like "keep expanding all Noweb links recursively; if we see a Noweb link being
used more than once, error out" to detect cycles. However this won't work
because you can technically reference the same block multiple times at different
points in the tree.

Specifically, we want to build a /directed/ graph where we treat all blocks as
nodes (vertices) and the dependency of Noweb links as edges. So if a block =x=
depends on a Noweb link =y=, then =x= would point to =y=.

From [cite:@clrs_2009 ch. 22] (p. 614) we can find a more formal definition of
cycles in a directed graph:

#+begin_quote
A directed graph G is acyclic if and only if a depth-first search of G yields no
back edges.
#+end_quote

And a back edge is defined like this in [cite:@clrs_2009 p. 609]:

#+begin_quote
Back edges are those edges (u, v) connecting a vertex u to an ancestor v in a
depth-first tree. We consider self-loops, which may occur in directed graphs, to
be back edges.
#+end_quote

Note that a back edge can be either an edge that points back to an ancestor, or
a self-loop. Whether an edge points back to an ancestor can be determined by
finding strongly connected components with more than one vertex. And we can
check for self-loops by just seeing if a block links to itself.

Checking for strongly connected components can be done with the =scc= function
provided by the =Data.Graph= library. This library also lets us create a /single/
graph with all of the blocks in it because the library doesn't care whether the
edges we feed into it are connected.

The [[f:buildGraph]] function looks at all code blocks and generates the necessary
edges to build up a directed graph. It does this by constructing edges that have
the [[id:f8254d58-7a3d-4595-a265-e0d6255e6ab5::data:LinkOid][data:LinkOid]] of the starting block as one vertex, and the Noweb links found
inside the body as the other vertices.

#+name: f:buildGraph
#+begin_src haskell
buildGraph ::
  [Block] ->
  ( G.Graph,
    G.Vertex -> (Block, LinkOid, [LinkOid]),
    LinkOid -> Maybe G.Vertex
  )
buildGraph blocks = G.graphFromEdges $ foldl' f [] blocks
  where
    f ::
      [(Block, LinkOid, [LinkOid])] ->
      Block ->
      [(Block, LinkOid, [LinkOid])]
    f acc block
      | Just name <- lookup "name" block.meta =
          let selfLink = LinkOid block.parentOid name
           in (\outLinks -> (block, selfLink, outLinks) : acc)
                . catMaybes
                $ map getOutLinks block.body
      | otherwise = acc
    getOutLinks = \case
      BTokenLinkTarget (LinkTargetOid linkOid) -> Just linkOid
      BTokenLinkTarget {}
      BTokenPadding {}
      BTokenString {} -> Nothing
#+end_src

The [[f:findCycles]] function takes the output of [[f:buildGraph]] and uses that to run
the =scc= function to get the strongly connected components, which we filter to
only keep the ones that have cycles in them.

#+name: f:findCycles
#+begin_src haskell
findCycles :: Archive -> [G.Tree LinkOid]
findCycles archive = map (fmap toLinkOid) . foldl' f [] $ G.scc graph
  where
    blocks = foldl' getBlocksFromAllSymbols [] $ elems archive.symbols
    getBlocksFromAllSymbols acc globalCellIdx
      | Just (_, cell) <- cellIdxToObjCell archive globalCellIdx =
          case cell of
            CBlock b -> b : acc
            CHeading {}
            CListItem {}
            CParagraph {}
            CGlossaryTerm {}
            CMathFragment {}
            CFigure {}
            CTable {}
            CFootnote {}
            CCommand {} -> acc
      | otherwise = acc
    (graph, vertexToNode, _) = buildGraph blocks
    toLinkOid vertex =
      let (_, selfLink, _) = vertexToNode vertex
       in selfLink
    f acc tree@(G.Node vertex _)
      | length tree > 1 = tree : acc
      | (_, selfLink, outLinks) <- vertexToNode vertex,
        elem selfLink outLinks =
          tree : acc
      | otherwise = acc
#+end_src

The line ~elems archive.symbols~ just gets all code blocks from the ~symbols~
field of the [[data:Archive]] (perhaps ~elems~ is a poor name and should have been
called ~values~ instead, but that's another matter).

Checking for back edges means just seeing whether there is more than one vertex,
or if there are any self-loops; these concerns are encoded in the ~f~ helper
function.

There are two major areas of concern for the compilation process:

  1) generation of expected ~symbols~ and ~externalOids~ as specified in the
     [[data:Object]], and

  2) detection of cycles when resolving symbols that cannot be resolved within
     the current object (when we require multiple objects).

Note that the helpers use the more convenient ~FilePath~ type instead of ~P.OsPath~,
mainly because using the ~QuasiQuoter~ for ~P.OsPath~ slows down the compilation
process and because [[data:Archive]] uses ~GPath~ anyway (and not ~P.OsPath~).

#+name: f:checkExternalOids
#+begin_src haskell
checkExternalOids :: FilePath -> [LinkOid] -> Spec
checkExternalOids path expectedExternalOids = do
  it path $ do
    (Right od) <- read
    LC.findExternalOids od `shouldBe` expectedExternalOids
  where
    read = do
      input <- LU.readFrom "test/Lilac/CompileSpec/" path
      pure $ LP.parseOrgDoc input
#+end_src

The [[f:checkCycles]] function uses [[f:findCycles]] to see if the archive that is
constructed from the given Org documents has any cycles.

#+name: f:checkCycles
#+begin_src haskell
checkCycles :: [FilePath] -> [G.Tree LinkOid] -> Spec
checkCycles paths expectedCycles = do
  pathObjs <- runIO $ LC.readObjectsFrom "test/Lilac/CompileSpec/" paths
  maybeArchive <- runIO $ LC.mkArchive pathObjs
  case maybeArchive of
    Left errMsg -> it "programmer error" $ expectationFailure errMsg
    Right archive -> it (show paths) $ do
      (LC.findCycles archive) `shouldBe` expectedCycles
#+end_src
