Release Notes

1 Versions

1.1 v0.2.0.3

Improvements:

  • Use Nix for generating the version string, so that consumers can use either the Git tag or the exact commit SHA for specifying the version of Lilac they want to use. Combined with the fact that next branch changes are built and pushed to Cachix, this means that consumers can now easily pull in a preview build. commit d1cad32d ("build: use Nix for generating the version", 2026-10-28)

1.2 v0.2.0.2

Changes:

  • Make version generation more friendly with GitHub's default CI optimization of using shallow clones (depth of 1). commit 66e545c9 ("build: don't use git-describe for generating the version", 2026-10-28).

1.3 v0.2.0.1

Changes:

  • Migrate away from SourceHut to GitHub.

    • commit ac0100cd ("build: publish to GitHub pages", 2026-10-26)

    • commit 18960e7e ("port SourceHut CI to GitHub Actions workflow", 2026-10-26)

1.4 v0.2.0.0

Changes:

  • Line labels now have a popup link next to them, such that clicking on it shows you a list of all references to it. This ended up being a surprising amount of work because it touched every part of the pipeline, from parsing to the frontend:

    • Create the concept of unique link indexes (similar to cell indexes) during parsing.

      • commit 3d017e44 ("parse: track the current link number (index) with linkNumber", 2026-09-25)

      • commit 61770c80 ("parser: PTokenLink: track link index (incrementing number)", 2026-09-25)

    • Construct OID aliases and precise backlinks during compilation. commit 10cd3625 ("compile: generate fine-grained backlinks", 2026-09-26)

    • Embed precise backlink data into line labels during weaving. commit 1b9c29e3 ("weave: encode precise backlinks for line labels", 2026-10-09)

    • Construct popups in frontend. commit 32fa69d4 ("frontend: fully render precise backlinks in popups", 2026-10-09)

    This work also exposed a design flaw with out data structures --- namely that we have a somewhat inadequate representation of links. Doing a larger refactor here is probably too much work (where if we decided to do this, we might consider rewriting the entire program).

  • Links from child blocks to parent blocks now target the exact location where the child block was referenced. Previously, the child block referenced the entire parent block, which meant that it could be hard to see where the child was used (especially for larger parent blocks with many different child blocks). commit 0baad1dc ("weave blocks: link back to parent blocks more precisely", 2026-08-17)

  • Glossary terms are both more strictly parsed, but also more flexible. See Multicell Glossary Items.

    The most notable difference is that they must be written inside unordered list items; if they are written anywhere else, they are parsed as regular paragraphs. commit e88c1d94 ("glossary terms: only recognize them in unordered list items", 2026-08-11)

    Glossary terms may no longer be nested. commit 72e973c9 ("glossary: forbid nesting of glossary terms", 2026-08-11)

    If the first item of an unordered list is a glossary term, then all subsequent items at that list level must also be glossary terms. Conversely if the first item is not a glossary term, then none of the list items at that level may be a glossary term. This is called the uniformity rule, see Uniformity of list items that define glossary terms. commit c94f41be ("glossary terms: implement uniformity rule", 2026-08-16)

    Glossary terms are also more flexible now, because you can use multiple cells to define them (this is unlike before where we only allowed a single paragraph). The inspiration comes from our work on rich blocks in v0.1.0.8. commit 2b38bfd3 ("weave: weave multicell glossary terms", 2026-08-16)

    When glossary terms are first woven (at the site where they are defined), we no longer weave the unordered list bullets next to them (no more weaving glossary terms inside singleton <dl> lists). This reduces unnecessary indentation. commit 2b38bfd3 ("weave: weave multicell glossary terms", 2026-08-16)

Fixes:

  • Long breadcrumbs are truncated if needed. They no longer bleed over the navbar if they're too long. commit 8b6f6cb5 ("weave: optionally truncate long breadcrumbs", 2026-09-20)

  • Replace the correct extension for filenames in breadcrumbs. commit ce89e7f9 ("weave: only replace the last extension of the breadcrumb", 2026-09-25)

1.5 v0.1.0.8

Improvements:

  • Support rich blocks. You can now do #+begin_note or #+begin_warn to enclose other cells (except headings) inside a box. These are also called alerts, callouts, admonition blocks, or advisory blocks in other systems. Only the note and warning types get different colors. If you add an unrecognized rich block like #+begin_hello, it will look plain.

    • commit c048d2ab ("parser: support rich blocks", 2026-08-01)

    • commit b11b691d ("weave: support rich blocks", 2026-08-01)

  • Explain how to bring in Lilac into a Nix configuration. commit 4a440910 ("user manual: explain how to install Lilac from a Nix config", 2026-07-24)

  • Stylize example, note, and warning blocks. commit 76249feb ("weave: stylize miscellaneous blocks", 2026-07-26)

Changes:

  • Prefer "block" instead of "code block" to refer to #+begin_... and #+end_... constructs. commit 67ab56e2 ("rename "code-block" to just "block"", 2026-07-25)

  • Slightly reduce indentation of list items. commit aa827501 ("css: slightly reduce indentation of list items", 2026-07-30)

1.8 v0.1.0.5

Improvements:

  • Block ancestors are no longer just arrow symbols. Instead we print the full name of the block (and the Org doc where it's from if it's external), inside the hidden metadata area. 5d5bc75d (block ancestry: use full parent (ancestor) name, instead of just arrows, 2026-07-22)

    We also filter out the redundant name and tangle metadata keys because they are already displayed in the Name and tangle path part of the block at the very top.

  • Binaries are now pushed to Cachix. d481eb94 (Makefile: push Nix-built binary to Cachix, 2026-07-19)

  • Hanging indentation for glossary terms. 4722cff7 (css: improve readability of glossary items, 2026-07-19)

  • Reduce excess whitespace in the woven output.

    • Less vertical spacing between list items. 7bdbb841 (css: reduce vertical whitespace between list item paragraphs, 2026-07-22)

    • Reduced left margin. 74520ba7 (weave: reduce space in left margin, 2026-07-22)

  • Make stamp-new-version.sh check for a COMMIT string in the release notes (this doc) first. Now we can remember more easily which set of preparatory notes need to be paired with Git commit descriptions. d7e65bf0 (stamp-new-version.sh: learn to check against a "COMMIT" string, 2026-07-22)

  • Various CSS fixes to the print preview. 2c944ade (css: various print preview fixes, 2026-07-23)

  • Various doc improvements.

Changes:

  • Make the footer advertise Lilac's homepage, not repo URL.
