  - The [[id:f3c2a043-2d0f-4d6c-a6d5-ce5f58a924c4][Prioritized TODOs]] section lists all TODOs that have currently been

** DONE weave: escape blocks in languages that Skylighting doesn't know

When Skylighting didn't know a block's language (such as ~gitignore~ or
~haskell-cabal~), [[id:e4cc0d4f-b129-4d94-be1c-3c0212527ae7::f:colorizeText][f:colorizeText]] fell back to ~code_ $ toHtmlRaw txt~, which
wrote the block text into the HTML without escaping it. So a ~gitignore~ block
with ~a<b>c & d~ in it got a real ~<b>~ tag, and our own woven ~build.org~ had a
raw ~base >=4.7 && <5~ in it. Now the fallback uses ~toHtml~.

** DONE compile: fix document links in archives with empty objects

[[id:b9c034c1-5499-44e6-855c-6c16e1693cb8::f:mkArchive][f:mkArchive]] dropped objects without any cells before
[[id:b9c034c1-5499-44e6-855c-6c16e1693cb8::f:docOidsToSymbols][f:docOidsToSymbols]] gave each document its negative ~GCI~. But
[[id:b9c034c1-5499-44e6-855c-6c16e1693cb8::f:gciToObjPath][f:gciToObjPath]] and [[id:e4cc0d4f-b129-4d94-be1c-3c0212527ae7::f:weaveLinkTargetLinkOid][f:weaveLinkTargetLinkOid]] turned a negative ~GCI~ back into
a path by indexing into ~sort $ keys archive.objects~, which still had the empty
objects. So if an archive had an empty ~a.org~, a link to all of ~b.org~ pointed
to ~/a.html~ instead. Now every object gets its negative ~GCI~, including the
empty ones, so links to an empty document work too.

** DONE compile: report each Noweb cycle only once

[[id:b9c034c1-5499-44e6-855c-6c16e1693cb8::f:getBlocksFromArchive][f:getBlocksFromArchive]] went through ~elems archive.symbols~, so it returned a
block once for every symbol that points to it (its name under the document OID,
under the parent heading's OID, and every line label in it).
[[id:b9c034c1-5499-44e6-855c-6c16e1693cb8::f:findCycles][f:findCycles]] then reported the same cycle several times; a block that refers
to itself and has two line labels was reported 3 times. This was also the real
reason why [[id:b9c034c1-5499-44e6-855c-6c16e1693cb8::t:0100-dag-self-loop-heading][t:0100-dag-self-loop-heading]] expected two nodes, and the prose
there talked about a "2-block cycle". Now each block is only looked at once, and
the test expects one node.

** DONE parse: make styled text survive the round trip back to text

The prose for ~toText~ in the ~CiteprocOutput~ instance for ~Prose~ says that there is no
loss of information going from ~Text~ to ~Prose~ and back. But
[[id:442c807f-c9d9-45a7-88bf-d38cbbca09cf::f:unparseStyledText][f:unparseStyledText]] did not escape backslashes, nor ~=~ inside verbatim text
or ~\~~ inside code text, so such text did not survive the round trip. Now it
escapes the same characters that the parser accepts after a backslash.

** DONE compile: only treat index.org as an index

[[id:b9c034c1-5499-44e6-855c-6c16e1693cb8::f:isIndexObjPath][f:isIndexObjPath]] only checked that the path ends in ~index.lobj~, so a file like
~appendix-index.org~ was treated as an index too, and then
[[id:b9c034c1-5499-44e6-855c-6c16e1693cb8::f:getChildPaths][f:getChildPaths]] dropped the wrong prefix when it removed the last 10
characters. Now it checks the file name instead.

** DONE compile: detect broken links in more cells

[[id:01da95fe-ba23-4481-9833-428423392f5f::f:findExternalOids][f:findExternalOids]] didn't look inside footnote bodies, glossary terms, or figure
and table captions. A broken link in these places passed [[id:a9bad6d4-5b1c-48de-8f09-178724859381::f:findBrokenLinks][f:findBrokenLinks]] and
was woven by [[id:a63d2021-2596-4c43-81e3-d08e90077f75::f:showBrokenLink][f:showBrokenLink]] as ~LILAC_BROKEN_LINK~. Now it looks in these places too.
This didn't reveal any broken links in our docs, but other documents with such
links now fail to compile.

** DONE frontend: remove the TOC click handler

In [[id:c4c13ce7-23d9-49d9-8d3f-6faecf839afa::ns:lilac.toc-active-entries][ns:lilac.toc-active-entries]], the click handler for TOC links had
~#(reset! visible-headings #{})~, which only created a function and never called
it. So the reset of the visible headings never ran. Removing the handler doesn't
change behavior, because of this. We removed it instead of repairing it because
the Intersection Observer only reports changes. A heading that stays visible
would not get added back after a reset, so it would lose its highlight.

** DONE frontend: make href->id use its argument

[[id:48d6dc87-f5fc-4a36-bef4-85b9d4207f05::f:href->id][f:href->id]] ignored its argument and read the anchor of the current URL. So when the
URL had no anchor (or one that didn't match any element), clicking on a link
didn't find an element, and the browser did its default jump. The page then
scrolled even if the target was already visible, which is what lazy scrolling is
supposed to prevent. Now it uses its argument. We also removed its ~#top~ fallback,
which never applied, because [[id:48d6dc87-f5fc-4a36-bef4-85b9d4207f05::f:maybe-scroll-by-hash][f:maybe-scroll-by-hash]] calls this function on page
load and woven pages have an element with the ~top~ ID.

** DONE weave: make the collapse button label change

[[id:3d4c0326-ee40-43d5-b49b-ab72081ae91a::css:Block controls inline][css:Block controls inline]] changes the button label to "Collapse contents" if the
button has the ~action-collapse~ class, but nothing ever set this class. So the button said
"Expand contents" even when the block was expanded. Now [[id:9c8e1074-edfb-4f89-bedf-07527981835d::f:render-block!][f:render-block!]] sets it
whenever the body is visible.

** DONE weave: avoid duplicate HTML IDs for figures

[[id:4eea4449-2418-42c5-86e4-af63c3b742e3::f:weaveFigure][f:weaveFigure]] gave both ~figure_~ and ~img_~ the same ~id~. We removed it from ~img_~.

** DONE weave: make the footer link always lead to Lilac

The "Generated by Lilac" link in [[id:797b6f06-64e0-4bf7-946f-055994ff160f::f:weaveFooter][f:weaveFooter]] went to the project's own homepage if one
was configured, and only fell back to Lilac's repo URL otherwise. So for other
projects using Lilac, the link might not have led to Lilac. Now it always goes to
Lilac's homepage.

** DONE build: stop tangle-loop.sh checks if tangling fails

The prose says that later steps abort if an earlier one fails, but in

** TODO track time-sensitive things with invisible timestamps only the compiler can see?

Sort of like citations, but, imagine if we link to something (e.g., a version of

We need some hidden way of saying "please remember a special TIMESTAMP" and then

** TODO tangle/detangle interop
There are several ways to understand the relationship between Org and tangled
files:

  - add special comments in the tangled text (this is what Org can do and
    presumably Orgmode can already understand how to detangle (jump to the right
    Org block) using such special comments)

  - add LINE and COLUMN pragmas (or ~#line~ directives) in the target language, if
    it supports such pragmas

  - do a fresh parse of Org, then ask "where does this tangled line come from?"

The last option is the most compute-intensive, but also the least messy. This is
because the first two options result in peppering the tangled output with lots
of custom line numbers, which can all change completely if we modify a single
line near the beginning of the Org file.

How about a special commenting style that is removed from line numbers? For
example we could add comments saying "BEGIN f:foo" and "END f:foo" to say that
the text belongs to a particular named block. Then we can easily just search for
that block name. We don't have to worry about line numbers either.

The problem with the above is we have to litter our source code output with such
generated, mechanical noise. Instead, we should have a separate ~.loc~ file
("Location file") or similar which encodes this information for us when we
tangle. Then the tool we use can just read this info when interpreting line
number information from compiler errors.

The ~.loc~ file is what the JS world does with their "source maps". It's an
external file that knows how to map a JS file into another file (the original
file).

Our ~tangle-loop.sh~ can use ~sed~ to just replace the line number info with what we
find in ~.loc~. And then we can keep this stuff removed (outside of) source
control.

*** Chicken-egg issues

When developing Lilac, we should be able to tangle ourselves (build shouldn't be
broken). Then if we introduce some error so the build breaks, we should still be
able to generate the correct ~.loc~ file with the first ~tangle()~ invocation. Then
on the second invocation of ~tangle()~ we will be unable to build ourselves. In
this broken state, it's important to be able to interpret the ~.loc~ file with a
tool that is not native to Lilac (the understanding is that Lilac is broken). So
we have to design the ~.loc~ file in such a way that any rudimentary (such as
~Bash~) tool can understand it.

*** Reference

Noweb just uses a flag to set this for the source language. See https://man.cx/notangle(1).

See https://github.com/ghc/ghc/blob/master/utils/unlit/unlit.c for GHC/Haskell
which claims the CPP understands line pragmas.

Compare with https://zyedidia.github.io/literate/manual.html. There it appears
they support either injecting line number directives or pragmas as above, but
also support understanding the compiler errors when they are fed into the =lit=
program which can perform substitutions of those line numbers on the fly(?).

In Haskell there is both a LINE and COLUMN pragma. See
https://downloads.haskell.org/ghc/latest/docs/users_guide/exts/pragmas.html#line-pragma.

See https://gcc.gnu.org/onlinedocs/cpp/Line-Control.html for GCC and C.

For an example, see: https://learn.microsoft.com/en-us/cpp/preprocessor/hash-line-directive-c-cpp?view=msvc-170
